# 用 ERA 制作角色卡

本文是写给 AI 助手的**操作规范**。按步骤做，每一步完成后对照该步的“完成标准”。不确定的设计问题先问作者，不要替作者编造设定。

ERA 的工作方式：AI 在回复末尾输出指令块（`<VariableInsert>` 等），ERA 读取后更新**聊天级**变量 `stat_data`，并为每条消息记录日志，因此删除、滑动、编辑消息时变量能自动回滚、重算。消息正文是变量的事实来源。

## 第 0 步：确认需求

先问清楚（作者已经说明的不要重复问）：

1. 题材和需要追踪的状态（数值、物品、人物关系、地点时间、剧情进度……）。
2. 有没有状态栏或前端界面，是用楼层里的 HTML，还是酒馆助手的前端界面项目。
3. 预计聊天长度（几十楼还是几百楼），是否打算用**分步更新**（剧情模型只写剧情，另一个模型更新变量）。
4. 是新卡，还是改造已有的卡。
5. 玩家常用的预设会不会让 AI 先写思考块、用什么标签（第 8 步的 `思考标签`）。

**完成标准**：能列出一张“变量清单”草稿，作者确认过。

## 第 1 步：设计变量

规则：

- **集合用对象，不用数组**：背包、人物、事件记录都写成 `{ "物品名或ID": {...} }`。对象的增删改都能精确回滚，AI 也更不容易写错下标。只有顺序本身有意义、且元素是简单值时才用数组。
- **键名就是给 AI 看的说明**：用作者和 AI 都看得懂的名字（中文可以），避免缩写。键名里不要用 `.`、`[`、`]`。
- **固定选项的字段要列出选项**：时间段、阶段、心情等，如果只有几种取值，就在第 2 步写成枚举，不要留成自由文本。
- **数值写明范围**：好感度 0~100 之类，在第 2 步用 schema 夹住。
- **设定不让 AI 改的字段**：姓名、种族等用 schema 的 `literal(...).catch(...)` 固定；或以 `_` 开头并开启脚本设置 `下划线只读`；或用 `$meta.updatable: false`。
- **可以由规则算出来的值不要让 AI 维护**：等级上限、派生属性、时间进位等交给第 6 步的钩子。需要 AI 当场按公式计算或掷骰的，让 AI 写 `$expr`（第 4 步）。
- 每张卡的顶层建议分成几个大块（如 `世界状态`、`角色名`、`玩家`、`记录`），便于写说明和分组更新。

**完成标准**：变量清单写成一份完整的初始值 JSON，每个字段都知道类型、取值范围或选项、由谁更新（AI / 钩子 / 前端 / 不变）。

## 第 2 步：写变量结构（zod schema）

强烈建议写。注册后 ERA 会：把类型和选项自动告诉 AI（宏 `{{ERA-schema}}`）；纠正 AI 写的 `"5"` 等格式问题；拦下不合法的修改并报告原因。不注册时 ERA 照常工作，只是没有这些保护。

常用写法（可直接复用）：

```ts
/** 数字；只接受数字和纯数字文本 */
const Num = z.union([z.number(), z.string().trim().regex(/^[+-]?\d+(\.\d+)?$/).transform(Number)]);
const Percent = Num.transform(v => _.clamp(v, 0, 100)).describe('0~100');
/** 文本；AI 有时会写成数字 */
const Str = z.union([z.string(), z.number().transform(String)]);
const Text = Str.prefault('--');

export const Schema = z.object({
  世界状态: z.looseObject({
    时间段: z.enum(['清晨', '白天', '傍晚', '夜晚', '深夜']).describe('随剧情推进'),
    地点: Text,
  }),
  林晚: z.looseObject({
    姓名: z.literal('林晚').catch('林晚'), // 只读设定
    好感度: Percent,
    背包: z.record(z.string().describe('物品名'), z.object({ 数量: Num })).prefault({}),
  }),
});
```

要点：

- **用 `.describe('…')` 给字段写说明**，它会出现在 `{{ERA-schema}}` 里。用 `transform` 夹的范围 AI 看不到，要写进 describe。
- 对象用 `z.looseObject`（保留 schema 没写到的键），除非确实要丢弃多余的键。
- **不要用 `z.coerce.number()`**：它会把 `null`、空字符串、`true` 变成 0 或 1，掩盖 AI 的错误。
- schema 必须幂等：`parse(parse(x))` 等于 `parse(x)`，因为同一条消息会被重算多次。
- **已发布的卡给 schema 新增字段时，新字段必须带 `.prefault(…)` 或 `.default(…)`**；新增的是嵌套对象时，外层对象本身也要 `.prefault({})`，内层字段都有默认值不等于外层有。否则玩家已有聊天的变量不再符合结构。这时 ERA 照常放行，面板提示“变量当前不符合结构”，玩家可以在面板“诊断 → 结构诊断”查看并一键修复。
- 注册方式二选一：
  - 酒馆助手**角色卡脚本**里直接写：`await waitGlobalInitialized('Era'); const off = Era.registerSchema(Schema); $(window).on('pagehide', off);`。ERA 脚本被重新启用或更新后 schema 会丢失，需要重新加载角色卡脚本。
  - 用酒馆助手前端模板（vue + pinia）的项目：本母版已内置 `util/era.ts` 与根目录的 `exported.era.d.ts`（不要移进 `@types/`，`bump_deps` 会清空它），直接 `import { registerEraSchema } from '@util/era'; $(() => errorCatched(registerEraSchema)(Schema));`（它会处理 ERA 晚加载、ERA 重载后补注册、脚本卸载）。**推荐。**
- 注册后在控制台执行 `Era.hasSchema()` 确认为 `true`；schema 无效时 ERA 会弹窗“变量结构注册失败”。
- 不在开场白里初始化、完全靠默认值的卡，注册时传 `{ fillDefaultsOnEmpty: true }`。

**完成标准**：把第 1 步的初始值 JSON 交给 `Schema.parse`，不报错且结果与原值一致。

## 第 3 步：在开场白里初始化

在**每一个**开场白（含所有备选开场白）的末尾放一个 `<VariableInsert>`，内容是完整的初始值：

```
（开场白正文……）
<VariableInsert>
{ "世界状态": { "时间段": "夜晚", "地点": "庭院" }, "林晚": { "姓名": "林晚", "好感度": 30, "背包": {} } }
</VariableInsert>
```

- 所有变量在开场白里一次初始化完。之后的消息里对已存在的路径用 `<VariableInsert>` 会被忽略。
- 需要统一结构的集合，可以在父节点上放 `$template`（新插入的元素自动补全字段）；需要保护的节点放 `$meta`。用法见 `docs/era/02-指令手册.md`。
- 改了开场白之后，要**新开聊天**才会生效。
- 用制卡母版（tavern_era_template）的项目：把初始值写在卡文件夹的 `initvar.yaml`，开场白末尾留 `<!-- ERA-INIT:BEGIN -->` / `<!-- ERA-INIT:END -->` 两行标记，运行 `pnpm era-init` 生成这块 `<VariableInsert>`（按 schema 校验，并把 schema 里 `.meta({ era: {…} })` 标的保护写成 `$meta`）。见母版的 `初始模板/ERA角色卡/使用说明.md`。

**完成标准**：新开聊天后，ERA 面板里的变量与初始值一致，没有报错提示。

## 第 4 步：世界书规则

1. 在角色卡上导入并启用 ERA 脚本（酒馆助手角色脚本，内容为 `import 'https://testingcf.jsdelivr.net/gh/Bailuci/ERA-Heron@v2.0.1/artifact/bundle.js';`），在角色卡设置里**开启局部正则**，打开 ERA 面板（点悬浮球，或酒馆扩展菜单 → “ERA 面板”），在“工具”页点“**ERA 快速初始化**”（以 `初始模板/ERA角色卡/` 为起点时，`index.yaml` 已经写好 ERA 脚本、这两个条目和五条正则，不用再点）。它会：
   - 在角色主世界书里建两个条目：`ERA 变量操作规则`（教 AI 指令格式，一般不改）和 `ERA 变量意图说明`（由你填写）；
   - 在角色卡局部正则里建 `ERA 数据隐藏正则`、`ERA 元数据隐藏正则`、`ERA 思考块隐藏正则`、`ERA 状态栏模板`、`ERA 状态栏占位符隐藏正则`（只作用于提示词，去掉 `<StatusPlaceHolderImpl/>`）。
   - 已有的卡用“**更新旧卡的规则**”把规则条目和隐藏正则更新到当前版本（会备份原内容）。
2. 填写 `ERA 变量意图说明`（名字中间有一个空格，不能改）。快速初始化生成的条目已经是下面的骨架，把 `<变量说明>` 里的占位行换成真实内容；`<变量结构>` 和 `<当前变量>` 两段必须保留——随 AI 输出时，ERA 不会自动把变量和结构发给 AI，全靠这两个宏。旧卡的这个条目要手动补上这两段。

```
<变量说明>
## 世界状态
- 世界状态.时间段：随剧情推进；跨过深夜后进入下一天的清晨。用 <VariableEdit> 改成新的值。
- 世界状态.地点：角色当前所在的具体地点，换场景时用 <VariableEdit> 更新。

## 林晚
- 林晚.好感度：……什么情况下增减，每次一般变化多少，用 "+=3" 之类的增量。
- 林晚.背包：键是物品名。获得新物品用 <VariableInsert> 新增键；数量变化用 <VariableEdit> 的 "+=1"/"-=1"；用完用 <VariableDelete> 删除。
</变量说明>

<变量结构>
{{ERA-schema}}
</变量结构>

<当前变量>
{{ERA:$ALLDATA}}
</当前变量>
```

规则：

- 写清楚**什么情况下改、改多少、用哪种指令**，不要只复述字段含义。
- 增量写 `"+=5"`、`"-=3"`；整体替换对象、增删数组元素、改名、有则改无则插用 `<VariablePatch>`。
- **要求 AI 输出变量指令的内容只放在 ERA 的规则条目里**。不要在“输出格式”之类的其他条目或预设里另写一遍；否则以后开启分步更新时，剧情模型仍会自己写指令。
- 变量多、规则长时，可以按大块拆成多个条目（名字里都带上同一个前缀便于管理）。

**公式与骰点 `$expr`（可选）**：AI 可以在 `<VariableEdit>` 里把数字字段写成 `{"$expr": "min(角色.生命值 + 20, 角色.生命上限)"}`、`{"$expr": "roll(1, 6) + 角色.力量"}`，同一楼重算时骰点不变。

- 什么时候用：结果取决于其他字段，或需要随机结果（掷骰、判定、掉落）。只加减固定数值仍写 `"+=5"`；作者自己定的派生值（上限、钳制、时间进位）仍写第 6 步的钩子。
- 只在 `<VariableEdit>` 里、只对当前值是数字的字段求值；写在 `<VariableInsert>`、`<VariablePatch>` 里会原样存成对象。计算失败时该字段不变，ERA 报告原因。
- 要用时，在角色主世界书里建一个名为 `ERA 表达式规则` 的条目（名字一字不差，开启分步更新时它和规则条目一样只发给更新模型），内容复制上表中的原文，设成常驻（蓝灯），位置与 `ERA 变量操作规则` 相同（系统、深度 0）、顺序排在它后面。默认的规则条目不教 `$expr`，不建这个条目 AI 就不会用。
- 同一个公式要反复用、又不想写脚本时，把公式文本存成变量（在开场白的 `<VariableInsert>` 里写 `"公式": {"伤害": "max(1, a * 2 - b)"}`，公式里 `a`、`b`、`c`…… 依次是第 1、2、3…… 个参数），让 AI 写 `call(公式.伤害, 主角.攻击, 敌人.防御)`；在意图说明里写清每个公式的参数顺序，不想让 AI 改公式时给 `公式` 加 `"$meta": {"updatable": false}`。
- 语法、函数表和限制见 `docs/era/02-指令手册.md`。

**把没生效的指令告诉 AI `{{ERA-issues}}`（可选）**：AI 反复写错路径、类型时，在 `ERA 变量意图说明` 末尾单独加一行 `{{ERA-issues}}`。上一条 AI 回复里有指令没有生效时，它展开成一段说明（哪条、为什么、请改正后重写），没有问题时为空。它只报告主模型写在正文里的指令；分步更新发给更新模型的提示词里它总是空。开启分步更新的卡，意图说明只发给更新模型，放在那里主模型看不到；改放进一条发给剧情模型、不带 `[era_update]` 的蓝灯条目（靠近末尾，如深度 0～1）。详见 `docs/era/04-宏.md`。

**完成标准**：AI 的回复末尾稳定出现 `<VariableThink>` 和指令块，变量随剧情正确变化。

## 第 5 步：状态栏与前端

按需求选一种：

- **楼层 HTML 状态栏（最简单）**：开启脚本设置 `在ai消息尾部生成特殊符号`，在 `ERA 状态栏模板` 正则里写 HTML。读变量用 `{{ERA:路径}}` 宏时，需要开启 `强制重载功能`；更好的做法是在 HTML 的脚本里监听 `era:writeDone`，见 `docs/era/03-状态栏.md` 和 `docs/era/示例/`。
- **酒馆助手前端界面（vue）**：用 `util/era.ts`（`@util/era`）的 `defineEraDataStore(Schema)` 得到只读、已校验的最新变量 `data`。
- **楼层里的状态栏**只监听 `era:writeDone` 时，每一楼都显示最新变量。想让旧楼显示“那一楼当时”的值，用 `defineEraFloorStore(Schema)` 或 `await Era.getVarsAt(getCurrentMessageId())`（每次 `era:writeDone` 后重新读取）；只想在最新一楼显示完整状态栏，用 `isLatestFloor()` 判断。见 `docs/era/05-接口与设置.md` 第 9 节。快速初始化生成的状态栏模板这样区分：最后一楼显示最新变量并监听 `era:writeDone`；旧楼只在加载时读一次那一楼当时的值、不再监听，长聊天里每次写入只刷新最后一楼（编辑、删除更早的楼层后，已显示的旧楼要重新渲染才更新）。改模板时保留这个区分，见 `docs/era/03-状态栏.md`。
- 前端**写变量**：用 store 的 `commit` / `patch`，或直接 `await Era.commit([...], { atomic: true })`，失败时 Promise 会说明原因（例如金币不足被 schema 拒绝）。store 的 `update` / `insert` / `remove` 只为兼容旧版保留，拿不到结果，新代码不要用。频繁写入（滑块等）请做防抖。
- 前端自己发消息（`/send`、`/trigger`）之前先 `await Era.extra.wait()`，否则开启分步更新时，下一次生成可能还看不到最新变量。
- 想显示“变量更新中”，监听 `era:extraStatus`；界面加载时先用 `Era.extra.status().running` 恢复，免得错过已经发出的 `started`。

**完成标准**：状态栏和界面在发送、滑动、删除消息后都显示正确的值。

## 第 6 步（可选）：钩子

由规则计算的值用钩子，在角色卡脚本里注册：

```js
await waitGlobalInitialized('Era');
const off = Era.onAfterApply('卡名.时间进位', ({ stat, old_stat, random }) => {
  if (stat.世界状态.小时 >= 24) { stat.世界状态.小时 -= 24; stat.世界状态.天数 += 1; }
});
$(window).on('pagehide', off);
```

用前端模板的项目推荐 `import { registerEraHook } from '@util/era'; registerEraHook('after', '卡名.时间进位', ctx => { … });`：它会等待 ERA 加载，ERA 重载后自动补注册，脚本卸载时自动注销。直接调用 `Era.onAfterApply` 时，ERA 脚本被重新启用或更新后钩子会丢失，需要重新加载角色卡脚本。

钩子必须同步、只依赖 `ctx`：随机数用 `ctx.random()`，三角、指数、对数用 `ctx.math`（用法同 `Math`，各浏览器结果逐位一致），不要用 `Math.random()`、`Math.sin()`。不要在楼层界面或 `era:writeDone` 里注册。钩子里不能调用 `Era.commit`、`Era.applyText`、`Era.extra.run` / `wait`，也不能发写入事件：这样做会让该钩子报错，它的修改被丢弃。注册后在控制台执行 `Era.hasHook('卡名.时间进位')` 确认为 `true`。完整规则见 `docs/era/05-接口与设置.md`，可复制的完整脚本见 `docs/era/示例/变量结构与钩子脚本示例.js`。

**不要在 `era:writeDone` 里回写变量。** 常见的旧写法是脚本监听 `era:writeDone`，用 `Math.random()` 生成天气，或算出派生值，再用 `era:updateByPath` 写回。这样的结果不进入重算：每次打开聊天都可能重掷并改写最新楼，删除、滑动后也对不上。改写成 `Era.onAfterApply` 钩子，随机数用 `ctx.random()`，数学函数用 `ctx.math`。改造旧卡时遇到这种脚本，按 `docs/era/05-接口与设置.md` 第 8 节“不要在 `era:writeDone` 里回写变量”的迁移配方处理。

**工具与自定义公式函数（可选）**：钩子只能在整楼前后改变量。需要 AI 当场触发、由程序按规则结算的多步逻辑（战斗、交易、合成），注册工具：`registerEraTool('攻击', { description, parameters: z.object({…}), handler(args, ctx) { … return { operations: [{ edit: {…} }], result: {…} }; } })`，AI 在正文里写 `<EraFCall name="攻击">{"目标": "哥布林"}</EraFCall>`。工具读到执行到这里时的变量，返回的操作和普通指令一样经过 schema。在规则条目里放 `{{ERA-tools}}`（工具说明）和 `{{ERA-toolResults}}`（上一楼的结算结果），让 AI 知道怎么调用、结果如何。只需要一个数值公式时，用更轻的 `registerEraExprFn('伤害', (攻, 防) => Math.max(1, 攻 - 防), { params: 2 })`，AI 在 `$expr` 里写 `伤害(主角.攻击, 敌人.防御)`，规则条目里放 `{{ERA-exprFns}}`。两者都要求同步纯函数，随机数用 `ctx.random()`；用到它们的卡把 `ERA最低版本` 写成 `2.0.0`。详见 `docs/era/05-接口与设置.md` 的 `Era.registerTool`、`Era.registerExprFn`。

## 第 7 步（可选）：分步更新与正文前规划

适合变量多、剧情模型经常漏写或写错指令的卡。做法：

1. 给只发给更新模型的条目名字加 `[era_update]`（`ERA 变量操作规则`、`ERA 变量意图说明`、`ERA 表达式规则` 自动视为这类），两边都要看的设定加 `[era_both]`，变量很多时用 `[era_update:组名]` 分组并行。
2. 确认没有其他条目或预设要求剧情模型输出指令（见第 4 步）。
3. 玩家在 ERA 面板的“分步更新”页里开启并选择接口。这是玩家本机的设置，不随卡导出；卡里只需要做好条目标记，不开启时照常工作。
4. 专为分步更新设计的卡，可以在角色卡变量 `ERA分步更新` 里推荐开启（如 `{ 变量更新方式: '额外模型解析', 重试次数: 2 }`），随卡导出；玩家“变量更新方式”为“跟随角色卡”（默认）时采用。也可以在面板“分步更新”页调好后点“存为本卡推荐”写入。更新模型需要了解角色时可以推荐 `附带角色信息: '开启'`（附上角色描述与用户人设）；`更新模型预设`、`规划模型预设` 只能推荐 `'不使用预设'`（默认）或 `'使用当前预设'`，一般不要推荐使用预设（预设里写给剧情模型的要求会干扰更新模型）。接口、密钥、头部提示词、请求方式和具体的预设名是玩家本机的设置，不能推荐。
5. 条目要按剧情状态切换时（例如前后两套规则二选一），分步更新按**被解析那一楼**的变量选择和渲染条目。两种写法任选：
   - **条目过滤器**：在角色卡脚本里 `Era.registerEntryFilter('卡名.规则二选一', (entry, ctx) => …)`（前端模板项目用 `util/era.ts` 的 `registerEraEntryFilter`）。`ctx.stat` 是目标楼的变量；返回 `false` 排除，`true` 纳入（文件里关闭的条目也能纳入），字符串表示纳入并替换内容，其他值不表态。必须是同步纯函数。
   - **EJS**（需要提示词模板插件）：条目里的 `<% %>`、`@@if` 按目标楼的变量渲染，`setvar` 等写函数在这个流程里不执行。分步更新设置 `EJS预处理`（`自动` / `关闭`，默认 `自动`）控制是否渲染，也可以写进角色卡变量 `ERA分步更新` 推荐。

   条目过滤器也作用于主生成（`ctx.purpose` 为 `main`，按最新变量，只在内存里选条目，不写世界书文件），同一个函数让剧情模型和更新模型拿到同一套条目。改造用脚本改写世界书开关（`replaceWorldbook` 改 `enabled`）的旧卡时，按 `docs/era/08-动态提示词.md` 的迁移步骤换成过滤器。只用 EJS、不用过滤器的卡，主生成在滑动重新生成时 EJS 可能读到回滚前的变量（ERA 只在提示词里有 ERA 宏时才等同步完成再放行），第 9 步要专门测滑动。

**正文前规划（可选）**：检定、骰点要在正文之前定下来的卡（战斗、技能判定），建名字带 `[era_plan]` 的规划规则条目，写清哪些行动要检定、怎么判定、改哪些变量；在角色卡变量 `ERA分步更新` 里推荐 `正文前规划: '开启'`。玩家发送时，规划模型先结算，结果作为 `<era_plan>` 追加在玩家消息里、发送时就执行，摘要在生成前注入提示词，剧情模型按结果写。规划里只能写结果数值，不能用 `$expr` 和工具。旧卡要先“更新旧卡的规则”让隐藏正则认识 `<era_plan>`。用到它的卡把 `ERA最低版本` 写成 `2.0.0`。

详见 `docs/era/06-分步更新.md`。

## 第 8 步：脚本设置建议

| 设置 | 建议 |
| --- | --- |
| `数组内保留对象` | 新卡建议开启；**发布前定好，之后不要改**（会改变重算结果） |
| `宽松解析` | 开启（默认），修复 AI 写坏的 JSON；发布前定好，之后不要改 |
| `繁体转简体` | AI 常输出繁体时开启；发布前定好，之后不要改 |
| `思考标签` | ；默认 `think, thinking`，这些标签里的指令不执行。按玩家常用的预设增删（如 `reasoning`）；发布前定好 |
| `指令外层标签` | ；默认留空。要求 AI 把指令包在某个标签里（如 `<ERA_Update>`）时填写，之后只执行标签内的指令。**在新聊天开始前设好**，见下文 |
| `指令失败提示` | 制卡调试时开启，看到哪条指令没生效、为什么 |
| `调试模式` | 制卡调试时开启，ERA 的警告和错误会弹窗显示 |
| `下划线只读` | 用了 `_` 开头的只读字段时开启；发布前定好，之后不要改 |
| `日志保留楼层数` | 预计聊天很长（几百楼以上）时设为 50~100，聊天文件更小；越小，能直接回滚、查询的旧楼越少 |
| `折叠日志存档` | 配合上一项，需要回看旧楼快照时开启 |
| `API写入不修改消息` | 前端用写入事件（而不是 `Era.commit`）频繁写变量时开启 |

“发布前定好”的几项：ERA 重算历史楼层时按**当前**设置执行，中途修改会让已有聊天的变量在下一次重算时变化。

**思考块与外层标签**：`思考标签` 和 `指令外层标签` 只对 新建的聊天生效，更早的聊天照旧全文执行指令。`指令外层标签` 要在新聊天开始时就设好：聊天进行到一半才开启，之前没有包外层标签的楼层在下次重算时指令全部失效，变量会变。开启时在 `ERA 变量意图说明` 里要求 AI 把指令块放进这个标签；外层标签本身不在 ERA 的隐藏正则里，要另写正则隐藏。

**声明需要的 ERA 版本**：卡用到 `$expr`、条目过滤器、`{{ERA-issues}}`、`思考标签` 等功能时，在角色卡变量里写 `ERA最低版本: '2.0.0'`，玩家的 ERA 低于它时加载角色卡会提示一次。较早版本的 ERA 不认识这个变量；需要它们也提示时，在角色卡脚本或前端里调用 `util/era.ts` 的 `await requireEra('2.0')`（不满足时弹窗并返回 `false`）。

## 第 9 步：测试

逐项确认，有问题回到对应步骤：

- [ ] 新开聊天：变量与初始值一致；`{{ERA-schema}}` 的内容正确（控制台执行 `Era.describeSchema()` 查看）。
- [ ] 正常聊 5~10 楼：每楼都有指令，变量变化合理；开着 `指令失败提示` 时没有反复出现的报错。
- [ ] 故意让 AI 写错（越界数值、不存在的选项）：被拦下并提示，变量不被破坏。
- [ ] 滑动到另一个回复、再滑回来：变量随之切换、恢复。
- [ ] 删除最后几楼、编辑中间一楼：变量回到正确状态。
- [ ] ERA 面板“工具 → 完全重算”：结果与重算前一致。
- [ ] 状态栏和前端在以上操作后都显示正确；楼层状态栏按设计显示最新值或那一楼当时的值。
- [ ] 在酒馆助手脚本库里关闭再开启 ERA 脚本、再发一条消息后，`Era.hasSchema()`、`Era.hasHook(…)` 仍为 `true`（用 `registerEraSchema` / `registerEraHook` 时会自动补注册，否则需要重新加载角色卡脚本）。
- [ ] 开启分步更新的卡：剧情回复里没有指令，更新模型的结果写回对应楼层。
- [ ] 按状态切换条目的卡：重新解析状态切换前后的楼，更新模型拿到的是对应的条目；用 EJS 的，滑动重新生成后条目按滑动后的变量选择。
- [ ] 用了 `$expr` 的卡：删楼、滑动、完全重算后骰点不变。
- [ ] 面板“诊断 → 结构诊断”没有问题。

检查变量时，可以在快速回复或 STscript 里用 `/era-get 路径` 读取变量、`/era-issues` 列出最新一楼没生效的指令。

## 常见错误

| 现象 | 原因与处理 |
| --- | --- |
| AI 写了指令但变量不变 | 路径不存在（`<VariableEdit>` 只改已有路径）、被 schema 拦下、或 JSON 写坏。开 `指令失败提示` 看原因 |
| 之后的 `<VariableInsert>` 不生效 | 路径已存在。改用 `<VariableEdit>` 或 `<VariablePatch>` 的 `replace` |
| 指令块显示在聊天里 | 隐藏正则缺失或是旧版，用面板的“更新旧卡的规则” |
| `$expr` 被原样存成对象 | 写在了 `<VariableInsert>` / `<VariablePatch>` 里，只有 `<VariableEdit>` 会求值 |
| `$expr` 没有生效、变量不变 | 目标字段当前不是数字或路径不存在。开 `指令失败提示` 看原因（如“$expr 只能用于数字变量”） |
| AI 在思考块里举例的指令被执行 | 聊天是较早版本的 ERA 建的（照旧执行），或预设的思考标签不在 `思考标签` 里 |
| 开启 `指令外层标签` 后旧楼的变量变了 | 聊天中途开启，之前没包外层标签的指令失效。关掉该设置，或新开聊天 |
| 开了分步更新但没有请求更新模型 | 剧情模型自己写了指令（其他条目或预设还在要求输出），或没有带 `[era_update]` 的条目 |
| 钩子让变量越来越大 | 钩子依赖了闭包状态或不是幂等的，只能依赖 `ctx` |
| 钩子报错，它的修改没有生效 | 钩子里调用了 `Era.commit` 等写入接口或发了写入事件（会被拒绝） |
| 每次打开聊天，天气等随机值都会变 | 脚本在 `era:writeDone` 里用 `Math.random()` 回写变量。改成钩子，见第 6 步 |
| 前端发消息后变量慢一拍 | 发送前没有 `await Era.extra.wait()` |
