# ERA 快速上手

本文带你从零做出一张能用的 ERA 变量卡，按顺序做完大约 10 分钟。

ERA 是一个酒馆助手（Tavern Helper）脚本。它的工作方式是：

1. AI 在回复末尾写 `<VariableInsert>`、`<VariableEdit>` 等**指令块**；
2. ERA 读取指令块，更新这个聊天的变量（聊天变量 `stat_data`）；
3. 删除、滑动（swipe）、编辑消息时，ERA 自动回滚并重算变量。

指令块写在消息正文里，正文就是变量的来源。玩家看不到指令块，是因为局部正则把它们隐藏了。

## 0. 导入 ERA 脚本

在酒馆中打开你的角色卡，进入 **酒馆助手 → 脚本库 → 角色脚本**，新建一个脚本。内容二选一：

| 方式 | 脚本内容 | 特点 |
| --- | --- | --- |
| 在线导入（推荐） | `import 'https://testingcf.jsdelivr.net/gh/Bailuci/ERA-Heron@v2.0.1/artifact/bundle.js';` | 固定在这个版本，升级时只改版本号（见[版本标签](https://github.com/Bailuci/ERA-Heron/tags)）；把 `@v2.0.1` 换成 `@main` 则总是取最新版，但 jsDelivr 对 `@main` 最多缓存 7 天 |
| 粘贴全文 | 把 [`artifact/bundle.js`](https://github.com/Bailuci/ERA-Heron/blob/main/artifact/bundle.js) 的全部内容粘进去 | 版本固定，不依赖网络 |

`import '网址'` 是酒馆助手脚本加载在线脚本的标准写法。`testingcf.jsdelivr.net` 是 jsDelivr 的一个镜像；打不开时可以把域名换成 `fastly.jsdelivr.net` 或 `cdn.jsdelivr.net`。

保存后确认这个脚本和“角色脚本”总开关都已启用。页面上出现 ERA 悬浮球，就说明脚本在运行。点悬浮球可以打开 ERA 面板。

> 为什么用**角色脚本**而不是全局脚本：角色脚本跟着角色卡一起导出，玩家导入卡就能用，不用另外安装。

**卡依赖新版功能时声明最低版本**：卡里用到了 `$expr`、`{{ERA-issues}}`、工具调用、条目过滤器等功能时，在酒馆助手的“变量管理器”→“角色卡”中添加变量 `ERA最低版本`，值写 `2.0.1`。玩家的 ERA 低于这个版本时，打开这张卡会弹一次“版本过低”的提示。较早版本的 ERA （包括原版 ERA）不认识这个变量，不会提示；卡片脚本里需要确认时，用 `util/era.ts` 的 `requireEra('2.0.1')`，见 [05-接口与设置](./05-接口与设置.md#eraversion--erafeatures)。

## 1. 开启局部正则

在酒馆的 **扩展 → 正则** 中，为当前角色卡开启**局部正则**（Scoped Scripts）。

下一步要往卡里写正则。局部正则没有开启时，“ERA 快速初始化”会提示“当前角色卡未开启局部正则”，并且什么都不做。

## 2. 点“ERA 快速初始化”

先用这张卡开一个聊天，并确保开场白不是空的（开场白为空时，按钮会提示你先在开场白里写点内容）。

然后点 **悬浮球 → 面板 → 工具 → ERA 快速初始化**。它会创建：

| 类型 | 名字 | 作用 |
| --- | --- | --- |
| 局部正则 | `ERA 数据隐藏正则` | 从显示和提示词中去掉 `<VariableInsert>`、`<VariableEdit>`、`<VariableDelete>`、`<VariablePatch>` 指令块 |
| 局部正则 | `ERA 元数据隐藏正则` | 去掉 `<era_data>` 块 |
| 局部正则 | `ERA 思考块隐藏正则` | 去掉 `<VariableThink>` 块 |
| 局部正则 | `ERA 状态栏模板` | 把 AI 消息末尾的 `<StatusPlaceHolderImpl/>` 替换成状态栏（只影响显示） |
| 局部正则 | `ERA 状态栏占位符隐藏正则` | 从发给 AI 的提示词中去掉 `<StatusPlaceHolderImpl/>`（只影响提示词） |
| 世界书条目 | `ERA 变量操作规则` | 告诉 AI 指令怎么写。蓝灯，深度 0，system |
| 世界书条目 | `ERA 变量意图说明` | 由你填写，说明每个变量的含义（见第 6 步）。蓝灯，深度 0，system |

- 两个条目写进角色卡的**主世界书**。卡还没有绑定主世界书时，会先新建一本并绑定。
- 同名的正则或条目已经存在时会跳过，不会覆盖。
- 条目名中间有一个空格，**不要改名**。分步更新只按这两个名字识别它们。
- 规则条目的原文在 `初始模板/ERA角色卡/新建为src文件夹中的文件夹/世界书/ERA/变量操作规则.txt`，一般不需要改。想补充规则，写进“ERA 变量意图说明”。

注意：隐藏正则也会从**发给 AI 的提示词**里去掉历史消息中的指令块。所以 AI 看不到以前写过的指令，必须靠第 6 步把当前变量发给它。

## 3. 设计变量

变量是一棵 JSON 树，用点号路径访问，例如 `主角.体力`。设计时遵守下面几条：

**集合用对象，不用数组。** 背包、人物表这类会增删的集合，写成“键 → 条目”的对象：

```json
"背包": { "治疗药水": { "数量": 3 }, "短剑": { "数量": 1 } }
```

不要写成 `"背包": [ { "名字": "治疗药水", "数量": 3 } ]`。原因：

- 脚本设置 `数组内保留对象` 默认关闭。关闭时，数组里的对象会被存成 JSON **字符串**，例如 `[{"a":1}]` 存成 `["{\"a\":1}"]`。状态栏读到的是字符串，指令也改不了里面的字段。
- 对象可以按键直接新增、修改、删除单个条目；数组只能按下标操作，下标会随增删变化，AI 很容易写错。

纯文本的列表（例如标签 `["勇敢", "冲动"]`）可以用数组，增删元素用 `<VariablePatch>`。

**键要稳定。** 条目的键用唯一的名字或编号（`村长`、`npc_001`），之后所有指令都靠它定位。

**只读字段用 `_` 开头。** 例如 `_姓名`。在 ERA 设置中开启 `下划线只读` 后，AI 的指令不能修改或删除以 `_` 开头的字段（仍能插入新的）；钩子和 `Era.commit` 不受限制。注意 `era:updateByObject` 等写入事件默认会把指令写进正文，同样受限，详见 [05-接口与设置](./05-接口与设置.md) 的 `下划线只读`。这个设置默认关闭。

**`$meta` 保护节点。** 写在节点里，防止 AI 误操作：

| 写法 | 效果 |
| --- | --- |
| `"$meta": { "updatable": false }` | 该节点及其子孙不能被 `<VariableEdit>` 修改 |
| `"$meta": { "necessary": "self" }` | 该节点本身不能被删除，子节点可以 |
| `"$meta": { "necessary": "children" }` | 直属子节点不能被删除，节点本身可以 |
| `"$meta": { "necessary": "all" }` | 该节点及其所有子孙都不能被删除 |
| `"$meta": { "unInsertAble": "self" }` 或 `"all"` | 禁止在该节点下新增键（`all` 包括所有层级） |

**`$template` 给新条目补默认值。** 写在集合对象里。之后 AI 用 `<VariableInsert>` 新增条目时，只需写与模板不同的字段，其余字段从模板补齐：

```json
"人物": {
  "$template": { "好感": 0, "状态": "陌生" },
  "村长": { "好感": 10, "状态": "友好" }
}
```

AI 插入 `{"人物": {"猎人": {"状态": "警惕"}}}`，结果是 `"猎人": {"好感": 0, "状态": "警惕"}`。开场白里同时写入的条目请写全字段。

`$meta` 和 `$template` 不会出现在 `{{ERA:...}}` 宏的结果里，AI 和状态栏通常看不到它们。完整规则见 [02-指令手册](./02-指令手册.md)。

## 4. （可选）注册变量结构

变量多、类型严格时，可以用 zod 写一份变量结构（schema），在角色脚本中注册（可以另建一个角色脚本）：

- 指令写入的值不符合结构时，这次修改会被丢弃，并发出 `era:schemaError` 事件；
- 缺少的字段按结构补默认值；
- 宏 `{{ERA-schema}}` 会输出结构的文字说明（类型、可选值、范围），第 6 步会用到。

写法见 [示例/变量结构与钩子脚本示例.js](./示例/变量结构与钩子脚本示例.js) 和 [05-接口与设置](./05-接口与设置.md) 中的 `Era.registerSchema`。同一个示例还演示了 `Era.onAfterApply` 钩子，例如“时满 24 进位到天”这类规则可以交给钩子，而不是让 AI 计算。

注册后，可以在面板的 **诊断** 页检查当前变量是否符合结构；旧存档缺了新加的必填字段时，那里能一键修复。

不注册也完全可以用，跳过这一步即可。

## 5. 在开场白中初始化变量

在开场白末尾用**一个** `<VariableInsert>` 写入**全部**变量的初始值：

```
你在村口醒来，晨雾还没散。

<VariableInsert>
{
  "主角": {
    "_姓名": "林远",
    "体力": 100,
    "体力上限": 100,
    "金钱": 50,
    "$meta": { "necessary": "self" }
  },
  "背包": {
    "$template": { "数量": 1, "描述": "" },
    "治疗药水": { "数量": 3, "描述": "恢复 30 点体力" }
  },
  "人物": {
    "$template": { "好感": 0, "状态": "陌生" },
    "村长": { "好感": 10, "状态": "友好" }
  },
  "时间": { "天": 1, "时": 8 },
  "地点": "起始村庄"
}
</VariableInsert>
```

- **每一条**备选开场白（alternate greetings）也要写自己的完整初始化。备选开场白就是第 0 楼的其他 swipe，玩家选哪条，就从哪条的变量开始。
- 内容必须是合法 JSON：键用双引号，最后一项后面不要有逗号。
- 改完开场白后**开一个新聊天**。已有聊天里的开场白是创建聊天时复制的，不会跟着变。
- 新聊天里看不到这个指令块，是第 2 步的隐藏正则在起作用。打开 ERA 面板可以看到变量。

## 6. 填写“ERA 变量意图说明”

打开主世界书中的 `ERA 变量意图说明` 条目（名字中间有一个空格，必须一字不差）。快速初始化生成的内容是一份骨架：

```
{{// 填写说明（这一段不会发给 AI）…… //}}
<变量说明>
- 【路径】: ……
</变量说明>

<变量结构>
{{ERA-schema}}
</变量结构>

<当前变量>
{{ERA:$ALLDATA}}
</当前变量>
```

**后两段必须保留。** 在默认的“随 AI 输出”模式下，ERA 不会自己把变量结构和当前变量发给 AI，只靠这两个宏：

| 宏 | 发给 AI 时替换为 |
| --- | --- |
| `{{ERA:$ALLDATA}}` | 当前全部变量的 JSON（不含 `$meta`、`$template`） |
| `{{ERA-schema}}` | 第 4 步注册的结构说明；没有注册时为空，可以保留 |

旧卡的这个条目可能只有一行注释。请照上面的样子补上 `<变量结构>` 和 `<当前变量>` 两段。“更新旧卡的规则”只在这个条目**从未改动过**（仍是最早版本的那一行注释）、并且卡里找不到任何 `{{ERA:...}}` 宏时替你补上；改动过的条目不会被修改，只会提示。

然后把 `<变量说明>` 换成你的变量。每个路径写清楚：**什么时候改、改多少、用哪种指令**。以第 5 步的变量为例：

```
<变量说明>
- `主角.体力`: 0 到 `主角.体力上限` 之间的整数。受伤、劳累时减少，休息、用药时恢复。用 <VariableEdit>，写 "-=数值" 或 "+=数值"。
- `主角.金钱`: 非负整数。买卖、获得报酬时用 <VariableEdit> 的增量写法。
- `主角._姓名`: 只读，不要修改。
- `背包`: 键是物品名。获得新物品用 <VariableInsert>，只写与模板不同的字段；数量变化用 <VariableEdit>；用完或丢弃时用 <VariableDelete> 删除整个物品。
- `人物`: 键是人物名。重要人物第一次登场时用 <VariableInsert> 新增。每次互动后好感变化 -5 到 +5，用 <VariableEdit>。
- `时间.天`、`时间.时`: 按剧情推进。`时` 满 24 时归零，并让 `天` 加 1。
- `地点`: 场景变化时用 <VariableEdit> 改为新地点名。
</变量说明>
```

更长的写法参考 [示例/变量意图说明示例.txt](./示例/变量意图说明示例.txt)。也可以把说明拆到其他世界书条目里；开启分步更新时，这些条目的名字要加 `[era_update]`（见第 8 步）。

## 7. 状态栏

ERA 默认在每条 AI 消息末尾加一个占位符 `<StatusPlaceHolderImpl/>`，局部正则 `ERA 状态栏模板` 把它替换成状态栏；`ERA 状态栏占位符隐藏正则` 把它从发给 AI 的提示词里去掉。你只需编辑 `ERA 状态栏模板` 的“替换为”，换成自己的 HTML，**不要再新建一条**。

快速初始化生成的默认状态栏读取的正是第 5 步示例开场白里的变量（`主角`、`人物`、`时间`、`地点`），可以拿来对照，再改成自己的。

在 HTML 中读变量有两种方式：

- 宏：直接写 `{{ERA:主角.体力}}`；
- 事件：用 `Era.getCurrentVars()` 取初值，再 `eventOn('era:writeDone', ...)` 监听更新。

做法和注意事项见 [03-状态栏](./03-状态栏.md)，宏的完整语法见 [04-宏](./04-宏.md)。

## 8. （可选）分步更新

默认由剧情模型在正文之后顺便写指令。也可以改成剧情写完后，ERA 再请求另一个模型专门写指令。这样剧情模型更专注，变量更新也更稳定。

设置在 **悬浮球 → 面板 → 分步更新**。只给更新模型看的世界书条目，名字里要加 `[era_update]`。详见 [06-分步更新](./06-分步更新.md)。

## 9. 测试清单

开一个新聊天，逐项检查：

- [ ] 开场白里的指令块看不到；ERA 面板里能看到初始变量。
- [ ] 聊几轮：AI 在正文后写了 `<VariableThink>` 和指令块，聊天里看不到它们，变量按剧情变化。新建的聊天里，写在思考块（默认 `<think>`、`<thinking>`）里的指令不执行，指令要写在思考块之后。
- [ ] 对最后一楼 swipe 重新生成：变量先回到上一楼的状态，再按新回复计算。
- [ ] 删除最后一楼：变量回到删除前一楼的状态。
- [ ] 编辑某一楼中的指令块：变量按修改后的内容重算。
- [ ] 点面板 **工具 → 完全重算**：结果与之前一致。
- [ ] 在 **ERA 设置** 中开启 `指令失败提示`：最新一条消息中有指令没有生效时会弹窗，写明路径和原因。
- [ ] 在输入框发送 `/era-get 主角.体力 | /echo`：弹出这个变量的当前值（JSON），路径写法与 `{{ERA:路径}}` 相同。发送 `/era-issues | /echo`：弹出最新一条 AI 消息里没有生效的指令和原因，全部生效时为空。这两个命令只把结果交给下一个命令，单独发送时界面上不显示，所以要接 `| /echo`。
- [ ] 按 F12 打开控制台，试算一条指令（不会写入变量）：

```javascript
await Era.simulate('<VariableEdit>{"主角":{"体力":"-=10"}}</VariableEdit>');
// 返回 { stat: 试算后的变量, problems: [{ path, reason }] }，problems 为空表示指令都能生效
```

如果 AI 经常写错，先看 `指令失败提示` 或 `/era-issues` 给出的原因，再修改第 6 步的说明。也可以在 `ERA 变量意图说明` 末尾加上 `{{ERA-issues}}`：上一条回复里有指令没有生效时，它会把路径和原因放进下一轮的提示词，没有问题时为空，写法见 [04-宏](./04-宏.md#把指令问题告诉-aiera-issues)。其他问题见 [07-常见问题与排错](./07-常见问题与排错.md)。

## 10. 导出前检查

| 内容 | 是否随角色卡导出 |
| --- | --- |
| 角色脚本（ERA 脚本、你的 schema 脚本） | 是 |
| ERA 设置（保存在 ERA 角色脚本的脚本变量里） | 是 |
| 局部正则（5 条 ERA 正则） | 是 |
| 主世界书（含两个 ERA 条目） | 是，导出时嵌入卡中 |
| 角色卡变量（`ERA最低版本`、`ERA分步更新` 等） | 是 |
| 分步更新的设置 | **否**，保存在本机的全局变量里，玩家需要自己设置 |

玩家导入卡后，需要允许角色脚本和局部正则运行。

**旧卡升级：** 用旧版 ERA 做的卡，点面板 **工具 → 更新旧卡的规则**。它会：

- 用新版内容覆盖所有已绑定世界书中的 `ERA 变量操作规则` 条目；
- 把 `ERA 数据隐藏正则`、`ERA 元数据隐藏正则`、`ERA 思考块隐藏正则` 的“查找”更新到新版（新版能隐藏 `<VariablePatch>`），其他选项保留；
- 补上缺少的 `ERA 元数据隐藏正则`、`ERA 思考块隐藏正则`、`ERA 状态栏占位符隐藏正则`（只对已有 `ERA 数据隐藏正则` 的卡）；
- `ERA 变量意图说明` 仍是最早版本的一行注释、卡里又找不到任何 `{{ERA:...}}` 宏时，在它后面补上 `<变量结构>` 和 `<当前变量>` 两段；
- 原来的条目和正则另存为关闭的备份，名字后面加“（更新前的备份）”。

找不到规则条目时，它会提示先做快速初始化；找不到变量宏时，它会提示按第 6 步补上，不会报告“已经是最新版本”。

如果你改过规则条目，更新后这些修改不会再生效，请把它们移到 `ERA 变量意图说明` 里。改动过的 `ERA 变量意图说明` 和你的状态栏不会被改动。
