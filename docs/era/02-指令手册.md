# ERA 指令手册

AI 在回复正文里写指令块，ERA（一个酒馆助手脚本）读取它们，更新当前聊天的变量 `stat_data`，并为每一楼记录日志。删除、滑动（swipe）或编辑消息时，变量会按日志回滚并重算。

- 指令块在显示时由角色卡局部正则“ERA 数据隐藏正则”隐藏，玩家看不到。
- AI 怎样写指令，由世界书条目“ERA 变量操作规则”告诉它。新卡在 ERA 面板点“ERA 快速初始化”即可创建这些条目和正则，见 [01-快速上手](./01-快速上手.md)。

本文说明四个变量指令（`<VariableInsert>`、`<VariableEdit>`、`<VariableDelete>`、`<VariablePatch>`）、`<VariableEdit>` 中的表达式 `$expr`，以及脚本工具调用 `<EraFCall>`。

## 选哪个指令

| 想做的事 | 用 |
| --- | --- |
| 新建变量、补充新字段（已存在的不动） | `<VariableInsert>` |
| 修改已存在的值，数字加减乘除 | `<VariableEdit>` |
| 按公式计算数字、掷骰 | `<VariableEdit>` 中写 `{"$expr": "表达式"}`，见 [表达式 `$expr`](#表达式-expr) |
| 删除字段或整个对象 | `<VariableDelete>` |
| 有则改无则建、把字段整体换成对象、数组增删、改名、复制、文本追加、开关切换 | `<VariablePatch>` |
| 交给作者写的程序结算（战斗、交易、合成等多步逻辑） | `<EraFCall>`，见 [工具调用](#工具调用-erafcall)，需要角色卡注册工具 |

## 通用写法

- 指令块的内容是 JSON。Insert / Edit / Delete 写一个对象，结构与变量树相同；Patch 写一个操作数组。
- 一个指令块里可以连写多个 JSON 对象（例如每行一个），按顺序执行，后一个能看到前一个的结果。
- 一条消息里可以有多个指令块，按它们在正文中出现的顺序执行。
- 指令写在用户消息里同样有效：发送时立即执行，结果与之后重算一致。（更新钩子 `Era.onBeforeApply` / `Era.onAfterApply` 只对 AI 消息执行。）
- 可以写 `//` 和 `/* */` 注释，也可以把内容放在 ` ``` ` 代码块里。
- 脚本设置“宽松解析”（默认开）会尝试修复尾逗号、单引号、全角标点、缺少收尾括号等小错误。
- `$meta` 和 `$template` 是保留键：`$meta` 存放保护规则，`$template` 存放模板。
- 指令没有生效时（路径不存在、受保护、无法解析等），ERA 会跳过它，继续执行其余部分，并广播 `era:commandError` 事件。开启脚本设置“指令失败提示”后还会弹窗。详见 [05-接口与设置](./05-接口与设置.md)。要让 AI 在下一轮看到自己哪里写错了，可以在提示词里放 `{{ERA-issues}}` 宏，见 [04-宏](./04-宏.md#把指令问题告诉-aiera-issues)。
- 新建的聊天中，思考块里的指令不执行；还可以设置只认某个外层标签里的指令。见下一节。

## 思考块与指令外层标签

很多预设要求模型先写思考块。思考里打草稿、举例写出的指令，以前会和正文里的一样被执行。新建的聊天在解析前先把思考块的内容遮蔽掉，其中的指令不执行；也可以设置“指令外层标签”，只执行包在这个标签里的指令。

### 只对新聊天生效

ERA 第一次往一个聊天写入数据时，在聊天变量 `ERAMetaData` 里记下 `ParserVersion: 3`，之后这个聊天的每次重算都按这种方式解析。

- 没有这个标记的聊天（较早版本的 ERA 建立的）保持原来的解析方式：思考块里的指令照旧执行，“指令外层标签”不起作用，重算结果与以前相同。旧聊天不会被自动升级。
- “新聊天”指 `ERAMetaData` 为空的聊天。玩家清空了聊天变量的旧聊天，也会被当成新聊天。
- 用较早版本的 ERA 打开新建的聊天，会重新执行思考块里的指令，重算结果可能不同。
- 保护规则里标了“只对新建的聊天生效”的几条（整体覆盖对象、用 `null` 删除子节点、Patch 改动 `$meta`）同样按这个标记判断：`ParserVersion` 小于 3 的聊天保持原来的结果。

### `思考标签`（默认 `think, thinking`）

脚本设置，列出要遮蔽的思考标签。

- 用逗号、顿号或空格分隔，可以带尖括号（`<think>, <reasoning>`）。不区分大小写，标签可以带属性。按你的预设增删；留空表示不遮蔽。
- 嵌套的思考标签按层配对。
- 没有闭合的思考标签一直遮蔽到正文结尾（回复被截断时常见）。
- 前面没有开始标签的闭合标签（有的接口会丢掉开头的 `<think>`）：从正文开头到这个闭合标签都算思考。
- ERA 自己的 `<VariableThink>` 不在默认列表里，需要时自己加上。
- 分步更新时，额外模型的输出在取出指令前同样按这个设置遮蔽（新旧聊天都是），并且总是包括 `think`、`thinking`，见 [06-分步更新](./06-分步更新.md)。

### `指令外层标签`（默认空）

脚本设置。填上 `ERA_Update`（或 `<ERA_Update>`）后，新聊天里只执行 `<ERA_Update>…</ERA_Update>` 之内的指令，外面的一律不执行。适合要求 AI 把变量更新统一写在某个标签里的卡：正文中引用、讨论的指令不会被误执行。

```xml
<ERA_Update>
<VariableEdit>
{ "player": { "hp": "-=10" } }
</VariableEdit>
</ERA_Update>
```

- 不区分大小写。外层标签没有闭合时，一直算到正文结尾。写在思考块里的外层标签不算。
- 分步更新写进正文的 `<era_extra>` 区段不受这个限制，照常执行。
- 默认设置下，`era:*` 写入事件追加到正文的指令块会自动包在外层标签里。
- ERA 的规则条目和隐藏正则不知道这个标签。要在自己的提示词里要求 AI 使用它；标签本身需要隐藏时，自己加一条正则。

**在新聊天开始时就设好，不要中途开启。** 这两个设置保存在 ERA 脚本里，不随聊天保存。重算时（删除、滑动、编辑消息，或完全同步）新聊天的每一楼都按**当前**设置重新解析。聊天进行到一半才开启“指令外层标签”，之前没有包外层标签的楼层在下次重算时指令全部失效，变量会跟着改变。中途关闭、改名，或修改“思考标签”，同样会让历史楼层按新设置重新解释。已有聊天中途开启前，先确认能接受这个结果。旁路写入挂在哪一楼、哪一块不受影响，不会错位。

### `<era_extra>` 区段

分步更新把额外模型的输出包在 `<era_extra>…</era_extra>` 里追加到正文末尾（见 [06-分步更新](./06-分步更新.md)）。新聊天中只有符合下面条件的才算这样的区段，才不受思考遮蔽和外层标签的限制：

- 必须闭合。只有开始标签的 `<era_extra>` 字样不算，也不会让后面的内容整段生效。
- 开头落在一个已闭合的思考块里的不算：主模型在思考里提到或举例的 `<era_extra>` 不会生效。
- 正文里的思考块没有闭合（主回复被截断）时，末尾追加的区段仍然算。
- 前面没有开始标签的 `</think>` 之前的不算。

## `<VariableInsert>`（插入）

**用途**：添加新数据。它不会修改或覆盖已经存在的值。

### 核心行为

- **只增不改**：只在不存在的路径上创建值。路径已有值时跳过（并报告“路径已存在”）。
- **补充结构**：父路径已存在时，在它下面补充新的子键。
- **整体插入**：父路径不存在时，把整个对象一次插入。

### `$template`（模板）

插入一个新对象时，ERA 会查找可用的模板，把模板内容作为缺省值，再用指令中的数据覆盖。

- **父级模板**：某个节点的 `$template`，会用于它的**直接子节点**。
- **嵌套模板**：模板里还可以写子键（例如 `"follower": { ... }`），用于新对象中同名的子节点；子节点模板里还可以有自己的 `$template`。
- **优先级**：
  1. 变量中**已经存在**的 `$template` 优先。
  2. 其次是从更上层继承下来的模板。
  3. 指令中写的 `$template` 只有在变量里还没有这个键时才会被插入，它不会覆盖已有的模板（Insert 只增不改）。
- 数组在合并时整体替换，不会逐项合并。

### 示例：使用模板

**第 1 步：定义带模板的结构**

```xml
<VariableInsert>
{
  "guild": {
    "$template": {
      "rank": "Rookie",
      "contribution": 0,
      "$meta": { "updatable": true }
    }
  }
}
</VariableInsert>
```

**第 2 步：插入新成员**

```xml
<VariableInsert>
{ "guild": { "Alex": { "class": "Warrior" } } }
</VariableInsert>
```

`Alex` 是 `guild` 的直接子节点，继承 `guild.$template`。结果：

```json
{
  "guild": {
    "$template": { "rank": "Rookie", "contribution": 0, "$meta": { "updatable": true } },
    "Alex": {
      "rank": "Rookie",
      "contribution": 0,
      "$meta": { "updatable": true },
      "class": "Warrior"
    }
  }
}
```

### `$meta.unInsertAble`（插入保护）

在节点的 `$meta` 里写 `unInsertAble`，禁止在它下面新增内容。根节点同样适用。

| 值 | 效果 |
| --- | --- |
| `"self"` | 不能在该节点下新增直属子键；已有的子键下面仍可继续插入。 |
| `"all"` | 除 `$meta` 外，拒绝经过该节点的一切插入。 |

- 只写 `$meta` 的插入总是放行。
- 要解除保护，用 `<VariableEdit>` 修改或 `<VariableDelete>` 删除 `$meta.unInsertAble`。
- `<VariablePatch>` 新建键时同样受此限制。

## `<VariableEdit>`（修改）

**用途**：修改已经存在的值。

### 核心行为

- **只改不增**：路径不存在时跳过（并报告“路径不存在”）。
- **按叶子修改**：指令中的值是对象时，ERA 只会向下进入已存在的子键，逐个修改叶子值。
  - 例外：值是 `{"$expr": "…"}`、目标当前值是数字时，按表达式计算，见 [表达式 `$expr`](#表达式-expr)。
  - 因此 Edit **不能**给对象新增键，也**不能**把一个字段整体换成对象。整体替换请用 `<VariablePatch>` 的 `replace`。
  - 把一个对象字段改成数字、文本等非对象值是可以的。
- **数组整体替换**：值是数组时，用新数组替换整个旧数组。要增删单个元素，请用 `<VariablePatch>`。
- **相同的值也会记录**：新值与旧值相同时，同样写入并记录日志。

### 增量运算

叶子值可以写成运算式，基于当前值计算：

| 写法 | 含义 |
| --- | --- |
| `"+=5"` | 加 5 |
| `"-=5"` | 减 5 |
| `"*=2"` | 乘 2 |
| `"/=2"` | 除以 2 |

```xml
<VariableEdit>
{ "player": { "hp": "-=10", "gold": "+=25" } }
</VariableEdit>
```

- 当前值必须是数字，或内容是普通十进制数的文本（如 `"10"`）。运算结果是数字。
- 当前值不是数字时（如 `"Al"`），`"+=5"` 会被当作普通文本原样写入。
- 除以 0 或结果不是有限数字时，这一项被跳过，并报告原因。
- 同一条消息里对同一路径的多次运算会依次累加。

### 表达式 `$expr`

叶子值写成 `{"$expr": "表达式"}`，ERA 按表达式算出一个数字，写回这个字段。用于结果取决于其他字段的公式，以及掷骰。

| 场景 | 推荐做法 |
| --- | --- |
| 加减乘除一个固定数 | 直接用增量运算（`"+=5"`、`"-=10"`） |
| 这次更新需要参考其他字段或掷骰 | 在 `<VariableEdit>` 里用 `$expr` |
| 同一条公式反复用、又不想写脚本 | 把公式文本存成变量，在 `$expr` 里用 `call()` 调用 |
| 每一楼都要自动重算的派生数值（如上限、进位） | 写在角色卡脚本的更新钩子里（见 [05-接口与设置](./05-接口与设置.md#8-更新钩子)） |

```xml
<VariableEdit>
{ "player": { "hp": { "$expr": "min(player.hp + 20, player.max_hp)" } } }
</VariableEdit>
```

较早版本的 ERA 不认识这种写法，会报告“路径不存在”并跳过。用到 `$expr` 的卡可以在角色卡变量 `ERA最低版本` 里写 `2.0.2`，ERA 加载时会检查并提示。较早版本的 ERA 不认识这个变量；要让它们也提示，在角色卡脚本里调用 `util/era.ts` 的 `requireEra('2.0.2')`，见 [05-接口与设置](./05-接口与设置.md#eraversion--erafeatures)。

#### 什么时候生效

- **只在 `<VariableEdit>` 中**，也包括脚本按 Edit 方式写入的数据（`Era.commit` 的 `edit`、`era:updateByPath` 等，见 [05-接口与设置](./05-接口与设置.md)）。`<VariableInsert>`、`<VariablePatch>` 会把 `{"$expr": ...}` 当作普通对象原样存进变量。
- **目标必须已经存在，当前值必须是数字。** 当前值是文本（包括 `"10"` 这样的数字文本）、布尔值、数组或 `null` 时不生效，报告“$expr 只能用于数字变量”。目标是对象时，`{"$expr": ...}` 按普通对象处理，即修改它的 `$expr` 子键（没有这个子键就报告“路径不存在”）。目标不存在时报告“路径不存在”。
- `{"$expr": ...}` 只能有这一个键，值必须是文本，否则不算表达式。
- 照常受 `$meta.updatable` 和 `下划线只读` 限制。
- 写入日志与普通修改相同，回滚、重算都正确。

#### 写法

| 内容 | 写法 |
| --- | --- |
| 数字 | `12`、`0.5`、`.5`、`1e3` |
| 运算 | `+ - * /`、乘方 `^`、括号 `( )`、正负号。`^` 从右往左算，并且先于负号：`2^3^2` 是 512，`-2^2` 是 -4 |
| 读变量 | `player.hp`，用 `.` 分级。键名含 `-`、空格、括号、`.` 等字符时，把这一段用反引号括起来：``player.`hp(当前)` ``；数组元素写 `` `队伍[0]` ``，数组长度写 `队伍.length` |
| 本楼开始前的值 | `@player.hp`：读这一楼的指令执行之前的值（早于本楼的旁路写入和 schema 默认值）。`player.hp - @player.hp` 是本楼的变化量。本楼开始时不存在的路径会报错 |
| 常数 | 大写 `PI`（圆周率）、`E`（自然常数）。它们始终是常数；变量恰好叫 `PI`、`E` 时写成 `` `PI` ``、`` `E` ``。小写 `pi`、`e` 不是常数 |

- 读到的变量必须是有限数字。普通十进制写法的数字文本（如 `"10"`）也按数字读取；`"007"`、`"0x10"` 这类文本不算。
- 不能省略乘号：写 `2*atk`，不能写 `2atk` 或 `2(atk)`。
- 没有 `%`：取余用 `mod(x, y)`，“增加 50%”写成 `x * 1.5`。
- 没有比较、条件和逻辑运算（`>`、`==`、`?:`、`&&`）：取舍用 `min`、`max`、`clamp`。
- 反引号之外不能有引号。指令本身是 JSON，表达式里不要写双引号。
- 反引号之外的全角符号（`（）＋－×÷，` 和全角数字等）会先换成半角；反引号里的键名不变。
- 每一步运算、每次函数调用的结果都要是有限数字，出现除以 0、无穷大或无意义的结果时当场失败。
- 最终结果：整数原样写入；小数保留 15 位有效数字（吸收 `0.1 + 0.2` 这类误差）；`-0` 写成 0。
- 上限：表达式最长 1000 个字符、300 个记号；括号和函数最多嵌套 32 层；一个函数最多 16 个参数；一个表达式最多抽取 64 次随机数。超出时报错，拆成几条指令即可。

#### 函数

| 类别 | 函数 | 说明 |
| --- | --- | --- |
| 基础 | `abs(x)` `sign(x)` `floor(x)` `ceil(x)` `trunc(x)` | 绝对值、符号、向下取整、向上取整、去掉小数 |
| | `round(x)` `round(x, 位数)` | 四舍五入，.5 远离零：`round(2.5)` 是 3，`round(-2.5)` 是 -3。位数是 0～10 的整数 |
| | `min(a, b, …)` `max(a, b, …)` | 最小、最大值，1～16 个参数 |
| | `clamp(x, 最小值, 最大值)` | 限制在范围内；最小值大于最大值时报错 |
| | `pow(x, y)` `sqrt(x)` | 乘方（同 `^`）、平方根 |
| | `mod(x, y)` | 取余，结果与除数同号：`mod(-1, 7)` 是 6 |
| 指数与对数 | `exp(x)` `ln(x)` | e 的 x 次方、自然对数 |
| | `log(x)` `log(x, 底数)` | **`log(x)` 就是 `ln(x)`**，不是以 10 为底；`log(1000, 10)` 是 3 |
| | `log10(x)` `log2(x)` | 以 10、2 为底的对数 |
| 三角（弧度） | `sin(x)` `cos(x)` `tan(x)` `asin(x)` `acos(x)` `atan(x)` | 参数和结果都是弧度 |
| | `atan2(y, x)` | **y 在前**，与 Excel 的 `ATAN2(x, y)` 顺序相反 |
| | `rad(x)` `deg(x)` | 角度换弧度、弧度换角度：`sin(rad(30))` |
| 双曲 | `sinh` `cosh` `tanh` `asinh` `acosh` `atanh` | 一个参数 |
| | `hypot(x, y, …)` | √(x²+y²+…)，1～16 个参数 |
| 随机 | `roll(最小值, 最大值)` | 掷骰：两端都含的整数。`roll(1, 6)` 是一个六面骰，`roll(1, 100)` 是百分骰。参数必须是整数，最小值不大于最大值，最大值与最小值之差不超过 4294967295 |
| | `random()` | 0（含）到 1（不含）之间的小数，**不接受参数**；`random(1, 6)` 会报错，掷骰请用 `roll` |
| | `random_at(种子, 序号)` | 由两个数决定的伪随机小数，范围同 `random()`，与楼层和调用顺序无关：同样的参数在哪里都得到同样的结果。适合作者按坐标、编号生成固定的随机表 |

定义域不对时报错并说明原因，例如 `ln(0)`、`sqrt(-1)`、`asin(2)`、`0^-1`、`(-8)^0.5`。三角、指数、对数函数在各浏览器上逐位一致（ERA 自带数学库，不用浏览器的 `Math`），同一份聊天在电脑和手机上重算结果相同。

#### 存成变量的公式 `call`

同一个公式要反复用时，不必每次让 AI 把整条公式抄进 `$expr`：作者把公式文本存成一个普通的文本变量，AI 用 `call` 调用它。不需要写脚本，纯文字卡也能用。

```xml
<VariableInsert>
{ "公式": { "伤害": "max(1, a * 2 - b + roll(1, 6))", "治疗": "min(a + 10, 角色.生命上限)" } }
</VariableInsert>
```

AI 这样写：

```xml
<VariableEdit>
{ "敌人": { "生命": { "$expr": "敌人.生命 - call(公式.伤害, 主角.攻击, 敌人.防御)" } } }
</VariableEdit>
```

- **`call(公式路径, 参数1, 参数2, …)`**：第一个参数是存放公式文本的**变量路径**（写法与表达式里其他路径相同，可以用反引号段，`@公式.伤害` 读本楼开始前存的公式），其余参数是普通的数值表达式，按位置传给公式。`call` 的结果是公式算出的数字，可以和其他运算组合。
- **公式里用单独一个小写英文字母引用参数**：`a` 是第 1 个参数，`b` 是第 2 个，依此类推（最多 15 个参数，即 `a`～`o`）。公式的其余写法与 `$expr` 完全相同：可以读变量、用内置函数和用 `Era.registerExprFn` 注册的自定义函数、用 `roll` 与 `random`。
- **参数名与变量重名时**：在公式里，单独一个小写字母（`a`～`z`）一律当作参数，不读变量；要读一个恰好叫 `a` 的顶层变量，写成 `` `a` ``。多段路径（如 `a.b`）、带 `@` 的路径不是参数。在公式之外（直接写在 `$expr` 里），单个字母仍然是变量路径，与以前相同。
- **参数个数必须与公式用到的一致**：公式用到的最大字母决定参数个数（用到 `b` 就要 2 个参数）。少给或多给都会报错，例如“公式 公式.伤害 用到了第 2 个参数（a、b），但只给了 1 个”。
- **参数在调用处求值**：参数里的单个字母是调用处所在公式的参数，例如公式 `"call(公式.伤害, a + 1, 0)"` 里的 `a` 是这个公式自己的第 1 个参数。
- **随机数**：公式里的 `roll`、`random` 与外层表达式共用同一个随机序列，按求值顺序（先参数、后公式）依次取值，同一楼重算时骰点不变；抽取次数与外层合计，仍是每个 `$expr` 最多 64 次。
- **限制**：公式可以再 `call` 别的公式，最多嵌套 4 层（`$expr` 直接调用的算第 1 层）；公式不能直接或间接调用自己（`甲 → 乙 → 甲` 会报错）；一个 `$expr` 里（含被调用的公式）最多执行 64 次 `call`。每个公式的长度、记号数、括号嵌套与 `$expr` 的上限相同。
- **出错时**：公式路径不存在、存的不是文本（“公式.伤害 不是文本（当前值：5）”）、公式本身写错（“公式 公式.伤害 写错了：……”）或计算失败（“公式 公式.伤害 出错：……”）时，整条 `$expr` 失败，字段保持原值并报告原因。
- **公式就是普通变量**：受 `$meta.updatable` 保护，随楼层回滚、重算，不需要额外的存储。AI 用 `<VariableEdit>` 改写公式文本后，之后的楼层按新公式计算；删除、滑动那一楼时自动恢复旧公式。不想让 AI 改公式时，给存放公式的对象加 `"$meta": { "updatable": false }`。
- 公式文本里可以有 `.`、反引号段等，ERA 存储时的转义不影响求值。和 `$expr` 一样，公式里不要写引号。
- `call` 是保留名，`Era.registerExprFn` 不能注册名为 `call` 的函数。可以用 `Era.features?.includes('exprCall')` 判断 ERA 是否支持 `call`。

#### 随机数与重算

骰点由种子决定，同一楼重算时结果不变：

- 正文中的表达式，种子由三部分组成：这条消息的 MK（ERA 写在 `<era_data>` 里的消息标识）、目标字段的完整路径、这个路径在本楼正文中第几次进入求值（只计算目标当前值是数字的 `$expr`）。一个表达式里的多次 `roll`、`random` 按调用顺序依次取值。
- 删除、编辑其他楼层，或编辑本楼时增删别的路径的指令，本楼原有路径的骰点都不变。读到的变量变了，结果仍会跟着变，骰点本身不变。
- 目标是数字、但表达式本身算不出来的，也算一次，所以改掉一个写错的表达式，不会让本楼同一路径后面的骰点改变。目标不是数字、路径不存在或受保护而被跳过的不算；修正这类指令后，同一路径后面的骰点会跟着变。
- 滑动（swipe）生成新回复会得到新的 MK，骰点重新掷。
- 旁路写入（`Era.commit`、`Era.applyText`、开启 `API写入不修改消息` 后的写入事件）按它在本楼旁路写入中的执行顺序取种子；钩子新建的指令按钩子 id 和新建的先后取种子。它们都与正文的计数分开，撤销或合并旁路写入不会改变正文的骰点。`Era.simulate` 只能预览正文里的骰点，见 [05 的 `Era.simulate`](./05-接口与设置.md#erasimulate)。

#### 出错时

表达式算不出来时，这个字段保持原值，同一指令里的其他字段照常执行。ERA 报告一条问题：

```
$expr 计算失败：不支持 %：取余请用 mod(x, y)；百分比请写成乘法，例如 50% 写成 *0.5（表达式：player.hp * 50%）
```

这条问题和其他指令问题一样：广播 `era:commandError`，开启“指令失败提示”时弹窗。额外模型输出里的表达式出错时，会触发它的自动重试（见 [06-分步更新](./06-分步更新.md)）；主模型写在正文里的表达式出错时，可以通过 `{{ERA-issues}}` 宏在下一轮告诉主模型（需要自己在提示词里加上，见 [04-宏](./04-宏.md#把指令问题告诉-aiera-issues)）。说明写成了 AI 可以照着改的话。

#### 同一个指令块里的先后

同一个 `<VariableEdit>` 里，后面的表达式读到的是前面字段刚算出的值。注册了 schema 时，这个值还没有按变量结构纠正（纠正在整个指令块执行完之后）。依赖前一个结果、又需要纠正后的值时，把它放进下一个 `<VariableEdit>`。

#### 示例

变量：`{ "player": { "hp": 60, "max_hp": 100, "def": 3 }, "enemy": { "atk": 5 }, "pos": { "x": 0, "y": 0, "facing": 90, "speed": 2 }, "log": { "damage": 0 } }`

```xml
<VariableEdit>
{ "player": { "hp": { "$expr": "clamp(player.hp - max(roll(1, 8) + enemy.atk - player.def, 1), 0, player.max_hp)" } } }
</VariableEdit>
<VariableEdit>
{ "log": { "damage": { "$expr": "@player.hp - player.hp" } } }
</VariableEdit>
<VariableEdit>
{ "pos": { "x": { "$expr": "round(pos.x + cos(rad(pos.facing)) * pos.speed, 2)" }, "y": { "$expr": "round(pos.y + sin(rad(pos.facing)) * pos.speed, 2)" } } }
</VariableEdit>
```

- 第一块掷一个八面骰，伤害至少为 1，`hp` 限制在 0 到上限之间。
- 第二块用 `@` 算出本楼 `hp` 的变化量。
- 第三块按朝向（角度）移动：`x` 为 0，`y` 为 2。

#### 和钩子怎样分工

- AI 或前端在某一次写入里需要的公式、骰点，用 `$expr`。
- 每一楼都要自动重算的派生数值（例如由属性算出的攻击力），仍然写在更新钩子里，见 [05-接口与设置](./05-接口与设置.md#8-更新钩子)。钩子的 `onBeforeApply` 会原样看到 `{"$expr": ...}` 叶子，按数字处理指令的旧钩子要注意兼容。

#### 让 AI 学会使用

默认的“ERA 变量操作规则”条目不介绍 `$expr`。ERA 另附一份给 AI 的说明“ERA 表达式规则”，原文在 `初始模板/ERA角色卡/新建为src文件夹中的文件夹/世界书/ERA/表达式规则.txt`，讲了写法、函数和常见错误。需要公式或骰点的卡，把它建成一条蓝灯世界书条目，名字写 `ERA 表达式规则`，放在“ERA 变量操作规则”之后。开启分步更新时，这个名字的条目和“ERA 变量操作规则”一样只发给更新变量的模型。

### `$meta.updatable`（修改保护）

- `"updatable": false`：该节点及其所有后代都不能被 Edit 修改。默认是 `true`。
- **解除**：在同一个 Edit 中、该节点这一层写上 `"$meta": { "updatable": true }`，保护解除，同一指令中对该节点的其他修改也会执行。
- 它不防删除。防删除请用 `$meta.necessary`。
- **整体覆盖也算修改**：用一个数字、字符串或数组去覆盖整个对象（例如 `{ "player": 0 }`）时，只要这个对象自己或里面任何一层带有 `updatable: false`、受 `necessary` 保护的子节点，或者（开启 `下划线只读` 时）以 `_` 开头的字段，这次修改就会被拒绝。这条规则只对新建的聊天生效，见[只对新聊天生效](#只对新聊天生效)。

### 示例

**示例 1：常规修改**

- 变量：`{ "player": { "hp": 100 } }`
- 指令：`<VariableEdit>{ "player": { "hp": 90 } }</VariableEdit>`
- 结果：`{ "player": { "hp": 90 } }`

**示例 2：修改受保护的变量（失败）**

- 变量：`{ "player": { "hp": 100, "$meta": { "updatable": false } } }`
- 指令：`<VariableEdit>{ "player": { "hp": 90 } }</VariableEdit>`
- 结果：无变化。

**示例 3：解除保护并同时修改**

- 变量：同上
- 指令：

  ```xml
  <VariableEdit>
  { "player": { "hp": 80, "$meta": { "updatable": true } } }
  </VariableEdit>
  ```

- 结果：`{ "player": { "hp": 80, "$meta": { "updatable": true } } }`

**示例 4：想把字段换成对象（失败）**

- 变量：`{ "player": { "weapon": "木棍" } }`
- 指令：`<VariableEdit>{ "player": { "weapon": { "name": "长剑" } } }</VariableEdit>`
- 结果：无变化，报告 `player.weapon.name` 路径不存在。应改用：

  ```xml
  <VariablePatch>
  [{ "op": "replace", "path": "/player/weapon", "value": { "name": "长剑" } }]
  </VariablePatch>
  ```

## `<VariableDelete>`（删除）

**用途**：删除已存在的数据。

### 核心行为

- **删除节点**：值写空对象 `{}`，删除该键对应的整个节点（写 `null` 等非对象值效果相同）。
- **深入删除**：值写非空对象，表示进入该节点，继续删除更深的子节点。
- 不能删除根对象。
- 删除数组中的单个元素，请用 `<VariablePatch>` 的 `remove`，它不会留下空位。

### `$meta.necessary`（删除保护）

| 值 | 效果 |
| --- | --- |
| `"self"` | 节点自身不能被删除；它的子节点可以删除。 |
| `"children"` | 节点的直属子节点不能被删除；节点自身可以删除。 |
| `"all"` | 节点自身及其所有后代都不能被删除。 |

**解除**：在深入删除的指令里，在该节点这一层写 `"$meta": {}`（删除整个 `$meta`）或 `"$meta": { "necessary": {} }`（只删这一项）。

- `self` / `all`：解除后，同一对象中对该节点子节点的其他删除也会执行。
- `children`：保护在该节点开始处理时就已生效，同一对象中对其他子节点的删除仍会被拒绝。请先在一个对象中删除 `$meta`，再在同一指令块的下一个对象中删除子节点。
- 直接用 `{ "节点": {} }` 删除一个受 `self` / `all` 保护的节点，无法解除保护。同样需要先删除它的 `$meta`，再删除节点。
- `null`、字符串、数组等非对象值和 `{}` 一样表示删除，同样受 `children` 保护。这条规则只对新建的聊天生效，见[只对新聊天生效](#只对新聊天生效)。

### 示例

**示例 1：`necessary: "self"`**

- 变量：`{ "user": { "name": "Alex", "stats": { "str": 10 }, "$meta": { "necessary": "self" } } }`
- 删除子节点（成功）：`<VariableDelete>{ "user": { "stats": {} } }</VariableDelete>`
  - 结果：`{ "user": { "name": "Alex", "$meta": { "necessary": "self" } } }`
- 删除自身（失败）：`<VariableDelete>{ "user": {} }</VariableDelete>`
  - 结果：无变化。

**示例 2：`necessary: "all"`**

- 变量：`{ "user": { "name": "Alex", "stats": { "str": 10 }, "$meta": { "necessary": "all" } } }`
- 删除子节点（失败）：`<VariableDelete>{ "user": { "stats": {} } }</VariableDelete>`
  - 结果：无变化。

**示例 3：解除保护并同时删除**

- 变量：同示例 2
- 指令：

  ```xml
  <VariableDelete>
  { "user": { "stats": {}, "$meta": { "necessary": {} } } }
  </VariableDelete>
  ```

- 结果：`{ "user": { "name": "Alex", "$meta": {} } }`

**示例 4：`necessary: "children"`，分两步解除**

- 变量：`{ "p": { "hp": 1, "mp": 2, "$meta": { "necessary": "children" } } }`
- 指令：

  ```xml
  <VariableDelete>
  { "p": { "$meta": { "necessary": {} } } }
  { "p": { "hp": {} } }
  </VariableDelete>
  ```

- 结果：`{ "p": { "mp": 2, "$meta": {} } }`
- 若写成一个对象 `{ "p": { "$meta": {}, "hp": {} } }`，`hp` 的删除会被拒绝。

## `<VariablePatch>`（路径式操作）

内容是一个操作数组，按顺序执行，语义参照 JSON Patch。

```xml
<VariablePatch>
[
  // 换武器：整体替换对象
  { "op": "replace", "path": "/player/weapon", "value": { "name": "长剑", "atk": 12 } },
  { "op": "insert", "path": "/player/titles/-", "value": "屠龙者" },
  { "op": "delta", "path": "/player/hp", "value": -10 },
  { "op": "move", "from": "/player/nickname", "to": "/player/alias" }
]
</VariablePatch>
```

### 操作

| op（别名） | 需要 | 作用 |
| --- | --- | --- |
| `replace`（`set`、`update`） | `path`、`value` | 已存在：整体替换。原值中的 `$meta`、`$template`（包括各级子对象的）会保留，除非新值自己写了。不存在：新建，缺失的父级自动补上，并应用 `$template`。 |
| `insert`（`add`） | `path`、`value` | 父级是数组：在指定位置插入，`/列表/-` 追加到末尾，`/列表/0` 插到开头。父级是对象：与 `replace` 相同，**已存在的键会被覆盖**。只想新增、不想覆盖时，请用 `<VariableInsert>`。 |
| `remove`（`delete`、`unset`） | `path` | 删除。删除数组元素时后面的元素前移，不留空位。 |
| `delta`（`increment`、`inc`） | `path`、`value` | 数字运算。`value` 写数字（如 `-10`）或 `"+=5"`、`"-=5"`、`"*=2"`、`"/=2"`。路径必须存在，当前值必须是数字。 |
| `toggle` | `path` | 切换布尔值。当前值必须是 `true` / `false`。 |
| `append` | `path`、`value` | 当前值是文本：拼接到末尾。当前值是数组：追加一个元素。其他类型失败。 |
| `move`（`rename`） | `from`、`to` | 移动或改名。`to` 也可写成 `path`。不能移动到自身内部。 |
| `copy` | `from`、`to` | 复制。`to` 也可写成 `path`。 |

- 不支持 JSON Patch 的 `test`，未知的 op 会被报告并跳过。
- 每个操作独立执行：失败的操作完全撤销，不影响其他操作。`move` / `copy` 也是要么全部完成，要么不变。
- 数组的增删以“整体替换数组”记入日志，回滚是精确的。

### 路径写法

| 写法 | 示例 |
| --- | --- |
| JSON Pointer | `/player/inventory/0` |
| 点分隔 | `player.inventory` |
| 方括号下标 | `player.inventory[0]` 或 `/player/inventory[0]` |

- 开头的 `stat_data` 会被忽略，`/stat_data/player/hp` 与 `/player/hp` 相同。
- `/` 写法中，键名里的 `/` 写作 `~1`，`~` 写作 `~0`；键名可以包含 `.`。
- 形如 `名字[0]` 的一段会被当作“数组 + 下标”。

### 保护规则

- `$meta.updatable`、`$meta.necessary`、`$meta.unInsertAble` 和 `$template` 在 Patch 中同样生效。
  - 整体替换一个对象时，不能丢掉其中受 `necessary` 保护的子节点，也不能改动受 `updatable: false` 保护的子节点。
- **Patch 不能解除保护。** 即使 `value` 里写了 `"$meta": { "updatable": true }`，操作也会因受保护而失败。需要解除时，请用 `<VariableEdit>` / `<VariableDelete>` 的解除写法。
- **Patch 不能改动已有的 `$meta`。** 路径指向 `$meta` 或它内部（例如 `remove /背包/$meta`），或者整体替换时新值自带的 `$meta` 与原来的不同，操作都会失败。新建的对象可以自带 `$meta`。这条规则只对新建的聊天生效，见[只对新聊天生效](#只对新聊天生效)。

## 工具调用 `<EraFCall>`

角色卡脚本用 [`Era.registerTool`](./05-接口与设置.md#eraregistertool--erahastool) 注册工具之后，AI 可以在正文里调用它，由程序按规则结算并更新变量：

```xml
<EraFCall name="攻击">{"目标": "哥布林"}</EraFCall>
```

也可以写成自闭合的形式，参数放在 `args` 属性里（单引号包住 JSON）：

```xml
<EraFCall name="攻击" args='{"目标": "哥布林"}'/>
```

- `name` 是工具名；参数是严格的 JSON（开启 `宽松解析` 时也接受常见的不规范写法），没有参数时可以省略。
- 调用和其他指令块一起**按出现的位置**执行：工具读到的是执行到这里时的变量，前面的 `<VariableEdit>` 已经生效，后面的指令能看到工具的修改。
- 工具产出的修改同样经过 schema 和 `$meta` 保护。调用失败（未知工具、参数不合法、工具出错）时这次调用不产生修改，后面的指令照常执行，原因会出现在 `{{ERA-issues}}` 里。
- 重算时重新调用，工具里的随机数按楼层和调用位置取种子，结果不变。
- 用户消息里的调用不执行；新聊天里思考块中的调用不执行。
- 让 AI 知道有哪些工具：在规则条目里放 `{{ERA-tools}}`，它展开为当前注册的工具、说明和参数；把结算结果告诉 AI：放 `{{ERA-toolResults}}`，它展开为最新一楼的调用结果。见 [04 宏](./04-宏.md)。
- 数据隐藏正则同样隐藏 `<EraFCall>`；旧卡用面板的“更新旧卡的规则”更新隐藏正则。用到工具的卡请在角色卡变量 `ERA最低版本` 里写 `2.0.2`，装着旧版 ERA 的玩家会收到提示，否则标签会原样显示、调用不执行。

## `$meta` 保护一览

| 字段 | 值 | 限制 | 解除方式 |
| --- | --- | --- | --- |
| `updatable` | `false` | 节点及后代不能被修改 | Edit 中写 `"$meta": { "updatable": true }` |
| `necessary` | `"self"` / `"children"` / `"all"` | 见 [删除保护](#metanecessary删除保护) | Delete 中删除 `$meta` 或 `$meta.necessary` |
| `unInsertAble` | `"self"` / `"all"` | 见 [插入保护](#metauninsertable插入保护) | Edit 修改或 Delete 删除 `$meta.unInsertAble` |

## 综合示例

以下是一个连续的场景。每一步的结果都用 ERA 源码实际运行过。

### 1. 初始化

```xml
<VariableInsert>
{
  "world_state": {
    "capital": {
      "type": "city",
      "population": 1000,
      "description": "The bustling capital city.",
      "$meta": { "updatable": false, "necessary": "all" }
    },
    "characters": {
      "$template": {
        "level": 1,
        "hp": 10,
        "inventory": [],
        "$meta": { "necessary": "self" }
      }
    },
    "game_version": "1.0.0"
  }
}
</VariableInsert>
```

`capital` 不能修改也不能删除。`characters.$template` 用于之后新建的角色。

### 2. `<VariableInsert>`

**场景 A：成功，应用父级模板**

- 指令：`<VariableInsert>{ "world_state": { "characters": { "player": { "hp": 15 } } } }</VariableInsert>`
- 结果：`player` 为

  ```json
  { "level": 1, "hp": 15, "inventory": [], "$meta": { "necessary": "self" } }
  ```

**场景 B：部分生效，已有模板不会被覆盖**

- 指令：

  ```xml
  <VariableInsert>
  {
    "world_state": {
      "characters": {
        "$template": { "level": 99, "hp": 9999, "$meta": { "necessary": "all" } },
        "final_boss": { "hp": 8888 }
      }
    }
  }
  </VariableInsert>
  ```

- 逻辑：`characters.$template` 已存在，其中的 `level`、`hp`、`$meta.necessary` 都已有值，新模板被跳过（报告“路径已存在”）。`final_boss` 仍使用已有模板，只有 `hp` 取指令中的 8888。
- 结果：`final_boss` 为

  ```json
  { "level": 1, "hp": 8888, "inventory": [], "$meta": { "necessary": "self" } }
  ```

**场景 C：嵌套模板**

- 前置：用 `<VariableInsert>` 在 `characters.$template` 中为 `follower` 定义一个嵌套模板。`$template` 是对象，Insert 会进入它并补充新键 `follower`。

  ```xml
  <VariableInsert>
  {
    "world_state": {
      "characters": {
        "$template": {
          "follower": {
            "$template": { "level": 10, "hp": 200, "faction": "None", "sex": "female" }
          }
        }
      }
    }
  }
  </VariableInsert>
  ```

- 指令（一个块里两个对象，按顺序执行）：

  ```xml
  <VariableInsert>
  { "world_state": { "characters": { "player": { "follower": {} } } } }
  { "world_state": { "characters": { "player": { "follower": { "lili": { "level": 1 }, "cityGuard": {} } } } } }
  </VariableInsert>
  ```

- 逻辑：
  1. `player` 创建于前置操作之前，所以还没有 `follower`。第一个对象新建 `player.follower`，它从 `characters.$template.follower` 得到自己的 `$template`。
  2. 第二个对象向 `follower` 插入 `lili` 和 `cityGuard`，二者都应用 `follower.$template`。`lili` 的 `level` 被指令中的 1 覆盖；`cityGuard` 是空对象，完全使用模板。
  3. 如果省略第一个对象，直接插入 `follower.lili`，`follower` 会连同 `lili` 一次插入，`lili` 不会应用模板，结果只有 `{ "level": 1 }`。
- 结果：`player.follower` 为

  ```json
  {
    "$template": { "level": 10, "hp": 200, "faction": "None", "sex": "female" },
    "lili": { "level": 1, "hp": 200, "faction": "None", "sex": "female" },
    "cityGuard": { "level": 10, "hp": 200, "faction": "None", "sex": "female" }
  }
  ```

**场景 D：失败，路径已存在**

- 指令：`<VariableInsert>{ "world_state": { "game_version": "1.0.1" } }</VariableInsert>`
- 结果：无变化，`game_version` 仍是 `"1.0.0"`。

### 3. `<VariableEdit>`

**场景 A：失败，受 `updatable: false` 保护**

- 指令：`<VariableEdit>{ "world_state": { "capital": { "population": 1001 } } }</VariableEdit>`
- 结果：无变化。

**场景 B：解除保护并同时修改**

- 指令：`<VariableEdit>{ "world_state": { "capital": { "population": 1002, "$meta": { "updatable": true } } } }</VariableEdit>`
- 结果：`capital.population` 为 1002，`capital.$meta` 为 `{ "updatable": true, "necessary": "all" }`。

**场景 C：失败，路径不存在**

- 指令：`<VariableEdit>{ "world_state": { "lost_city": { "population": 1 } } }</VariableEdit>`
- 结果：无变化。

### 4. `<VariableDelete>`

**场景 A：失败，受 `necessary: "all"` 保护**

- 指令：`<VariableDelete>{ "world_state": { "capital": { "description": {} } } }</VariableDelete>`
- 结果：无变化。

**场景 B：成功，删除受 `self` 保护节点的子节点**

- 指令：`<VariableDelete>{ "world_state": { "characters": { "player": { "inventory": {} } } } }</VariableDelete>`
- 结果：`player.inventory` 被删除。

**场景 C：成功，删除子节点并移除保护**

- 指令：`<VariableDelete>{ "world_state": { "characters": { "final_boss": { "hp": {}, "$meta": {} } } } }</VariableDelete>`
- 逻辑：`final_boss` 受 `necessary: "self"` 保护，只是不能删除自身，删除 `hp` 本来就允许；`"$meta": {}` 一并删除了保护。
- 结果：`final_boss` 为 `{ "level": 1, "inventory": [] }`。此后 `<VariableDelete>{ "world_state": { "characters": { "final_boss": {} } } }</VariableDelete>` 可以删除它。

**场景 D：失败，直接删除受 `self` 保护的节点**

- 指令：`<VariableDelete>{ "world_state": { "characters": { "player": {} } } }</VariableDelete>`
- 结果：无变化。

## 相关设置与 schema

以下脚本设置在酒馆助手的脚本设置中修改，完整说明见 [05-接口与设置](./05-接口与设置.md) 的“脚本设置”一节。

### `数组内保留对象`（默认关）

关闭时，写入数组的对象和数组会被转成 JSON 字符串存放，例如 `[{ "n": "a" }]` 存为 `["{\"n\":\"a\"}"]`。所有指令都是如此。

- 这样存放的元素，状态栏要自己 `JSON.parse`，指令也无法按路径修改其中的字段。
- 建议：列表中的条目需要多个字段时，用以名字为键的对象代替数组，例如 `"背包": { "长剑": { "数量": 1 } }`。这样 Insert / Edit / Delete 都能按键操作，还能使用 `$template` 和 `$meta`。
- 确实需要数组存放对象时，开启此设置。重算历史楼层时会按当前设置重新处理，建议在角色卡发布前定好，之后不要修改。

### `下划线只读`（默认关）

开启后，正文中的指令不能修改或删除以 `_` 开头的字段。钩子、`Era.commit`，以及开启 `API写入不修改消息` 后的写入事件不受限制；默认设置下的 `era:*` 写入事件会把指令块写进正文，与 AI 的指令无法区分，同样受限（见 [05-接口与设置](./05-接口与设置.md) 的 `下划线只读`）。

| 指令 | 规则 |
| --- | --- |
| Insert | 可以新建 `_` 开头的字段。 |
| Edit / Delete | 不能修改或删除 `_` 开头的字段及其内部。 |
| Patch | 路径（`path` / `from` / `to`）经过已存在的 `_` 字段时失败，例如不能向只读数组 `/_list/-` 插入；可以新建还不存在的 `_` 字段；整体替换父对象时，其中 `_` 字段保留原来的值；把含 `_` 字段的对象替换成非对象时失败。 |

### `宽松解析`（默认开）

指令块的 JSON 不合法时，先尝试修复再解析。无法修复的部分不会被猜测，而是报告为解析失败。删除指令中被截断的内容不会被自动补全。

### `思考标签`（默认 `think, thinking`）、`指令外层标签`（默认空）

只对新建的聊天生效，见 [思考块与指令外层标签](#思考块与指令外层标签)。“指令外层标签”要在新聊天开始时就设好，中途开启会让之前没有包外层标签的楼层在重算时失效。

### schema 校验

角色卡可以在角色脚本（酒馆助手脚本）中调用 `Era.registerSchema(...)` 注册变量结构。注册后：

- 会让变量不符合结构的修改被丢弃，其余修改照常生效，并广播 `era:schemaError`。
- 执行 Edit / Patch 之前会补全 schema 的默认值，所以只由默认值提供的字段也能被修改。
- 可以在世界书中用 `{{ERA-schema}}` 宏把结构说明提供给 AI，见 [04-宏](./04-宏.md)。

详见 [05-接口与设置](./05-接口与设置.md) 的 `Era.registerSchema` 一节。把变量更新交给另一个模型的做法见 [06-分步更新](./06-分步更新.md)。

## 旧卡更新规则

`<VariablePatch>`、增量运算、`<EraFCall>` 和 `<era_plan>` 是后续加入的。旧卡的“ERA 变量操作规则”没有介绍它们，旧版隐藏正则也不认识这些标签，直接启用会让指令显示在聊天里。

在 ERA 面板的“工具”页点击 **更新旧卡的规则**，即可备份旧内容并把规则条目和隐藏正则升级到当前版本（完整更新范围与异常提示处理见 [07-常见问题与排错](./07-常见问题与排错.md#旧卡升级)）。使用时注意三点：

- 不要把自定义说明写进 `ERA 变量操作规则`（升级时会整体覆盖它）；自定义规则请写在 `ERA 变量意图说明` 中，它不会被覆盖。
- “更新旧卡的规则”不会自动添加 `ERA 表达式规则` 条目，规则正文里也没有 `$expr`。旧卡要启用表达式，请按 [让 AI 学会使用](#让-ai-学会使用) 自己建这条条目。
- 不建议手动修改旧的隐藏正则（新版 `ERA 数据隐藏正则` 除了 `<VariablePatch>`，还要匹配 `<EraFCall>`、`<era_plan>` 和 `<era_extra>`），直接用面板的“更新旧卡的规则”即可。
