## 工作原理

| 步骤 | 谁来做 | 说明 |
| --- | --- | --- |
| 1 | ERA 脚本 | 处理最新一条 AI 消息时，在正文末尾补一个特殊符号，默认是 `<StatusPlaceHolderImpl/>`。正文里已经有这个符号时不再添加；用户消息不添加。 |
| 2 | 角色卡局部正则 `ERA 状态栏模板` | 显示消息时，把这个符号替换成状态栏的 HTML（用 ` ```html ` 代码块包住）。这条正则只作用于 AI 输出、只改显示，不会发给 AI。另一条 `ERA 状态栏占位符隐藏正则` 把符号本身从发给 AI 的提示词中去掉；缺少这条正则的旧卡，由 ERA 在发送前从 AI 消息里去掉（发给分步更新模型的聊天记录也一样）。 |
| 3 | 酒馆助手 | 把 ` ```html ` 代码块渲染成嵌入在消息里的独立前端界面（iframe）。 |
| 4 | 状态栏里的脚本 | 读取 ERA 变量并显示。 |

相关的脚本设置（在 ERA 面板或酒馆助手脚本库的 ERA 脚本设置里）：

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `在ai消息尾部生成特殊符号` | 开启 | 关闭后 ERA 不再补符号，状态栏也就不会出现。 |
| `特殊符号值` | `<StatusPlaceHolderImpl/>` | 补到消息末尾的符号。改了它，要同步修改 `ERA 状态栏模板` 和 `ERA 状态栏占位符隐藏正则` 两条正则的“查找”。 |

## 准备

1. 在角色卡设置里启用**局部正则**。
2. 打开 ERA 面板（点悬浮球），在“工具”页点“**ERA 快速初始化**”。它会在角色卡局部正则里建好 `ERA 状态栏模板`，内容是一个默认状态栏。
   - 看不到悬浮球：在酒馆扩展菜单（输入框左侧的魔棒图标）点“ERA 面板”，或在输入框发送 `/era`；发送 `/era ball` 重新显示悬浮球。
   - 快速初始化按名字判断正则是否已存在：已有的同名正则不会被覆盖。误删了 `ERA 状态栏模板` 时，再点一次即可恢复默认状态栏。
   - “更新旧卡的规则”只更新规则条目和隐藏正则（会补上缺少的隐藏正则），不会改动你的状态栏。
3. 确认 `在ai消息尾部生成特殊符号` 处于开启状态（默认开启）。

## 修改状态栏

1. 酒馆“扩展 → 正则”，在角色卡的局部正则里找到 `ERA 状态栏模板`，编辑它的“替换为”。
2. 把内容换成你自己的完整 HTML。**必须用 ` ```html ` 代码块包住**，否则酒馆助手不会把它渲染成界面：

   ``````
   ```html
   <!doctype html>
   <html>
     ...你的状态栏...
   </html>
   ```
   ``````

3. **不要再新建一条匹配同一符号的正则**，两条会冲突，结果不可预料。按深度分工、深度范围不重叠的除外，见[长聊天：控制渲染的楼层](#长聊天控制渲染的楼层)。
4. 只有改过 `特殊符号值` 时，才需要同步修改这条正则的“查找”。默认值是 `/<StatusPlaceHolderImpl\/>/gsi`。

## 读取变量（推荐写法）

在状态栏的 `<script>` 里，先用 `Era.getCurrentVars()` 读取变量，再通过监听 `era:writeDone` 事件（每次变量更新完成时 ERA 发出的通知）刷新画面。`waitGlobalInitialized`、`eventOn`、`$`、`_` 都是酒馆助手提供给前端界面的全局函数，不需要导入。

下面提供两种写法：只需要所有楼都显示最新变量时选**方案 A**；聊天较长、希望旧楼保留“那一楼当时”的值并减少刷新开销时选**方案 B**（快速初始化生成的默认状态栏采用方案 B）。

### 方案 A：每楼都显示最新变量（最简写法）

```html
<div id="hp">-- / --</div>
<script>
  function render(stat) {
    const hp = _.get(stat, 'player_status.hp', '--');
    const maxHp = _.get(stat, 'player_status.max_hp', '--');
    $('#hp').text(`${hp} / ${maxHp}`);
  }

  $(async () => {
    await waitGlobalInitialized('Era');
    render(Era.getCurrentVars().statWithoutMeta);
    eventOn('era:writeDone', detail => render(detail.statWithoutMeta));
  });
</script>
```

### 方案 B：旧楼定格当时的值、最新楼实时刷新（默认状态栏写法）

快速初始化生成的默认状态栏这样区分新旧楼：

- 最后一条消息的状态栏显示最新变量，并监听 `era:writeDone`；
- 旧楼加载时用 `await Era.getVarsAt(getCurrentMessageId())` 显示那一楼当时的变量，不再监听；
- 最后一楼后面有了新消息、变成旧楼后，停止监听，保持显示本楼的值。

这样长聊天里每次写入只刷新最后一楼，不会让渲染出来的全部旧楼一起刷新。自己改默认状态栏时建议保留这个区分（“更新旧卡的规则”不会改动状态栏）。把上面 `<script>` 里的 `$(async () => { ... })` 换成：

```javascript
function isOldFloor(self) {
  return self < getLastMessageId();
}

$(async () => {
  await waitGlobalInitialized('Era');
  const self = getCurrentMessageId();
  if (isOldFloor(self)) {
    // 旧楼：显示那一楼当时的变量，不监听
    try {
      render((await Era.getVarsAt(self)).statWithoutMeta);
    } catch {
      render(Era.getCurrentVars().statWithoutMeta); // 读不到那一楼时退回最新变量
    }
    return;
  }
  render(Era.getCurrentVars().statWithoutMeta);
  const listener = eventOn('era:writeDone', detail => {
    if (isOldFloor(self)) {
      listener.stop(); // 后面有了新消息：保持显示本楼的值，不再监听
      return;
    }
    render(detail.statWithoutMeta);
  });
});
```

### 要点与注意事项

- `statWithoutMeta` 是去掉 `$meta`、`$template` 的变量，用来显示；`stat` 含这些字段。
- 每次变量变化后都会广播 `era:writeDone`，包括 AI 回复、滑动（swipe）、删除或编辑消息、回滚和脚本写入。`detail.actions` 说明这次做了什么，结构见 [05-接口与设置.md](05-接口与设置.md) 的 `era:writeDone` 一节。
- 这种写法不需要开启 `强制重载功能`，更新时不会整块闪烁。
- 也可以在加载时发送 `era:requestWriteDone`，让 ERA 重新广播一次 `era:writeDone`，但 ERA 还没有广播过时它不会响应，所以推荐 `Era.getCurrentVars()`。
- 把变量里的文字写进页面时用 `.text()` 或 `textContent`，不要拼进 `innerHTML`：AI 写入的名字里可能有 `<` 等字符。
- 使用 Vue 前端项目时，可用 `util/era.ts` 的 `defineEraFloorStore` 按楼层读取，或用 `isLatestFloor()`（等价于 `getCurrentMessageId() === getLastMessageId()`，在 `era:writeDone`、`MESSAGE_DELETED` 时重新判断）控制只在最新一楼显示完整状态栏，详见 [05-接口与设置](./05-接口与设置.md) 第 9 节“旧楼的状态栏”。
- 方案 B 的边界情况：`Era.getVarsAt` 读不到那一楼时 Promise 失败（例如开启了 `日志保留楼层数`、没开 `折叠日志存档` 时折叠边界之前的楼层），上述代码会退回显示最新变量。删掉后面的消息、旧楼重新成为最后一楼时，它不会恢复监听，这一楼重新渲染（例如重新打开聊天）后恢复。编辑或删除更早的楼层会改变之后各楼的值，已经显示出来的旧楼状态栏不会跟着更新，同样要等重新渲染；需要旧楼随时准确时，旧楼也在每次 `era:writeDone` 后重新调用 `Era.getVarsAt`（见 [05-接口与设置](./05-接口与设置.md#eragetvarsat)），代价是每次写入都刷新全部渲染出来的楼层。

## 读取变量（宏写法）

在 HTML 的文字里直接写 `{{ERA:路径}}`，例如 `{{ERA:player_status.hp}}`。宏的完整语法见 [04-宏.md](04-宏.md)。

限制：

- 宏只替换消息里的**普通文字**，不替换 `<script>`、`<style>` 里的内容和标签属性（例如 `style="width: {{ERA:hp}}%"` 不会被替换）。
- 要让变量变化后状态栏跟着刷新，需要开启脚本设置 `强制重载功能`（默认关闭）。开启后，每次写入完成约 1 秒后，ERA 会重新渲染最后几条消息，条数由 `强制重载消息数` 决定（默认 2）。重新渲染时整个状态栏会闪一下。
- 状态栏被酒馆助手渲染成 iframe 之后，宏能否刷新取决于渲染的先后，不保证每次都成功。

所以宏写法只适合简单展示。需要稳定刷新、进度条宽度、条件显示时，请用上一节的事件写法。

## 在状态栏里修改变量

状态栏里的按钮等需要改变量时：

- 用 `await Era.commit([...])`，例如 `await Era.commit([{ edit: { player_status: { hp: '-=10' } } }])`。它返回 Promise，写入计算完成后才完成；加 `{ atomic: true }` 时，有一项不能生效就全部放弃并报错。
- 或者用 `eventEmit('era:patch', [...])` 发送 `<VariablePatch>` 格式的操作，例如 `eventEmit('era:patch', [{ op: 'insert', path: '/inventory/-', value: '面包' }])`。
- 用 `era:insertByPath` / `era:updateByPath` / `era:deleteByPath` 时，`path` 只能用 `.` 分隔对象键，**不要写 `[0]` 这样的数组下标**，否则整个数组会被替换或删除。操作数组元素请用 `era:patch`。
- 不要在 `era:writeDone` 的监听器里无条件写入变量，否则会无限循环。

各接口的参数与返回值见 [05-接口与设置.md](05-接口与设置.md)。

## 长聊天：控制渲染的楼层

每一楼的状态栏都是一个独立的界面（iframe）。聊天很长时，同时渲染的状态栏越多，打开聊天越慢、每次写入要刷新的界面也越多。面板“诊断”页的“聊天数据体积”会显示当前聊天里挂载的界面（iframe）数，状态栏和其他前端界面都算在内。

**玩家**可以用酒馆助手自带的渲染设置（酒馆助手设置里的渲染器）：

| 设置 | 建议 |
| --- | --- |
| 渲染深度 | 设为一个小的数，例如 5～10：只把最近这么多楼的代码块渲染成界面。0 表示渲染全部楼层。 |
| 启用代码折叠 | 选“前端”：只折叠会渲染成界面的代码块。超出渲染深度的楼层，状态栏显示为一个折叠的代码块，不会铺开一大段代码。 |
| 取消前端代码高亮 | 开启：取消会渲染成界面的代码块的高亮，聊天加载更快。 |

**作者**可以用正则的深度只给最近几楼生成状态栏。酒馆正则的深度从最后一条消息算起（最后一条为 0，用户消息也计数，隐藏的楼层不计数）：

1. `ERA 状态栏模板`：“最大深度”设为 N（例如 4），只有最近 N + 1 条消息里的占位符会换成状态栏。
2. 再建一条只作用于 AI 输出、只改显示的正则，查找与 `ERA 状态栏模板` 相同，“最小深度”设为 N + 1，替换为空（或者一行简短的文字摘要），让更早的楼层不显示占位符。两条正则的深度范围不重叠，不会冲突。

正则在楼层渲染时按深度判断：聊天中途已经显示出来的状态栏不会因为有了新消息而消失，重新打开聊天后才按新的深度显示。

此外，新卡的默认状态栏在旧楼不监听 `era:writeDone`，见[读取变量（推荐写法）](#读取变量推荐写法)。

## 同层前端改写正文

把整个游戏界面放在一楼里、由前端自己调用 `generate()` 的卡（同层前端），可以用三个接口：

- `Era.applyText(text, options?)`：把一段文本（例如 `generate()` 的回复）里的指令应用到一楼，不修改正文。指令保存为旁路写入，按正文指令的规则执行。
- `Era.setMessageText(where, text)`：改写一楼的正文（例如重画界面楼层），自动保留 ERA 写在正文里的块，并按新正文重新计算变量。
- `Era.keepMessageKey(text, from)`：前端改写楼层正文时，保留 ERA 写在正文里的块（`<era_data>` 和分步更新的 `<era_extra>`）。`<era_data>` 里是这一楼的 MK，丢了它，这一楼的旁路写入会在下次完全同步时被清除；丢了 `<era_extra>`，分步更新写入的变量会回滚。`from` 填原来的正文或楼层的消息 ID；`text` 里已经有某种块时不再补。

```javascript
await setChatMessages([{ message_id: 0, message: Era.keepMessageKey(newText, 0) }]);
```

酒馆助手的 `setChatMessages` 改写正文后，酒馆不会发出“消息已修改”的事件，ERA 不知道正文变了，新正文里的指令有增减时变量不会跟着变。更省事的做法是用 `Era.setMessageText(楼层, 新正文)`：它自动保留 ERA 的块、改写正文、按新正文重算，算完后返回。坚持用 `setChatMessages` 时，改写后自己发一次 `eventEmit('era:forceSync')`。玩家在酒馆界面上手动编辑消息不受影响。

推荐**每回合一条隐藏楼层**：每回合新建一楼（隐藏起来不显示），把这一回合的指令写到这一楼。不要把整局的写入都挂在同一楼上：

- 钩子按楼执行，所有回合都在一楼时，“每回合 +1”这样的钩子整局只执行一次；
- 一楼的旁路写入越多，每次重算越慢，开销随回合数近似平方增长（实测注册 schema、每回合一条 edit 加一条数组 patch：第 1～50 回合的写入共耗时约 0.45 秒，第 101～150 回合共约 5.3 秒）。只适合短局或很少写入的卡。

参数和返回值见 [05-接口与设置.md](05-接口与设置.md)。

## 常驻状态面板

楼层状态栏跟着消息走：每一楼一个，往上翻能看到那一楼当时的值。如果你更想要一个始终显示最新变量、不占聊天位置的面板，可以用角色卡脚本在酒馆页面上自己挂一个，订阅 `era:writeDone` 刷新。整个页面只有一个面板，长聊天也不会因为它变卡。

这完全由卡来设计（放在哪、显示什么、什么样式），ERA 只提供变量（`Era.getCurrentVars()`）和变化通知（`era:writeDone`）。可以从 [示例/常驻状态面板示例.js](示例/常驻状态面板示例.js) 改起：把 `FIELDS` 换成你的变量路径和显示名，作为角色卡脚本导入即可。

- 面板只显示最新的变量；需要逐楼回看时，保留楼层状态栏（或只在最近几楼显示，见[长聊天：控制渲染的楼层](#长聊天控制渲染的楼层)）。
- 同层前端、独立前端的卡本来就有常驻界面，不需要它。
- 不想写任何界面时，玩家也可以点 ERA 悬浮球，在“变量”页查看全部变量。

## 常见问题

| 现象 | 检查 |
| --- | --- |
| 消息末尾没有状态栏 | 角色卡是否启用了局部正则；`ERA 状态栏模板` 是否启用；`在ai消息尾部生成特殊符号` 是否开启；替换内容是否用 ` ```html ` 包住。 |
| 消息末尾显示出 `<StatusPlaceHolderImpl/>` 原文 | `ERA 状态栏模板` 的“查找”与 `特殊符号值` 不一致，或正则没有启用。 |
| 状态栏出现两个 | 有两条正则都在替换这个符号。删掉自己新建的那条。 |
| 显示 `--` 或空白 | 状态栏里的路径与实际变量不一致。在浏览器控制台执行 `Era.getCurrentVars().statWithoutMeta` 查看实际结构。 |
| 某条消息没有补符号 | ERA 只在正文里**没有**这个符号时才补。检查该消息正文是否已经包含它。 |
| 旧楼的状态栏不随变量变化 | 新卡的默认状态栏在旧楼只显示那一楼当时的值，不监听 `era:writeDone`，这是有意的，见[读取变量（推荐写法）](#读取变量推荐写法)。 |
| 较早的楼层没有状态栏 | 超出了酒馆助手的“渲染深度”（显示为代码块，开了“启用代码折叠”时是折叠的），或者 `ERA 状态栏模板` 设置了“最大深度”。见[长聊天：控制渲染的楼层](#长聊天控制渲染的楼层)。 |
