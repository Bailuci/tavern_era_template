# ERA 宏

ERA 宏是写在文本里的 `{{ERA:路径}}` 这类标记，会被替换成变量的值。它可以写在世界书条目、角色描述、预设提示词里，让 AI 看到当前变量；也可以写在状态栏 HTML 里做简单展示。

## 宏语法

| 宏 | 替换为 |
| --- | --- |
| `{{ERA:路径}}` | 该路径的值，**不含** `$meta`、`$template` 等 `$` 开头的字段 |
| `{{ERA-withmeta:路径}}` | 该路径的值，**包含** `$meta`、`$template` |
| `{{ERA:$ALLDATA}}` | 全部变量，不含 `$` 字段 |
| `{{ERA-withmeta:$ALLDATA}}` | 全部变量，包含 `$` 字段 |
| `{{ERA-schema}}` | 已注册的变量结构的文字说明（类型、可选值、`.describe()` 写的说明）；没有注册 schema 时为空。注册方法见 [05-接口与设置.md](05-接口与设置.md) 的 `Era.registerSchema` |
| `{{ERA-issues}}` | 最新一条 AI 消息中没有生效的指令和原因；没有问题时为空。见 [把指令问题告诉 AI](#把指令问题告诉-aiera-issues) |
| `{{ERA-tools}}` | 当前注册的工具、说明、参数和 `<EraFCall>` 的写法；没有工具时为空。见 [02 工具调用](./02-指令手册.md#工具调用-erafcall) |
| `{{ERA-toolResults}}` | 最新一条 AI 消息中工具调用的结果（成功时工具返回的 `result`，失败时的原因）；没有调用时为空 |
| `{{ERA-exprFns}}` | `$expr` 里可以调用的自定义公式函数及说明；没有时为空 |

- 路径用 `.` 分级，例如 `player_status.hp`；数组元素可以写 `tags[0]`。
- `ERA` 不区分大小写，宏内可以有空格：`{{ era : player_status.hp }}` 也有效。
- `{{ERA-schema}}` 建议包在标签里，让 AI 知道这是什么：`<变量结构>{{ERA-schema}}</变量结构>`。ERA 的规则条目会要求 AI 遵守 `<变量结构>` 中的类型。

## 替换规则

| 情况 | 结果 |
| --- | --- |
| 值是文本、数字、布尔值 | 原样输出，例如 `100`、`勇者` |
| 值是对象或数组 | 输出 JSON 文本，例如 `{"hp":100,"max_hp":100}` |
| 路径不存在 | 空字符串 |
| 用 `{{ERA:…}}` 读 `$meta`、`$template` | 空字符串（这些字段只能用 `{{ERA-withmeta:…}}` 读） |
| 键名本身含有 `.`，例如 `a.b` | 先按分级查找，找不到时按字面键名查找，所以 `{{ERA:a.b.c}}` 也能读到 `{"a.b":{"c":1}}` 中的值 |

宏输出的是最新变量。ERA 在内部存储时会转义部分字符（例如 `.` 存成 `__DOT__`），宏输出前会还原，不需要自己处理。

注意：脚本设置 `数组内保留对象` 默认关闭，此时数组里的对象会被存成 JSON 文本，宏读出的也是文本，`bag[0].name` 读不到。列表请尽量用对象（以名字为键），或者在新卡里开启这个设置。

## 宏在哪里生效

| 位置 | 是否替换 | 说明 |
| --- | --- | --- |
| 发给 AI 的提示词（主生成） | 是 | 包括世界书条目、角色描述、预设、聊天记录等全部提示词，任何角色（system / user / assistant）都替换。使用发送那一刻的最新变量；如果此时还有同步在进行（例如刚发送的消息里有指令、滑动重新生成时的回退），会先等它完成（最多约 3 秒） |
| 分步更新时发给更新模型的提示词 | 是 | 按被解析那一楼的变量取值，见 [06-分步更新.md](06-分步更新.md)。`{{ERA-issues}}`、`{{ERA-toolResults}}` 在这里展开为空；注册了工具或公式函数、条目里又没有引用 `{{ERA-tools}}` / `{{ERA-exprFns}}` 时，ERA 自动附上它们的说明 |
| 正文前规划时发给规划模型的提示词 | 是 | 按规划时的当前变量取值，见 [06-分步更新.md](06-分步更新.md#正文前规划)。规划阶段不使用工具与 `$expr`，一般只需用 `{{ERA:路径}}`、`{{ERA-schema}}` |
| 显示出来的消息 | 部分 | 只替换消息里的**普通文字**；不替换 `<script>`、`<style>`、`<textarea>` 里的内容和标签属性（例如 `style="width: {{ERA:hp}}%"`） |

ERA 在发给 AI 的提示词中还会去掉历史 AI 消息里的状态栏占位符（脚本设置 `特殊符号值`，默认 `<StatusPlaceHolderImpl/>`）及其前面的空白。新卡由“ERA 状态栏占位符隐藏正则”去掉它；没有点过“更新旧卡的规则”的旧卡缺少这条正则，以前每条历史 AI 消息都会带着占位符发给 AI。规则：

- 只处理角色为 AI（assistant）的提示词消息，也就是历史 AI 消息；以 AI 角色注入的世界书、预设条目也会被处理。系统、用户角色的内容（含角色描述和用户输入）不动；
- 默认值始终去掉；改过的 `特殊符号值` 只在开启 `在ai消息尾部生成特殊符号` 时去掉；
- 分步更新发给更新模型的聊天记录按同样的规则处理。

显示出来的消息里，宏在变量写入完成后被替换。要让已显示的宏随变量变化而刷新，需要开启脚本设置 `强制重载功能`（见下文步骤 3）。

宏可以与酒馆自带的宏一起使用，例如用 `{{// 注释 }}` 写不发给 AI 的说明。

## 在世界书中使用

最常见的用法：在世界书条目 `ERA 变量意图说明` 里，把变量结构和当前变量提供给 AI。点 ERA 面板“ERA 快速初始化”创建的这个条目已经包含下面两段，请保留：

```
<变量结构>
{{ERA-schema}}
</变量结构>

<当前变量>
{{ERA:$ALLDATA}}
</当前变量>
```

也可以只引用一部分变量，例如 `玩家当前生命值：{{ERA:player_status.hp}}`。

完整示例见 [示例/宏使用示例.txt](示例/宏使用示例.txt)。意图说明条目的写法见 [01-快速上手.md](01-快速上手.md) 和 [示例/变量意图说明示例.txt](示例/变量意图说明示例.txt)。

## 把指令问题告诉 AI：`{{ERA-issues}}`

AI 写错路径、类型或触发保护时，ERA 跳过这条指令，最多只给玩家一个弹窗（需要开启脚本设置“指令失败提示”）；下一轮 AI 并不知道，常会重复同样的错误。`{{ERA-issues}}` 把最新一条 AI 消息里没有生效的指令和原因放进提示词，例如：

```
上一条回复中有 2 处变量指令没有生效，相关变量保持原值。需要时请在本次回复中按原因改正后重新写，已经生效的修改不要重复：
1. <VariableEdit> 主角.体力值：路径不存在，VariableEdit 只能修改已存在的变量
2. <VariableEdit> 主角.金钱：$expr 计算失败：不支持 %：取余请用 mod(x, y)；百分比请写成乘法，例如 50% 写成 *0.5（表达式：主角.金钱 * 10%）
```

**报告哪些问题**：最新一条 AI 消息（末尾是用户消息时往前找）中，主模型自己写在正文里的指令：

- 没有生效的指令：路径不存在、路径已存在、受 `$meta` 保护、`$expr` 计算失败等；
- 无法解析的指令块；
- 被变量结构（`Era.registerSchema`）拦截的修改。

不报告分步更新写在 `<era_extra>` 里的额外模型输出（额外模型有自己的重试）、旁路写入（`Era.commit`、`Era.applyText` 等）和钩子引起的问题，它们不是主模型写的。最多列出 10 处，其余写成“……另有 N 处”。

**什么时候为空**：

- 最新一条 AI 消息的指令全部生效，或者聊天里还没有 AI 消息；
- 这一楼还没有计算过，例如刷新页面后还没有同步、刚滑到一条还没同步的新回复；
- 在分步更新发给更新模型的提示词里。

**怎样启用**：快速初始化建的规则条目和意图说明条目都不引用它，需要时自己加。最简单的做法是在“ERA 变量意图说明”末尾单独加一行：

```
{{ERA-issues}}
```

输出本身带说明，不需要再包标签；没有问题时这一行为空。

- 开启分步更新时，“ERA 变量意图说明”“ERA 表达式规则”和带 `[era_update]` 的条目只发给更新模型，在那里它展开为空，主模型看不到。这种卡把它放进一条发给剧情模型的蓝灯条目（不带 `[era_update]`）。
- 放在靠近对话末尾的位置（例如深度 0～1），AI 更容易注意到。

**与 `/era-issues` 的关系**：两者读同一份记录。`/era-issues format=model` 返回与 `{{ERA-issues}}` 相同的文字；`/era-issues` 不带参数时列出这一楼全部来源的问题（含旁路写入、钩子和额外模型的输出），给作者排错用。区别在于没有记录时：`/era-issues` 会从上一楼重算，宏按没有问题处理。命令的用法见 [05-接口与设置.md](05-接口与设置.md#11-斜杠命令)。

## 用宏做状态栏

宏写法最简单，但有刷新限制。需要稳定刷新、进度条、条件显示时，请用 [03-状态栏.md](03-状态栏.md) 中的事件写法（`Era.getCurrentVars()` 加 `era:writeDone`）。

### 步骤 1：在开场白中初始化变量

在角色卡**开场白**末尾用 `<VariableInsert>` 写入变量的初始值：

```xml
<VariableInsert>
{
  "player_status": {
    "name": "勇者",
    "level": 1,
    "hp": 100,
    "max_hp": 100,
    "mp": 50,
    "max_mp": 50
  },
  "game_info": {
    "day": 1,
    "hour": 8,
    "weather": "晴朗"
  }
}
</VariableInsert>
```

本目录的状态栏示例和 [示例/变量结构与钩子脚本示例.js](示例/变量结构与钩子脚本示例.js) 都按这份变量编写。

### 步骤 2：编写包含宏的 HTML

在需要显示变量的文字处写 `{{ERA:路径}}`：

```html
<!doctype html>
<html>
  <head>
    <meta charset="UTF-8" />
  </head>
  <body>
    <div style="font-family: sans-serif; border: 1px solid #ccc; padding: 10px; border-radius: 5px">
      <h3 style="margin-top: 0">角色状态</h3>
      <div><strong>姓名:</strong> {{ERA:player_status.name}}</div>
      <div><strong>等级:</strong> {{ERA:player_status.level}}</div>
      <div><strong>HP:</strong> {{ERA:player_status.hp}} / {{ERA:player_status.max_hp}}</div>
      <div><strong>MP:</strong> {{ERA:player_status.mp}} / {{ERA:player_status.max_mp}}</div>
      <div style="font-size: 11px; color: #888; text-align: right">
        第 {{ERA:game_info.day}} 天 {{ERA:game_info.hour}} 时 | 天气: {{ERA:game_info.weather}}
      </div>
    </div>
  </body>
</html>
```

把完整 HTML 用 ` ```html ` 代码块包好，填进角色卡局部正则 `ERA 状态栏模板` 的“替换为”（它匹配 ERA 补在消息末尾的 `<StatusPlaceHolderImpl/>`）。不要另建一条正则。详见 [03-状态栏.md](03-状态栏.md)。

带样式的完整示例见 [示例/状态栏-宏版.html](示例/状态栏-宏版.html)。

### 步骤 3：开启刷新设置

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| `强制重载功能` | 关闭 | 开启后，每次变量写入完成约 1 秒后，ERA 重新渲染最后几条消息，让其中的宏重新取值。不开启时，宏只在消息第一次显示时取值。 |
| `强制重载消息数` | 2 | 每次重新渲染最后几条消息。至少为 1，小数向下取整；填写的值不合法时使用默认值 2。 |

重新渲染时状态栏会整体闪一下。状态栏被酒馆助手渲染成 iframe 后，宏能否刷新还取决于渲染的先后，不保证每次成功。

### 何时改用接口

| 需求 | 做法 |
| --- | --- |
| 只是展示几个值 | 宏 |
| 变量变化后稳定刷新、无闪烁 | `Era.getCurrentVars()` 加 `eventOn('era:writeDone', …)`，见 [03-状态栏.md](03-状态栏.md) |
| 进度条宽度、颜色等写在属性或样式里的值 | 同上（宏不替换属性和样式） |
| 点击按钮修改变量 | `Era.commit` 或 `era:patch`，见 [05-接口与设置.md](05-接口与设置.md) |

## 需要条件判断时：EJS

宏只能输出值。需要“人口大于 1000 时写一段话，否则写另一段”这类逻辑时，可以在世界书条目里写 EJS 模板（需要安装酒馆的“提示词模板”扩展）。示例见 [示例/EJS动态提示词示例.txt](示例/EJS动态提示词示例.txt)。只是按变量开关整条条目时，也可以用脚本注册条目过滤器；几种做法的比较见 [08-动态提示词.md](08-动态提示词.md)。

注意：

- ERA 的变量存在聊天变量 `stat_data` 下，EJS 用 `getvar('stat_data.路径', { scope: 'local' })` 读取。读到的是 ERA 存储的原始数据：文本中的 `.`、`"`、`'` 被转义成 `__DOT__`、`__DQUOTE__`、`__SQUOTE__`，也含 `$meta` 等字段。只是显示文本时，优先用 `{{ERA:…}}` 宏。
- 开启分步更新时，发给更新模型的条目里的 EJS：分步更新设置“EJS 预处理”为“自动”（默认）且装有、开启了提示词模板扩展时，ERA 按目标楼的状态渲染，写变量等函数不执行；设为“关闭”，或者没有装、没有开启扩展时，`<% %>` 原样发送，`@@if` 不求值（条目照常发送），条目开头的 `@@` 装饰器行不发送。见 [06-分步更新.md](06-分步更新.md#ejs-预处理) 的“EJS 预处理”。
- 主生成里的 EJS 由提示词模板扩展渲染，ERA 不参与。如果卡只用 EJS、提示词里没有任何 ERA 宏，滑动（swipe）重新生成时 EJS 可能读到回滚前的变量；原因、聊天补全与文本补全接口的差异，以及改用条目过滤器的做法见 [08-动态提示词.md](08-动态提示词.md#ejs条目里的条件文字) 和 [07-常见问题与排错.md](07-常见问题与排错.md#ejs-读到的变量是滑动前的)。
