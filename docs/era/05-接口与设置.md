# 接口与设置

本文写给编写酒馆助手**脚本**或**前端界面**（状态栏、面板等）的作者，说明怎样读写 ERA 的变量，以及 ERA 的全部脚本设置。

ERA 本身是一个酒馆助手脚本。变量保存在当前聊天的**聊天变量** `stat_data` 中，每一楼的改动记录在聊天变量 `ERAMetaData` 中。请不要用 `replaceVariables` 等接口直接改这两个键，否则删除、滑动、编辑消息时变量无法正确回滚。读写变量请用下面两种方式之一：

- **事件**：用酒馆助手的 `eventEmit` 发送 `era:*` 事件，用 `eventOn` 监听 ERA 广播的事件。
- **全局接口 `Era`**：ERA 通过酒馆助手的 `initializeGlobal` 共享了一个 `Era` 对象，`await waitGlobalInitialized('Era')` 之后可以直接调用。

两种方式可以混用，事件 API 全部保留。

## 1. 怎么选

| 想做的事 | 推荐用法 |
| --- | --- |
| 界面初始化时读一次变量 | `Era.getCurrentVars()` |
| 变量变化时刷新界面 | 监听 `era:writeDone` |
| 改变量并等待结果、失败时提示（推荐） | `await Era.commit([...])` |
| 多项改动要么全成功、要么全不做 | `Era.commit([...], { atomic: true })` |
| 玩家点按钮改变量，不关心结果 | `era:updateByObject` 等写入事件，或 `era:patch` |
| 楼层里的状态栏显示“那一楼当时”的值 | `await Era.getVarsAt(getCurrentMessageId())`，见[第 9 节](#9-在前端界面中使用) |
| 查看历史某一楼的变量 | `Era.getVarsAt(...)`，或 `era:getSnapshotAtMId` 等查询事件 |
| 限制变量的类型、范围，补全默认值 | `Era.registerSchema(schema)`（在角色卡脚本中） |
| 检查现有变量是否符合 schema | `await Era.checkSchema()`，或面板“诊断”页 |
| 每楼自动计算派生数值（上限、天气等） | `Era.onAfterApply(...)`（在角色卡脚本中）；不要在 `era:writeDone` 里回写，见[迁移配方](#不要在-erawritedone-里回写变量) |
| 前端自己请求 AI，再执行回复里的指令（同层前端） | `await Era.applyText(reply)` |
| 角色卡依赖某个版本的 ERA | 角色卡变量 `ERA最低版本`，或 `util/era.ts` 的 `requireEra`，见[版本检查](#eraversion--erafeatures) |

## 2. 写入事件

### 写入的去向

| 情况 | 结果 |
| --- | --- |
| 默认设置 | ERA 把对应的指令块（如 `<VariableEdit>`）追加到**最后一条 AI 消息**的正文末尾，再像 AI 写的指令一样计算。 |
| 聊天里还没有 AI 消息 | 默认设置下写入被**忽略**，只在控制台警告。 |
| 新聊天设置了 `指令外层标签` | 默认设置下追加到正文的指令块会包在外层标签里，否则不会执行。见[第 10 节](#思考标签-与-指令外层标签)。 |
| 开启脚本设置 `API写入不修改消息` | 写入保存在聊天变量 `ERAMetaData.ApiOps` 中，挂在最后一条 AI 消息上（没有 AI 消息时挂在最后一条消息上），正文不变。见 [第 10 节](#10-脚本设置)。 |
| 用 `era:commit` / `Era.commit` | 总是按上一行的方式保存，与设置无关。 |

写入挂在哪一楼，就随那一楼一起回滚：滑动、删除那一楼，写入也随之撤销。

### 路径规则

`era:insertByPath`、`era:updateByPath`、`era:deleteByPath` 的 `path` **只能用点分隔对象键**，如 `player.inventory.gold`。

- **不要用 `[n]` 指向数组元素。** ERA 用 lodash 的 `_.set({}, path, value)` 把路径转成指令块，带 `[n]` 的路径会变成一个数组值，结果是整个数组被替换或删除：

  | 写法 | 原数组 `["apple","banana","cherry"]` 变成 |
  | --- | --- |
  | `deleteByPath('items[0]')` | 整个 `items` 被删除 |
  | `updateByPath('items[1]', 'X')` | `[null, "X"]` |
  | `insertByPath('items[3]', 'X')` | 不变（`items` 已存在，插入被忽略） |

- 键名本身含 `.`、`[` 或 `]` 时，路径无法表达，请改用 `*ByObject` 事件。
- 操作数组元素（追加、删除某一项）请用 [`era:patch`](#erapatch)。

### `era:insertByObject`

插入不存在的变量，已存在的路径不会被覆盖。等同于 `<VariableInsert>`。

- **`detail`**：要插入的变量对象。

```javascript
eventEmit('era:insertByObject', {
  testData: {
    description: 'Initial state for testing',
    user: { name: 'Tester', level: 1, stats: { int: 3, str: 2 } },
    items: ['apple', 'banana', 'cherry'],
    metadata: { createdBy: 'script' },
  },
});
```

### `era:updateByObject`

修改已存在的变量，不存在的路径被忽略。等同于 `<VariableEdit>`。

- **`detail`**：只写要改的字段。数字可写成增量 `'+=5'`、`'-=5'`、`'*=2'`、`'/=2'`。

```javascript
// 同时修改 testData.user.level 和 testData.description；不存在的路径（如 testData.status）会被忽略
eventEmit('era:updateByObject', {
  testData: {
    user: { level: 5 },
    description: 'updated',
  },
});
```

### `era:insertByPath`

按路径插入一个不存在的变量；路径已存在时忽略。

- **`detail`**：`{ path: string, value: any }`。`path` 见[路径规则](#路径规则)。

```javascript
eventEmit('era:insertByPath', {
  path: 'testData.inventory',
  value: { gold: 100, slots: ['sword', 'shield'] },
});
```

### `era:updateByPath`

按路径修改一个已存在的变量；路径不存在时忽略。

- **`detail`**：`{ path: string, value: any }`。
- `value` 可以是增量 `'+=10'`、`'-=10'`、`'*=2'`、`'/=2'`：
  - 只在当前值是数字（或纯数字字符串）时计算，否则按普通字符串写入；
  - 除以 0 等得不到有限结果的运算会被跳过。
- `value` 是数组时，整个数组被替换。

```javascript
// 金币加 50
eventEmit('era:updateByPath', { path: 'testData.inventory.gold', value: '+=50' });

// 直接设置等级
eventEmit('era:updateByPath', { path: 'testData.user.level', value: 10 });
```

### `era:deleteByObject`

删除已存在的变量。等同于 `<VariableDelete>`。

- **`detail`**：结构与变量相同，要删除的键的值写**空对象 `{}`**。

```javascript
// 删除 testData.user.stats.int 和 testData.metadata
eventEmit('era:deleteByObject', {
  testData: {
    user: { stats: { int: {} } },
    metadata: {},
  },
});
```

注意：`{ player: {} }` 删除整个 `player`；`{ player: { gold: {}, mana: {} } }` 只删除这两个子键，`player` 本身保留。

### `era:deleteByPath`

按路径删除一个已存在的变量。

- **`detail`**：`{ path: string }`。只能用点分隔的路径，见[路径规则](#路径规则)。

```javascript
eventEmit('era:deleteByPath', { path: 'testData.metadata' });

// 删除数组 items 的第一个元素（后面的元素前移，不留空位）：用 era:patch
eventEmit('era:patch', [{ op: 'remove', path: '/testData/items/0' }]);
```

### `era:patch`

执行 `<VariablePatch>` 中的操作，适合数组增删、整体替换对象、重命名。操作的写法见 [02 指令手册](./02-指令手册.md)。

- **`detail`**：一个操作，或一组操作。

```javascript
eventEmit('era:patch', [
  { op: 'insert', path: '/背包/-', value: '面包' },
  { op: 'delta', path: '/金币', value: -3 },
]);
```

默认设置下，`<VariablePatch>` 块会追加到最后一条 AI 消息的正文。**旧卡**的隐藏正则不认识这个块，它会显示在楼层里。处理方法任选其一：

- 在 ERA 面板“工具”页点“更新旧卡的规则”，换上新的隐藏正则；
- 开启脚本设置 `API写入不修改消息`；
- 改用 `Era.commit`。

### `era:commit`

按顺序提交一组写入，不修改消息正文。参数与 [`Era.commit`](#eracommit) 相同，但拿不到结果，失败只在控制台警告。需要结果时请用 `Era.commit`。

- **`detail`**：`{ operations, mk?, message_id?, atomic?, key? }`。

```javascript
eventEmit('era:commit', { operations: [{ edit: { 金币: '-=3' } }] });
```

## 3. 查询事件

所有查询都通过 `era:queryResult` 事件返回结果，见 [第 5 节](#eraqueryresult)。只读当前变量时，`Era.getCurrentVars()` 更方便；只查某一楼时，[`Era.getVarsAt`](#eragetvarsat) 直接返回 Promise，不必监听 `era:queryResult`。

| 事件 | 作用 | `detail` | 结果 |
| --- | --- | --- | --- |
| `era:getCurrentVars` | 当前最新的变量 | 无 | 单个快照 |
| `era:getSnapshotAtMk` | 某个 MK 那一楼处理完之后的变量 | `{ mk }` | 单个快照 |
| `era:getSnapshotsBetweenMks` | 两个 MK 之间（含两端）每一楼的变量 | `{ startMk?, endMk? }`，省略则从第一楼 / 到最后一楼 | 快照数组 |
| `era:getSnapshotAtMId` | 某个消息 ID 那一楼处理完之后的变量 | `{ message_id }` | 单个快照 |
| `era:getSnapshotsBetweenMIds` | 两个消息 ID 之间（含两端）每一楼的变量 | `{ startId?, endId? }`，省略则从 0 / 到最后一楼 | 快照数组 |

MK（消息密钥）是 ERA 写在每条消息 `<era_data>` 中的唯一标识，形如 `era_mk_1759246942209_jipmrj`。滑动生成的新回复有新的 MK。

```javascript
eventEmit('era:getSnapshotAtMk', { mk: 'era_mk_1759246942209_jipmrj' });
eventEmit('era:getSnapshotAtMId', { message_id: 15 });
eventEmit('era:getSnapshotsBetweenMIds', { startId: 10, endId: 20 });
```

开启 `日志保留楼层数` 后，折叠边界之前的楼层可能查不到（返回 `error`，或只返回可用的部分），除非开启了 `折叠日志存档`。

## 4. 其他请求事件

### `era:requestWriteDone`

让 ERA 重新广播上一次的 `era:writeDone`，用于新打开的界面获取当前状态。

- **`detail`**：无。
- ERA 加载后还没有广播过 `era:writeDone` 时没有响应。初始化时更推荐 `Era.getCurrentVars()`。

```javascript
eventEmit('era:requestWriteDone');
```

### `era:forceSync`

强制同步一次变量，用于手动修复。

- **`detail`**（可选）：`{ mode?, message_id? }`。

| `mode` | 作用 |
| --- | --- |
| `'auto'`（默认） | 普通的差异同步，修复不一致 |
| `'full'` | 从第 0 楼开始完全重算 |
| `'latest'` | 只重算最后一条消息 |
| `'rollbackTo'` | 回滚到 `message_id` 那一楼处理完之后的状态并停在那里，需要提供 `message_id` |

完成后广播 `era:writeDone`。

```javascript
eventEmit('era:forceSync');
eventEmit('era:forceSync', { mode: 'full' });
eventEmit('era:forceSync', { mode: 'rollbackTo', message_id: 10 });
```

## 5. ERA 广播的事件

| 事件 | 何时广播 |
| --- | --- |
| `era:writeDone` | 写入或同步完成后 |
| `era:queryResult` | 回应查询事件 |
| `era:schemaError` | 注册了 schema，且本轮同步中有修改被拦截 |
| `era:commandError` | 本轮同步中有指令没有生效 |
| `era:schemaInvalid` | 注册了 schema，同步后最新的变量不符合它 |
| `era:extraStatus` | 分步更新（额外模型）的进度 |
| `era:toolResult` | 本轮同步中执行了工具调用，见 [`Era.registerTool`](#eraregistertool--erahastool) |

`era:apiWrite`、`era:writeExtra` 是 ERA 内部使用的事件，外部脚本**不要发送，也不要依赖**。

### `era:writeDone`

变量写入或同步完成后广播，携带最新的变量。界面应监听它来刷新。

```typescript
{
  mk: string;            // 本轮最后处理的消息的 MK
  message_id: number;    // 本轮最后处理的消息的 ID
  is_user: boolean;      // 该消息是否由用户发送
  actions: {
    rollback: boolean;       // 保留字段，始终为 false
    apply: boolean;          // 保留字段，始终为 false
    resync: boolean;         // 因聊天记录变化而重算
    api: boolean;            // 本轮处理了 era:* 请求事件（如 era:forceSync）
    apiWrite: boolean;       // 由 ERA 的写入引起的同步：写入事件、Era.commit / applyText / setMessageText，也包括分步更新写回、重新规划
    editedResync: boolean;   // 因编辑消息而重算
    swipedRollback: boolean; // 因滑动生成新回复而回退到上一楼的状态
  };
  selectedMks: (string | null)[];     // 当前聊天每一楼的 MK，下标约等于消息 ID
  editLogs: { [mk: string]: any[] };  // 每一楼的改动记录
  stat: any;                          // 含 $meta、$template 的完整变量
  statWithoutMeta: any;               // 去掉所有 $ 开头字段的变量，推荐用于显示
  consecutiveProcessingCount: number; // 对同一 MK 的连续处理次数，换 MK 后重置为 1
}
```

**防止无限循环**：任何写入最终都会触发 `era:writeDone`。如果你在监听器里又发送写入，会形成“写入 → writeDone → 写入”的循环。请检查 `detail.actions.apiWrite`，或比较变量是否真的变了再写。需要“变量变了就自动改另一个变量”时，请用[更新钩子](#8-更新钩子)：在 `era:writeDone` 里回写的结果不能重放，见[迁移配方](#不要在-erawritedone-里回写变量)。

```javascript
eventOn('era:writeDone', detail => {
  if (detail.actions.apiWrite) {
    // 由写入事件引起，按需跳过
  }
  updateMyUI(detail.statWithoutMeta);
});
```

### `era:queryResult`

回应所有查询事件。

```typescript
{
  queryType: 'getCurrentVars' | 'getSnapshotAtMk' | 'getSnapshotsBetweenMks' | 'getSnapshotAtMId' | 'getSnapshotsBetweenMIds';
  request: any;                       // 原始请求的 detail
  result: QueryResultItem | QueryResultItem[] | { error: string };
  selectedMks: (string | null)[];
  editLogs: { [mk: string]: any[] };
}

// QueryResultItem
{
  mk: string;
  message_id: number;
  is_user: boolean;
  stat: any;            // 含 $meta 等字段
  statWithoutMeta: any; // 不含 $ 开头的字段，推荐使用
}
```

**先检查 `error`**：查询失败时，`result` 中带有 `error` 字段。

```javascript
eventOn('era:queryResult', detail => {
  if (detail.result && detail.result.error) {
    console.error(`ERA 查询 [${detail.queryType}] 失败:`, detail.result.error);
    return;
  }

  if (Array.isArray(detail.result)) {
    // getSnapshotsBetweenMks / getSnapshotsBetweenMIds 返回数组
    detail.result.forEach(item => console.log(item.message_id, item.statWithoutMeta));
  } else {
    console.log(detail.result.message_id, detail.result.statWithoutMeta);
  }
});
```

### `era:schemaError`

注册了 schema、且本轮同步中有修改被 schema 拦截时广播。

```typescript
{
  errors: {
    mk: string | null;   // 发生拦截的消息的 MK
    message_id: number;
    op: 'insert' | 'update' | 'delete'; // 被拦截的改动类型
    path: string;        // 被拦截的变量路径
    value?: any;         // 试图写入的值；delete 没有
    message: string;     // schema 给出的说明
    origin?: 'text' | 'api' | 'hook' | 'tool'; // 被拦截的改动来自哪种指令，见下
    source?: 'extra' | 'api';               // 指令的来源标记，见下
  }[];
}
```

`origin`：`'text'` 是正文里的指令（含 [`Era.applyText`](#eraapplytext) 写入的指令）；`'api'` 是旁路写入（`Era.commit`，或开启 `API写入不修改消息` 时的写入事件）；`'hook'` 是 `onBeforeApply` 钩子追加的指令；`'tool'` 是工具（`<EraFCall>`）产出的操作。由 `onAfterApply` 钩子的修改引起的拦截**没有** `origin`。`origin` 决定指令按哪种规则执行，例如 `'text'` 受 `下划线只读` 限制。

`source`：指令写在哪里，只用于报告，不影响任何规则。`'extra'` 是分步更新写入的 `<era_extra>` 中额外模型的输出；`'api'` 是保存在 `ERAMetaData.ApiOps` 中的旁路写入（`Era.commit`、`Era.applyText`、开启 `API写入不修改消息` 时的写入事件）。主模型写在正文里的指令没有这个字段。宏 `{{ERA-issues}}` 只报告主模型写在正文里的指令（`origin` 为 `'text'`、没有 `source`）和无法解析的块，不报告旁路写入、钩子和分步更新输出的问题，见 [04 宏](./04-宏.md)。

最新一条消息的拦截还会弹窗提示；重算历史消息时的拦截只通过事件报告。

### `era:commandError`

本轮同步中有指令没有生效时广播（路径不存在、已存在、受 `$meta` 保护、JSON 无法解析等）。无论是否开启 `指令失败提示` 都会广播。

```typescript
{
  errors: {
    mk: string | null;
    message_id: number;
    type: 'insert' | 'edit' | 'delete' | 'patch' | 'parse' | 'call'; // parse 表示指令块无法解析，call 表示工具调用失败
    path: string;   // 涉及的路径；parse 时是内容的开头，call 时是工具名或片段
    reason: string; // 没有生效的原因
    origin?: 'text' | 'api' | 'hook' | 'tool'; // 含义同 era:schemaError；无法解析的块没有
    source?: 'extra' | 'api';               // 含义同 era:schemaError
  }[];
}
```

### `era:schemaInvalid`

注册了 schema 时，ERA 在每次同步后检查最新的变量；变量不为空、又不符合 schema 时广播。同一个聊天、同一组问题只广播一次，变量恢复合法后再出问题会重新广播。面板也会提示，点击后打开“诊断”页，可以一键修复。

它只报告，不拦截任何修改：变量已经不合法时，ERA 无法判断是哪条修改造成的，之后的修改照常放行（见[第 7 节的注意事项](#eraregisterschema)）。常见原因是 schema 升级后新增了必填字段，旧聊天里没有。

```typescript
{
  mk: string | null;   // 最后一条消息的 MK
  message_id: number;  // 最后一条消息的 ID
  issues: {
    kind: 'missing' | 'invalid'; // missing：缺必填字段；invalid：类型或取值不符
    path: string;
    message: string;
  }[];
  error?: string;      // schema 的 safeParse 抛出异常时的说明，此时 issues 为空
}
```

要主动检查某一楼的变量，用 [`Era.checkSchema`](#eracheckschema)。

### `era:extraStatus`

分步更新（额外模型）解析某一楼的进度，状态栏可以据此显示“变量更新中”。详见 [06 分步更新](./06-分步更新.md)。

```typescript
{
  mk: string;
  message_id: number;
  status: 'started' | 'retry' | 'done' | 'no_change' | 'no_entries' | 'aborted' | 'failed';
  problems?: string[]; // 重试的原因，或最终没有解决的问题
  warnings?: string[]; // 结束时才有：不影响结果判定的告警（条目过滤器、EJS 渲染出错等）
}
```

| `status` | 含义 |
| --- | --- |
| `started` | 开始解析 |
| `retry` | 输出有问题，正在重试 |
| `done` | 完成，变量已更新 |
| `no_change` | 完成，没有需要更新的变量 |
| `no_entries` | 角色卡没有名字含 `[era_update]` 的世界书条目，没有解析 |
| `aborted` | 已取消（同一楼开始了新一次解析时，旧的一次不再发出任何状态） |
| `failed` | 失败 |

**声明角色卡需要的 ERA 版本**，两种做法可以同时用：

- **角色卡变量 `ERA最低版本`**：在角色卡变量里加一个键 `ERA最低版本`，值写字符串 `"2.0.2"`（可以只写两段，如 `"2.1"`）。写成数字（如 `2.1`）也能识别，但数字末尾的 0 会丢掉（`2.10` 会被当作 `2.1`），建议一律写字符串。ERA 在加载和切换聊天时检查，当前版本更低时提示玩家一次。较早版本的 ERA 不认识这个变量，不会提示。
- **`util/era.ts` 的 `requireEra(min_version, options?)`**：在角色卡脚本里调用，返回 `Promise<boolean>`。等不到 `Era`（ERA 没有启用）或 `Era` 没有 `version`（较早版本的 ERA）时一律视为不满足，因此对旧版 ERA 也能提示。`options.toast`（默认 `true`）决定不满足时是否弹窗，`options.timeout`（默认 `10000` 毫秒）是等待 `Era` 的时间。

```typescript
import { requireEra } from '@util/era';

if (await requireEra('2.0.2')) {
  await Era.applyText(reply);
}
```

版本号可以写 `2.0`、`2.0.2`、`v2.0.2`，缺少的段按 0 计。`era.ts` 的 `compareEraVersions(a, b)` 按同样的规则比较两个版本号。

另外，ERA 在聊天变量 `ERAMetaData` 中记下最近一次写入它的 ERA 版本（`WrittenWith`）。以后玩家用较旧的 ERA（2.0.2 及以后的版本）打开由更新的 ERA 写过的聊天时，ERA 提示一次：新版本功能的结果在旧版本里重算可能不同。

### `Era.getCurrentVars()`

同步返回当前最新的 `{ stat, statWithoutMeta }`，与 `era:getCurrentVars` 的结果相同，但不需要监听 `era:queryResult`。

### `Era.getVarsAt`

`Era.getVarsAt(where)`：某一楼**处理完之后**的变量。只读，不写入任何数据。

“处理完之后”包括挂在这一楼的旁路写入：界面按钮用 `Era.commit` / `Era.applyText` 往第 0 楼写过变量后，`Era.getVarsAt(0)` 返回的是写入之后的值，不是开场白的原始初始值。

- **`where`**：消息 ID（可以用负数从末尾倒数，`-1` 是最后一条消息）、MK，或 `{ message_id }` / `{ mk }`（同时给出时以 `mk` 为准）。
- **返回**：`Promise<{ mk, message_id, is_user, stat, statWithoutMeta }>`，与 `era:getSnapshotAtMId` / `era:getSnapshotAtMk` 的单个快照相同。开启了 `折叠日志存档` 时会先读取存档。
- **失败**：楼层不存在、MK 对应的回复当前没有显示、这一楼还没有计算到（例如 AI 正在输出）、或日志已折叠又没有存档时，Promise 失败并说明原因。

楼层里的状态栏用它显示“那一楼当时”的值，在每次 `era:writeDone` 后重新读取（编辑、删除更早的楼层会改变之后各楼的值）：

```javascript
await waitGlobalInitialized('Era');
const message_id = getCurrentMessageId();
async function render() {
  try {
    const { statWithoutMeta } = await Era.getVarsAt(message_id);
    updateMyUI(statWithoutMeta);
  } catch (error) {
    console.warn(error.message); // 例如这一楼还没有算完；保留上一次的显示
  }
}
eventOn('era:writeDone', render);
render();
```

前端项目可以直接用 `util/era.ts` 的 `defineEraFloorStore`，见[第 9 节](#9-在前端界面中使用)。

### `Era.commit`

`Era.commit(operations, options?)`：按顺序提交一组写入，在写入被**计算完成后**返回结果。不修改消息正文。

- **`operations`**：一项或一组写入。每项只能有一个键：`{ insert }`、`{ edit }`、`{ delete }` 或 `{ patch }`，内容与对应的指令块相同（`patch` 是操作数组）；还可以是工具调用 `{ call: { name, args } }`，效果与正文里的 `<EraFCall>` 相同。
- **`options.mk`** / **`options.message_id`**：写到哪一楼。默认是最后一条 AI 消息（没有 AI 消息时是最后一条消息）。同时给出时以 `mk` 为准；`message_id` 可以用负数从末尾倒数（`-1` 是最后一条消息）。写到旧楼时，之后的楼层会重新计算。
- **`options.atomic`**：为 `true` 时先试算，只要有一项不能生效，就全部不写入。
- **`options.key`**：幂等键。目标楼已有同一个 key 的写入时，这次提交不写入，结果带 `skipped: true`。用于“首次显示时发奖励”“点击领取”这类只能生效一次的写入，例如 `{ key: '领取:第3章' }`。带 key 的写入不参与合并与压缩。
- **返回**：`Promise<{ mk, stat, statWithoutMeta, skipped? }>`。`mk` 是写入的楼层；`stat`、`statWithoutMeta` 是计算完成后最新的变量；`skipped` 见 `options.key`。

写入保存在聊天变量 `ERAMetaData.ApiOps` 中，挂在目标楼层上，效果与开启 `API写入不修改消息` 相同：随该楼一起回滚，AI 在正文里看不到它们。这类写入不受 `下划线只读` 限制。

**原子提交（`atomic: true`）**：ERA 先把之前的改动同步完，再从目标楼的上一楼状态开始，把整楼（正文、已有的旁路写入、这次的写入、钩子、schema）完整试算一遍。这次的写入只要引入任何问题（路径不存在、被 schema 拒绝等），Promise 就失败，信息形如 `提交被放弃: 路径: 原因`，什么都不写入。目标楼之前的日志已折叠、又没有存档时无法试算，会直接失败。

**失败的情况**：

| 错误信息 | 含义 |
| --- | --- |
| `没有要写入的内容` | `operations` 为空（`undefined`、`null`、空数组），没有写入 |
| `写入的内容无法转换成 JSON: …` | `operations` 中有循环引用等无法转成 JSON 的内容，没有写入 |
| `每项写入必须是 { insert } / { edit } / { delete } / { patch } / { call } 之一` | 格式错误，没有写入 |
| `key 必须是非空字符串` | `options.key` 不是非空字符串，没有写入 |
| `目标消息不存在` / `目标消息仍在生成中` / `没有可以写入的消息` | 找不到可写的楼层 |
| `该楼之前的日志已折叠，无法预先检查；请不要使用 atomic` | 原子提交无法试算，没有写入 |
| `提交被放弃: …` | 原子提交的试算发现问题，没有写入 |
| `聊天已切换` | 写入完成前切换了聊天 |
| `目标消息已被删除或切换到了其他回复，写入随该楼一起撤销（滑回该回复时会重新生效）` | 写入已保存，但计算完成前目标楼被删除或滑走。写入挂在那条回复上：删除的不会再生效，滑回该回复时重新生效 |
| `写入没有在限定时间内执行，已放弃` | 20 秒内没有轮到执行，这次写入不会再执行 |
| `写入已保存，但同步没有在限定时间内完成` | 写入已保存，目标楼仍在，但 20 秒内没有算完；之后的同步仍会让它生效 |

```javascript
try {
  const { statWithoutMeta } = await Era.commit(
    [{ edit: { 金币: '-=3' } }, { patch: [{ op: 'insert', path: '/背包/-', value: '面包' }] }],
    { atomic: true },
  );
  console.log(statWithoutMeta.金币);
} catch (error) {
  toastr.warning(error.message); // 例如金币不足被 schema 拒绝
}
```

### `Era.applyText`

`Era.applyText(text, options?)`：把一段文本里的指令应用到一楼，**不修改正文**，在写入被计算完成后返回。用于同层前端：前端自己用 `generate` 请求 AI，自己显示回复，把回复里的指令交给 ERA。

- **`text`**：含指令块的文本，解析方式与 AI 消息正文相同，见 [`Era.parseCommands`](#eraparsecommands)。
- **`options`**：与 [`Era.commit`](#eracommit) 相同（`mk`、`message_id`、`atomic`、`key`）。`atomic: true` 时，有任何一条指令不能生效、或有无法解析的块，就全部不写入；不用 `atomic` 时，无法解析的块被跳过，其余照常写入。
- **返回**：与 `Era.commit` 相同，`Promise<{ mk, stat, statWithoutMeta, skipped? }>`。

与正文的关系：

- 文本在写入时解析一次，解析出的指令保存为旁路写入（聊天变量 `ERAMetaData.ApiOps`，标记 `origin: 'text'`），挂在目标楼上，排在该楼正文的指令和已有的旁路写入之后。之后的重算直接用保存的指令，不再解析文本。
- 这些指令**按正文指令的规则执行**：`下划线只读` 会限制它们（`Era.commit` 不受限制）；钩子、schema、`$meta` 保护照常生效。错误事件中它们的 `origin` 是 `'text'`、`source` 是 `'api'`；`{{ERA-issues}}` 不报告它们。
- 回滚与 `Era.commit` 相同：随目标楼一起回滚，删除或滑走该楼时撤销，滑回该回复时重新生效。
- 指令不在正文里，AI 看不到；聊天变量是它们的唯一副本，注意事项与 [`API写入不修改消息`](#api写入不修改消息) 相同。前端改写该楼正文时，用 [`Era.keepMessageKey`](#erakeepmessagekey) 保留 MK，否则这些写入会在下一次完全同步时被清除。
- 表达式 `$expr` 的骰点按写入序号取种子，与“这段文本写在正文里”时不同，`Era.simulate` 无法预览，见 [`Era.simulate`](#erasimulate)。

失败的情况除了 [`Era.commit` 的表格](#eracommit)，还有：

| 错误信息 | 含义 |
| --- | --- |
| `text 必须是字符串` | 参数类型错误，没有写入 |
| `选项无法转换成 JSON: …` | `options` 无法转成 JSON，没有写入 |
| `文本中没有可以执行的指令` | 文本里没有指令块（或都在思考块里、外层标签外），没有写入 |
| `文本中的指令无法解析: …` | 指令块都无法解析，没有写入 |

```javascript
await waitGlobalInitialized('Era');
const reply = await generate({ user_input: '……' });
try {
  const { statWithoutMeta } = await Era.applyText(reply, { message_id: 0 });
  updateMyUI(statWithoutMeta);
} catch (error) {
  toastr.warning(error.message);
}
```

### `Era.parseCommands`

`Era.parseCommands(text)`：解析一段文本里的指令块，**不执行、不写入**。

- 解析方式与 AI 消息正文相同：先替换 `{{user}}`、`{{char}}`，再按脚本设置 `繁体转简体`、`宽松解析` 处理；当前聊天是新建的聊天时，思考标签里的指令不算，设置了 `指令外层标签` 时只认标签内的指令（见[第 10 节](#思考标签-与-指令外层标签)）。
- **返回**：`{ commands, problems }`（同步返回）。`commands` 是按出现顺序排列的指令块 `{ type: 'insert' | 'edit' | 'delete' | 'patch' | 'call', data: any[] }[]`，`data` 未转义，一个块可以有多个对象（工具调用 `call` 为 `[{ name, args }]`）；`problems` 是无法解析的块 `{ path, reason }[]`。

```javascript
const { commands, problems } = Era.parseCommands(reply);
if (problems.length > 0) console.warn(problems);
```

### `Era.simulate`

`Era.simulate(text, where?, options?)`：把一段含指令的文本当作一条新的 AI 消息试算，**不写入任何数据**。

- **`text`**：含指令块的文本，如 `'<VariableEdit>{"金币":"-=3"}</VariableEdit>'`。解析方式与 AI 消息正文相同：新建的聊天中，思考标签里、外层标签外的指令不算。
- **`mk`**：在哪一楼处理完之后的状态上试算；省略时用最新状态。
- **`options.seedMk`**：表达式 `random()` / `roll()` 和钩子的 `ctx.random()` 按哪个 MK 取种子。省略时不对应任何消息，骰点仅供参考。指定时，骰点与“这段文本写在该楼正文里”时相同。它只对应正文里的指令：`Era.applyText`、`Era.commit` 的旁路写入按写入序号取种子，骰点不同；要在写入前检查旁路写入能否生效，用 `atomic: true` 提交（试算不通过时什么都不写入）。
- **返回**：`Promise<{ stat, problems: { path, reason }[] }>`。`stat` 不含 `$meta` 等字段；钩子和 schema 照常参与。
- MK 不存在、或该楼的日志已折叠又没有存档时，Promise 失败。

### `Era.setMessageText`

`Era.setMessageText(where, text)`：改写一楼的正文，并按新正文重新计算变量，算完后返回 `Promise<{ mk, stat, statWithoutMeta }>`。用于同层前端重画界面楼层、脚本替换某一楼的内容。

- **`where`**：楼层的消息 ID（可以用负数从末尾倒数）、MK，或 `{ mk, message_id }`。改写的是该楼当前显示的回复；给 MK 时可以改写没有显示的 swipe。
- 自动把 ERA 写在原正文里的块（`<era_data>`、`<era_extra>`、玩家消息里的 `<era_plan>`）补到新正文里，新正文里已经有的不再补，效果与先调用 `Era.keepMessageKey` 相同。
- **只补这三种 ERA 自己写的块。** 原正文里 AI 或开场白写的指令块（`<VariableInsert>` 等）、工具调用和状态栏占位符不会补回；只改文字时要把它们原样带回新正文，否则重算后这些指令的效果会消失。详见 [03 状态栏](./03-状态栏.md#改写正文时要自己带回的内容)。
- 新正文里的指令按正文指令的规则执行；挂在这一楼的旁路写入（`Era.commit`、`Era.applyText`）仍然保留，它和额外模型输出（`<era_extra>`）之间的先后不会因为改写正文而改变。旁路写入记着“排在正文第几个指令块之后”，新正文里的指令块比原来少时，它排在现有的正文指令之后。
- 只是往某一楼写变量时不要改正文，用 `Era.applyText` 或 `Era.commit`。
- 楼层不存在、这一楼还没有被 ERA 登记（没有 MK）时 Promise 失败；钩子、工具执行期间调用会被拒绝（见[重入保护](#重入保护)）。

```javascript
// 这一楼原来没有指令块时可以直接换；有的话（例如带初始化指令的开场白）要把指令块一起写进新正文
const { statWithoutMeta } = await Era.setMessageText(-1, '<div>新的界面</div>');
```

### `Era.sync`

`Era.sync(mode?)`：请求一次同步并等它完成，返回 `Promise<boolean>`。相当于可以等待的 [`era:forceSync`](#eraforcesync)。

- **什么时候用**：脚本删楼、切换 swipe 之后（酒馆助手的 `deleteChatMessages`、`setChatMessages` 默认不通知 ERA），或用 `refresh: 'none'` 建楼之后。等它完成再读变量、生成或建下一楼。
- **`mode`**：`'auto'`（默认，按聊天记录的变化决定重算范围）、`'latest'`（只重算最新一楼）、`'full'`（从第一楼完全重算）。
- 返回 `true` 表示同步已经完成；`false` 表示等了 20 秒还没有完成。钩子、工具执行期间调用会被拒绝。

```javascript
await deleteChatMessages([lastId]);
await Era.sync();
const { statWithoutMeta } = Era.getCurrentVars();
```

**界面刚加载时先等一次同步。** `waitGlobalInitialized('Era')` 只表示接口可以调用了，不表示当前聊天已经算完：新开聊天、切换聊天时，第一次同步可能还在排队，这时读到的变量是空的或上一个聊天的，`Era.simulate` 也会按空变量试算。界面初始化时先 `await Era.sync()` 再读变量、试算。

```javascript
await waitGlobalInitialized('Era');
await Era.sync();
const { statWithoutMeta } = Era.getCurrentVars();
```

### `Era.keepMessageKey`

`Era.keepMessageKey(text, from)`：前端用 `setChatMessages` 等改写楼层正文时，把 ERA 写在原正文里的块补到新正文末尾，返回补好的正文。

- **`<era_data>`**：该楼的 MK。丢失后，挂在该楼的旁路写入（`Era.commit`、`Era.applyText`、开启 `API写入不修改消息` 时的写入事件）会在下一次完全同步时被清除。
- **`<era_extra>`**：分步更新写入的额外模型输出。丢失后，额外模型写入的变量随之回滚。
- **`<era_plan>`**：正文前规划写在玩家消息里的结算。丢失后，规划写入的变量随之回滚。
- 只补这三种块。原正文里的指令块、工具调用和状态栏占位符要自己带回，见 [03 状态栏](./03-状态栏.md#改写正文时要自己带回的内容)。
- **`from`**：原来的正文，或楼层的消息 ID（可以用负数从末尾倒数；读该楼当前显示的回复）。
- `text` 已经含有某种块时不再补这种块；原正文里也没有时原样返回。
- `from` 是楼层号而这一楼不存在时抛出错误（例如拿着删楼之前记下的楼层号调用）。

```javascript
await setChatMessages([{ message_id: 0, message: Era.keepMessageKey(newText, 0) }]);
```

酒馆助手的 `setChatMessages` 改写正文后，酒馆不会发出“消息已修改”的事件，ERA 不知道正文变了，新正文里的指令有增减时变量不会跟着变。更省事的做法是用 `Era.setMessageText(楼层, 新正文)`：它自动保留 ERA 的块、改写正文、按新正文重算，算完后返回。坚持用 `setChatMessages` 时，改写后自己发一次 `eventEmit('era:forceSync')`。玩家在酒馆界面上手动编辑消息不受影响。

### `Era.math`

确定性数学函数，用法同 `Math`：`PI`、`E`、`exp`、`expm1`、`log`、`log1p`、`log2`、`log10`、`sin`、`cos`、`tan`、`asin`、`acos`、`atan`、`atan2(y, x)`、`sinh`、`cosh`、`tanh`、`asinh`、`acosh`、`atanh`、`hypot(x, y)`、`pow`、`sqrt`、`abs`、`sign`、`floor`、`ceil`、`trunc`、`round`、`min`、`max`。

与 `Math` 的区别：三角、指数、对数、乘方由 ERA 自己计算（移植自 fdlibm），在各浏览器、各设备上结果逐位一致；`Math.sin`、`Math.exp`、`Math.pow`、`**` 的最后几位可能因浏览器而不同。玩家换了浏览器或设备后重算历史楼层，用 `Math` 算出的变量就可能变化。

- 钩子里用 `ctx.math`（同一个对象），见[第 8 节](#8-更新钩子)。
- 前端需要与 ERA 重算结果一致的数值时用 `Era.math`，或 `util/era.ts` 的 `getEraMath()`。
- `Era.math.round` 与 `Math.round` 相同（.5 向正无穷取整），与表达式 `$expr` 里的 `round`（.5 远离零）不同。
- `atan2` 的参数是 y 在前；`hypot` 只接受两个参数。

### `Era.describeSchema()`

返回已注册 schema 的文字说明（类型、可选值、范围），没有注册时返回空字符串。内容与宏 `{{ERA-schema}}` 相同，见 [04 宏](./04-宏.md)。

### `Era.extra`

控制分步更新（额外模型），详见 [06 分步更新](./06-分步更新.md)。

| 方法 | 作用 |
| --- | --- |
| `Era.extra.run(where?)` | 请额外模型重新解析某一楼，省略时为最后一条 AI 消息；不要求开启分步更新。解析结束后返回 `{ mk, ok, status, problems, warnings }`（`status` 与 `era:extraStatus` 的结果状态相同，`ok` 表示 `done` 或 `no_change`；`warnings` 是不影响结果判定的告警，如条目过滤器出错、EJS 渲染出错或超时），同时照常发出 `era:extraStatus` 和弹窗。MK 不存在（或不是当前显示的 swipe）、没有 AI 消息时 Promise 失败。 |
| `Era.extra.autoRun(where)` | 按自动触发的同样条件解析一楼：没有开启分步更新、是玩家消息、正文自己带有指令时不请求，返回 `null`；否则返回与 `run` 相同的结果。成功和无变化时不弹提示。自己建楼的前端在建好 AI 楼之后调用，因为脚本建的楼不会触发自动解析。`where` 是楼层的消息 ID、MK 或 `{ mk, message_id }`；找不到这一楼或它还没有 MK 时 Promise 失败。 |
| `Era.extra.settings()` | 同步返回 `{ update, plan }`：分步更新、正文前规划当前实际生效的开关（已经合并角色卡推荐和默认值；规划在群聊里不生效）。不含接口地址和密钥。 |
| `Era.extra.planInjection(from)` | 返回玩家消息里的规划对应的注入文字，与原生发送时 ERA 注入给剧情模型的逐字相同；没有规划时返回空字符串。`from` 是玩家消息的正文或楼层号。自己调用 `generate()` 的前端用它，见 [03 状态栏](./03-状态栏.md#同层前端须知)。 |
| `Era.extra.abort(where?)` | 取消某一楼正在进行的解析；省略时取消全部。 |
| `Era.extra.wait()` | 等待正在进行的解析完成；没有时立即完成。也等待已写进正文、但同步还没算完的输出（`status().pendingSync`）。返回 `true` 表示都已完成；`false` 表示到了时限（按“(重试次数 + 1 + 备用接口数) × 超时”加上退避、写入和同步的时间计算；`EJS预处理` 为“自动”时另加最多 15 秒的条目渲染时间）或玩家点击了“正在等待”提示框放弃等待。 |
| `Era.extra.plan(text)` | 正文前规划：按 `[era_plan]` 条目为一段玩家文字做规划，返回 `{ status, summary, blocks, text, problems, warnings }`，`text` 是追加了 `<era_plan>` 的文字，不写入任何内容。`status`：`done` 有结果，`no_change` 不需要结算，`no_entries` 卡里没有 `[era_plan]` 条目，`failed` 失败，`aborted` 被新的规划取代。脚本、快速回复自己发送消息时用它；玩家点击发送时由设置 `正文前规划` 自动进行 |
| `Era.extra.replan()` | 重新规划最新一条玩家消息，替换其中的 `<era_plan>`；它后面已有回复时，要重新生成才会按新的结果写。出错时弹窗提示并返回 `null` |
| `Era.extra.status()` | 同步返回 `{ running, last, history, pendingSync }`：`running` 是正在进行的解析 `{ mk, startedAt, attempt }[]`（`attempt` 为已发出的请求次数）；`last` 是最近一次结束的分步更新 `{ mk, ok, error?, prompt?, rawReply?, finishedAt, status, problems, warnings }`，含实际发送的提示词（包括头部提示词和预设条目）和原始回复，没有时为 `null`；`history` 是最近 10 次分步更新与正文前规划的记录，最新的在前，每条比 `last` 多一个 `type`（`'update'` 或 `'plan'`），规划的 `mk` 是玩家楼（发送前规划时还没有 MK，为空字符串），卡里没有 `[era_plan]` 条目、没有发出请求的规划不记录；`pendingSync` 是输出已写进正文、但同步还没算完的楼层的 MK。只保存在内存中，切换聊天时清空，不含 API 密钥。界面晚于 `started` 事件加载时，用它恢复“变量更新中”的显示。 |

```javascript
const { ok, status, problems } = await Era.extra.run();
if (!ok) console.warn(status, problems, Era.extra.status().last?.rawReply);
```

前端界面自己触发生成（如 `/trigger`、`generate`）之前，应先 `await Era.extra.wait()`，避免下一轮生成读到旧变量。

### `Era.registerEntryFilter` / `Era.hasEntryFilter`

`Era.registerEntryFilter(name, filter)`：注册条目过滤器，按变量决定世界书条目发不发、发什么内容，在世界书文件里的开关之前运行，不改世界书文件。分步更新收集 `[era_update]` / `[era_both]` 条目时按**目标楼**的状态调用；正文前规划和主生成（玩家触发的剧情生成加载世界书时，先等变量同步完；dry run、quiet 生成，以及脚本用 `generate` / `generateRaw` 发起的生成（包括同层前端自己发起的）都不调用）也调用，按最新的状态。返回注销函数。`Era.hasEntryFilter(name)` 返回当前角色卡是否注册了该名字的过滤器。

- **`filter(entry, ctx)`**：`entry` 是条目的副本 `{ world, uid, name, content, enabled, … }`；`ctx` 是 `{ stat, statRaw, text, mk, purpose }`，`stat` 是目标楼（主生成和规划时是最新）去掉 `$` 字段、已反转义的变量，`text` 是匹配关键字用的最近几楼正文，`mk` 是目标楼的 MK（主生成时为最新一楼，发送前规划时为空字符串），`purpose` 是 `'extra'`（分步更新）、`'plan'`（正文前规划）或 `'main'`（主生成）。主生成里返回 `true` 或字符串的条目被打开、设为常驻并关闭概率，但仍受酒馆的延迟、分组和上下文预算限制，不保证发送；带粘性（sticky）或冷却（cooldown）的条目在主生成里只能排除，返回 `true` 或字符串会被忽略并记一条警告。返回 `false` 的这一次不发送。
- **返回值**：`false` 排除；`true` 纳入（即使文件里关闭了）；字符串表示纳入并替换内容；其他值表示不表态，按文件里的开关和关键字处理。
- 过滤器必须是同步的、只依赖参数的纯函数。出错、返回 Promise、或执行期间调用了写入接口（见[重入保护](#重入保护)）时，忽略它的结果，并记入告警：分步更新时在结果的 `warnings` 里，正文前规划时在 `Era.extra.plan` 结果的 `warnings` 里，主生成时只输出到控制台。
- 同名的过滤器会被替换，多个过滤器按名字顺序调用。名字不是非空字符串或 `filter` 不是函数时不注册，弹窗提示“条目过滤器注册失败”。
- 与钩子一样只保存在内存中，绑定当前角色卡，需要在角色卡脚本每次加载时注册。前端项目用 `util/era.ts` 的 `registerEraEntryFilter(name, filter)`，ERA 重载后会自动补注册。

```javascript
const off = Era.registerEntryFilter('我的卡.规则二选一', (entry, ctx) => {
  if (entry.name.includes('[觉醒前]')) return !ctx.stat.主角?.已觉醒;
  if (entry.name.includes('[觉醒后]')) return !!ctx.stat.主角?.已觉醒;
});
$(window).on('pagehide', off);
```

详细的处理顺序和示例见 [06 分步更新的“条目过滤器”](./06-分步更新.md#条目过滤器)，按变量切换条目的整体做法见 [08 动态提示词](./08-动态提示词.md)。

### `Era.registerTool` / `Era.hasTool`

工具让 AI 调用作者写的 JS 函数：AI 在正文里写 `<EraFCall name="工具名">{"参数": 值}</EraFCall>`（写法见 [02 指令手册](./02-指令手册.md#工具调用-erafcall)），ERA 在执行本楼指令时**按位置**调用工具的 `handler`。`handler` 读到的是执行到这里时的变量（同一楼前面的指令已经生效），返回普通的变量操作，这些操作紧接着执行，同样经过 schema、`$meta` 保护和日志。重算时重新执行，不保存额外的数据。

钩子拿不到“执行到某条指令时的中间状态”，复杂的多步结算（战斗、交易、合成）用工具更合适；只做数值计算、不需要读变量的，用更轻的[自定义公式函数](#eraregisterexprfn--erahasexprfn)。

`Era.registerTool(name, definition)` 返回注销函数，`Era.hasTool(name)` 返回当前角色卡是否注册了该工具。`definition`：

| 字段 | 说明 |
| --- | --- |
| `handler(args, ctx)` | 必填。同步纯函数，返回操作数组（格式同 `Era.commit`，不能再含 `call`），或 `{ operations?, result? }`；`result` 会出现在 `{{ERA-toolResults}}` 和 `era:toolResult` 里，告诉 AI 结算结果。抛出异常表示调用失败，原因会报告出来 直接返回单个操作对象（`return { edit: {…} }`）是错误写法，这次调用会失败并报告原因。 |
| `parameters` | 参数的 zod schema：先 `safeParse`，不合法时调用失败，`handler` 收到的是校验后的值。也可以只写一段说明文字（不校验） |
| `description` | 给 AI 看的说明，`{{ERA-tools}}` 会列出 |
| `version` | 改了 `handler` 的逻辑时提高它，ERA 会完全重算一次，让历史按新逻辑结算 |

`ctx` 有 `mk`、`stat`（执行到这里时的变量，副本）、`old_stat`（本楼开始前的变量）、`random()`（按 MK、工具名和调用位置取种子，重算不变）、`math`（确定性数学函数）。

```javascript
import { registerEraTool } from '@util/era'; // 或直接调用 Era.registerTool

registerEraTool('攻击', {
  description: '主角对一个敌人发动普通攻击',
  parameters: z.object({ 目标: z.string().describe('敌人的名字') }),
  version: 1,
  handler({ 目标 }, ctx) {
    const enemy = ctx.stat.敌人?.[目标];
    if (!enemy) throw new Error(`没有名为 ${目标} 的敌人`);
    const damage = Math.max(1, ctx.stat.主角.攻击 - enemy.防御 + Math.floor(ctx.random() * 6));
    const hp = Math.max(0, enemy.生命 - damage);
    return {
      operations: [{ edit: { 敌人: { [目标]: { 生命: hp } } } }],
      result: { 伤害: damage, 击败: hp === 0 },
    };
  },
});
```

规则：

- 与钩子相同，`handler` 必须是同步的、只依赖参数的纯函数，返回 Promise 时调用失败；执行期间调用写入接口会被拒绝（[重入保护](#重入保护)）。
- 用户消息里的调用不执行；每楼最多执行 50 次调用，一次调用最多产出 200 个操作。
- 调用失败（未知工具、参数不合法、`handler` 出错）时报告问题（`era:commandError`，类型 `call`），本楼后面的指令照常执行；主模型写的调用失败会出现在 `{{ERA-issues}}` 里。
- 工具产出的操作不受 `下划线只读` 限制（与钩子一样是作者的代码）。
- 工具在注册之前就被调用过（例如聊天加载时脚本还没注册），注册后 ERA 会完全重算一次。
- 新聊天里思考块中的调用不执行；分步更新（额外模型）的输出也可以调用工具，注册了工具时，发给更新模型的提示词会自动附上工具说明。

**`era:toolResult`**：每次同步后，对本轮计算过、有工具调用的楼层广播一次：

```javascript
eventOn('era:toolResult', ({ results }) => {
  for (const { mk, message_id, calls } of results) {
    for (const call of calls) console.log(message_id, call.name, call.ok ? call.result : call.error);
  }
});
```

`calls` 的每项是 `{ name, args, ok, result?, error?, operations }`。重算历史楼层时也会再次广播，按 `mk` 去重。

### `Era.registerExprFn` / `Era.hasExprFn`

`Era.registerExprFn(name, fn, options?)`：注册在 `$expr` 里调用的自定义公式函数，返回注销函数；`Era.hasExprFn(name)` 返回是否注册了它。

```javascript
Era.registerExprFn('伤害', (攻击, 防御) => Math.max(1, 攻击 - 防御), { params: 2, description: '攻击减防御，至少 1' });
// AI 写：<VariableEdit>{"敌人": {"生命": {"$expr": "敌人.生命 - 伤害(主角.攻击 + roll(1, 6), 敌人.防御)"}}}</VariableEdit>
```

- `fn` 只接收数字参数、返回有限数字，必须是同步纯函数；它不读变量（需要读变量的用工具）。三角、指数等请用 `Era.math`，不要用 `Math.sin` 之类（各浏览器的末位可能不同）。
- `options.params`：参数个数，一个数表示固定个数，`[最少, 最多]` 表示范围，默认 0～16 个。`options.description` 会出现在 `{{ERA-exprFns}}` 里。改了公式时提高 `options.version`，ERA 会完全重算一次。
- 名字只能由字母、数字、下划线和中文组成，不以数字开头，不能与内置函数或常量同名，也不能叫 `call`（保留给[存成变量的公式](./02-指令手册.md#存成变量的公式-call)）。查找时已注册的函数优先，以后 ERA 新增同名的内置函数也不会改变你的卡的结果。
- 一个表达式里最多调用自定义函数 200 次。
- 表达式在函数注册之前算过（结果是“未知函数”），注册后 ERA 会完全重算一次。
- 不写脚本的卡可以把公式文本存成变量，让 AI 用 `call(公式.伤害, 主角.攻击, 敌人.防御)` 调用，见 [02 指令手册](./02-指令手册.md#存成变量的公式-call)。存成变量的公式里也能调用这里注册的函数。

`util/era.ts` 的 `registerEraTool`、`registerEraExprFn` 会等待 ERA 加载、ERA 重载后自动补注册、脚本卸载时注销，用法与 `registerEraHook` 相同。

## 7. 变量结构 schema

### `Era.registerSchema`

`Era.registerSchema(schema, options?)`：注册变量结构。`schema` 是一个 zod schema（或任何带 `safeParse` 方法的对象）。**不注册时 ERA 的行为完全不变。**

注册后，ERA 在每个指令块执行之后：

1. **纠正**：把 schema 的 `coerce`、`transform` 等结果写回变量，例如把 `"5"` 转成 `5`、把超出范围的数值钳回范围内。
2. **拦截**：丢弃会让原本合法的变量变得不合法的修改，同一块里的其他修改照常生效，并广播 `era:schemaError`。

校验的单位：

| 指令 | 校验单位 |
| --- | --- |
| `<VariableInsert>` / `<VariableEdit>` / `<VariableDelete>` | 整个指令块 |
| `<VariablePatch>` | 每个操作单独校验，被拒绝的操作不影响同块的其他操作 |

补全默认值（`prefault` / `default`）的时机：每个 `<VariableEdit>` 和 `<VariablePatch>` 执行之前，以及一条消息的全部指令执行完之后。不在 `<VariableInsert>` 之前补全，是为了不让默认值抢先占位，导致开场白里的初始值被忽略。

纠正和拦截的结果都记入该楼的日志，因此回滚、滑动、完全重算都不受影响。

```javascript
await waitGlobalInitialized('Era');

// 数字：只接受数字和纯数字文本。不要用 z.coerce.number()，见下面的注意事项
const Num = z.union([z.number(), z.string().trim().regex(/^[+-]?\d+(\.\d+)?$/).transform(Number)]);

const Schema = z.object({
  player: z.object({
    hp: Num.transform(value => _.clamp(value, 0, 100)),
    name: z.string(),
  }),
});

const unregister = Era.registerSchema(Schema);
// 脚本卸载时注销，避免切换角色卡后旧的 schema 继续生效
$(window).on('pagehide', unregister);
```

前端项目里更推荐用 `util/era.ts` 的 `registerEraSchema(Schema)`：它会等待 ERA 加载、在 ERA 重载后自动补注册、脚本卸载时自动注销，见[第 9 节](#9-在前端界面中使用)。

**`options`**：

| 选项 | 默认 | 含义 |
| --- | --- | --- |
| `keepUnknownRootKeys` | `true` | 保留 `stat_data` 顶层那些 schema 没有定义的键。`z.object` 默认会丢弃未定义的键，开启后不会误删没写进 schema 的顶层变量。嵌套对象仍按 schema 自身的定义处理。 |
| `fillDefaultsOnEmpty` | `false` | 变量完全为空时也补全默认值。角色卡不用 `<VariableInsert>` 初始化、完全靠 schema 默认值时设为 `true`。 |
| `resync` | `true` | 注册后立即重算最新楼层，使现有变量符合 schema。 |

**返回值**：注销函数。`schema` 无效（没有 `safeParse` 方法）时不注册，弹窗提示“变量结构注册失败”，但不抛出异常，以免已发布的卡停止运行；可以用 `Era.hasSchema()` 确认是否注册成功。

**注意事项**：

- **不要用 `z.coerce.number()`**：它会把 `null`、空字符串、`true` 变成 `0` 或 `1`，掩盖 AI 写错的值。请用上面示例中的 `Num`。
- schema 必须幂等：`Schema.parse(Schema.parse(x))` 应与 `Schema.parse(x)` 相同，因为同一条消息可能被多次重算。
- 修改前的变量本身就不合法时（例如还没初始化完整），ERA 无法判断是哪条修改造成的问题，该块的修改全部放行。同步后最新的变量不合法时会广播 [`era:schemaInvalid`](#eraschemainvalid)，面板也会提示；可以用 [`Era.checkSchema`](#eracheckschema) 或面板“诊断”页查看问题并一键修复。
- `<VariableInsert>` 不覆盖已存在的路径。schema 补上默认值之后，之后的消息再对该字段用 `<VariableInsert>` 会被忽略，需要改用 `<VariableEdit>`。建议在同一条消息（通常是开场白）中初始化完所有变量。
- `$meta` 和 `$template` 是 ERA 的保留字段，不参与校验，也不会被 schema 删除。
- schema 的结果需要能用 JSON 表示，`Date` 等类型会按 JSON 序列化后的形式保存。
- schema 只保存在内存中，需要在**角色卡脚本**每次加载时注册。它绑定在注册时的角色卡上（群聊中绑定在群组上），切换到其他角色卡后自动失效。ERA 脚本被重新启用或更新后，schema 会丢失；`registerEraSchema` 会自动补注册，直接调用 `Era.registerSchema` 时需要重新加载角色卡脚本。
- 想让 AI 也知道变量结构，在世界书里写 `<变量结构>{{ERA-schema}}</变量结构>`，见 [04 宏](./04-宏.md)。

### `Era.unregisterSchema(schema?)`

注销 schema。传入 `schema` 时，只有当前生效的正是它才注销。返回是否确实注销了一个 schema。

### `Era.hasSchema()`

返回当前是否注册了 schema。

### `Era.checkSchema`

`Era.checkSchema(where?)`：检查变量是否符合当前注册的 schema。只读，不修改变量。

- **`mk`**：检查哪一楼处理完之后的变量；省略时检查最新的变量。
- **返回**：`Promise<{ registered, valid, issues, error? }>`。
  - `registered`：是否注册了 schema；没有注册时 `valid` 为 `true`。
  - `issues`：`{ kind, path, message }[]`。`kind` 为 `missing` 表示缺必填字段（多半是 schema 升级新增了字段，旧聊天里没有），`invalid` 表示类型或取值不符。
  - `error`：schema 的 `safeParse` 抛出异常时的说明。
- MK 不存在、或该楼的日志已折叠又没有存档时，Promise 失败。

```javascript
const { valid, issues } = await Era.checkSchema();
if (!valid) console.table(issues);
```

## 8. 更新钩子

### `Era.onBeforeApply` / `Era.onAfterApply`

`Era.onBeforeApply(id, hook, options?)`、`Era.onAfterApply(id, hook, options?)`：注册钩子，在**同一次计算中**修改指令或变量，不需要监听 `era:writeDone` 再发一轮写入。

| 钩子 | 调用时机 | 能改什么 |
| --- | --- | --- |
| `onBeforeApply` | 每条 AI 消息的指令解析出来之后、执行之前 | `ctx.commands`：可修改、删除、追加 |
| `onAfterApply` | 每条 AI 消息的指令执行、schema 纠正之后 | `ctx.stat`：修改作为普通改动记入该楼日志，同样经过 schema 校验 |

```javascript
await waitGlobalInitialized('Era');
const off = Era.onAfterApply('我的角色卡.面板计算', ({ stat, old_stat, random }) => {
  if (!stat.player) return;
  stat.player.maxHp = 100 + stat.player.level * 10;
  if (stat.day !== old_stat.day) {
    stat.weather = random() < 0.3 ? '雨' : '晴';
  }
});
$(window).on('pagehide', off);
```

**`ctx`**：

| 字段 | 说明 |
| --- | --- |
| `mk` | 本条消息的 MK，重算时不变 |
| `old_stat` | 本条消息执行前的变量（副本，改了无效） |
| `stat` | 仅 `onAfterApply`：执行后的变量，可原地修改或整体赋值 |
| `commands` | 本条消息的指令（含挂在该楼的旁路写入）：`{ type: 'insert' \| 'edit' \| 'delete' \| 'patch' \| 'call', data: any[] }[]`。`patch` 的 `data` 是原样的操作数组，`call` 的 `data` 是 `[{ name, args }]`。`edit` 的数据里可能有尚未求值的表达式叶子 `{ "$expr": "…" }`，按数字处理指令的钩子要跳过它 |
| `commands[i].source` | 这条指令是谁写进来的（只读）：`'api'` 是脚本或界面的旁路写入（`Era.commit`、`Era.applyText`、开启 [`API写入不修改消息`](#api写入不修改消息) 时的写入事件），`'extra'` 是额外模型写进 `<era_extra>` 的指令；正文里的指令（AI、开场白）没有这一项。**只想限制 AI、放过界面按钮的提交时，用 `if (command.source === 'api') continue;`。** 默认设置下写入事件是把指令块追加进正文，之后和 AI 写的分不出来；需要区分时改用 `Era.commit` 或 `Era.applyText`。 |
| `commands[i].origin` | 这条指令按哪一类规则执行（只读）：`'text'` 按正文指令的规则，`'api'` 结构化的旁路写入（`Era.commit`、不改正文的写入事件），`'hook'` 钩子生成，`'tool'` 工具返回。`Era.applyText` 的指令按正文规则执行，所以它的 `origin` 是 `'text'`、`source` 是 `'api'`。 |

> 钩子里的 `source`、`era:schemaError` / `era:commandError` 的 `source`、`/era-issues format=json` 的 `source` 取值相同：`'api'` 是旁路写入，`'extra'` 是额外模型的输出。卡片可以用 `Era.features.includes('hookSource')` 确认钩子里有这两个字段。

| `random()` | 以 MK 和钩子 id 为种子的确定性随机数，范围 [0, 1)。同一楼重算时序列相同；滑动生成的新回复有新的 MK，结果不同 |
| `math` | 确定性数学函数，用法同 `Math`，与 [`Era.math`](#eramath) 相同 |

变量和指令都是反转义后的副本，不含 `$meta` / `$template`。

**`options`**：`order`（默认 0，小的先执行，相同时按 id 排序）；`resync`（默认 `true`，注册后同步一次）。

**返回值**：注销函数。同一 id 重复注册会替换之前的钩子，建议用“角色卡.功能”作 id。`id` 不是非空字符串或 `hook` 不是函数时不注册，弹窗提示“钩子注册失败”，不抛出异常。

### `Era.hasHook(id, phase?)`

返回当前角色卡是否注册了该 id 的钩子。`phase` 为 `'before'` 或 `'after'`，省略时任一阶段都算。

**编写规则**：

1. 钩子必须是同步的、只依赖 `ctx` 的纯函数，因为重算历史消息时会再次执行。不要用 `Math.random`、`Date.now`、闭包里的状态或异步操作；请用 `old_stat` 和 `random()`。三角、指数、对数、乘方用 `ctx.math`，不要用 `Math.sin`、`Math.exp`、`Math.pow` 或 `**`（各浏览器的结果末位可能不同）。
2. 不要在钩子里发送任何写入事件或调用 `Era.commit` 等写入接口。它们会被拒绝，并让这个钩子按出错处理，见下面的[重入保护](#重入保护)。
3. 钩子不在用户消息上执行；`onAfterApply` 在变量为空时也不执行。因此**正文前规划写在玩家消息里的指令不经过钩子**：前置钩子的限幅管不到它；后置钩子里的进位、钳制、派生值要到下一条 AI 消息才计算。下一条 AI 消息的 `old_stat` 已经包含规划的改动，用 `stat.x !== old_stat.x` 判断“这一回合变了没有”会漏掉规划造成的变化；需要这种判断时，把上次结算到的值存进变量里再比较。
4. 钩子不受 `下划线只读` 限制。`$meta` 保护分两种情况：后置钩子（`onAfterApply`）直接改 `ctx.stat`，不受 `$meta.updatable` / `necessary` 限制；前置钩子（`onBeforeApply`）改写或新增的指令仍按指令执行，照常受 `$meta` 保护，改受保护的字段会失败并出现在 `era:commandError` 里。两种钩子都不能修改 `$meta` / `$template`。
5. 钩子出错时，它的修改被丢弃，其他钩子和指令照常生效。
6. 新注册或修改的钩子只影响之后重算的消息；想应用到全部历史，执行一次“强制完全重算”（`era:forceSync` 的 `full`）。
7. 钩子只保存在内存中并绑定当前角色卡，需要在**角色卡脚本**每次加载时注册。不要在楼层界面里、也不要在 `era:writeDone` 的监听器里**无条件**注册：每次注册都会触发同步，会无限循环。
8. ERA 脚本被重新启用或更新后，钩子会丢失，之后的楼层会在没有钩子的情况下计算。前端项目请用 `util/era.ts` 的 `registerEraHook(phase, id, hook, options?)`：它会等待 ERA 加载，在 `era:writeDone` 时用 `Era.hasHook` 检查、只在钩子丢失时补注册，脚本卸载时自动注销。直接调用 `Era.onAfterApply` 时，ERA 重载后请重新加载角色卡脚本。
9. 顶层键名不能含 `[` 或 `]`，这样的修改会被忽略。

### 重入保护

钩子在每次同步、重算、试算时都会执行。如果钩子在执行期间写入变量，写入会触发新一轮同步，新一轮同步又执行钩子，形成“提交 → 重算 → 钩子再提交”的循环。较早的版本里这样写会无限循环；钩子执行期间下面这些写入一律被拒绝：

| 入口 | 被拒绝时 |
| --- | --- |
| `Era.commit`、`Era.applyText`、`Era.setMessageText`、`Era.sync`、`Era.extra.run`、`Era.extra.autoRun`、`Era.extra.wait`、`Era.extra.plan`、`Era.extra.replan` | 返回失败的 Promise（`ReentryError`），不写入 |
| 注册接口 `Era.registerSchema`、`Era.onBeforeApply`、`Era.onAfterApply`、`Era.registerTool`、`Era.registerExprFn`、`Era.registerEntryFilter` | 直接抛出 `ReentryError`，不注册。注册会在稍后触发一次重算，重算又会执行钩子和工具；请在脚本加载时注册，不要在钩子、工具、过滤器里注册 |
| 写入事件 `era:insertByObject`、`era:updateByObject`、`era:deleteByObject`、`era:insertByPath`、`era:updateByPath`、`era:deleteByPath`、`era:patch`、`era:commit`、`era:forceSync` | 事件被丢弃，不进入 ERA 的队列 |

只要钩子调用过其中任何一个，即使它自己捕获了异常，这个钩子也按出错处理：它的修改全部丢弃，弹窗提示一次，其他钩子和指令照常生效。以前在钩子里调用 `Era.commit` 的卡，升级后会看到这个提示，请改成直接修改 `ctx.stat`（`onAfterApply`）或 `ctx.commands`（`onBeforeApply`）。

只读的接口（`Era.getCurrentVars`、查询事件等）不受影响，但钩子是同步函数，拿不到异步接口的结果。

工具和自定义公式函数也在同样的保护下执行，违规时这次调用失败。[条目过滤器](#eraregisterentryfilter--erahasentryfilter)也在同样的保护下调用：执行期间调用上述接口或发出写入事件时，忽略这个过滤器的结果，并记入分步更新结果的 `warnings`。

### 不要在 `era:writeDone` 里回写变量

常见的旧写法是监听 `era:writeDone`，根据最新变量算出天气、潮汐、上限等派生值，再用写入事件写回：

```javascript
// 旧写法：不要这样做
let lastDay = -1;
eventOn('era:writeDone', ({ statWithoutMeta: stat }) => {
  if (!stat.世界 || stat.世界.天数 === lastDay) return;
  lastDay = stat.世界.天数;
  const weather = Math.random() < 0.3 ? '雨' : '晴';
  const tide = Math.sin((2 * Math.PI * stat.世界.小时) / 12.42);
  eventEmit('era:updateByObject', {
    世界: { 天气: weather, 潮位: Math.round(tide * 100) / 100 },
    角色: { 生命上限: 100 + stat.角色.等级 * 10 },
  });
});
```

它的问题：

- **每次打开聊天都会重掷。** `lastDay` 只在脚本的内存里，每次加载都是 -1。打开聊天后的第一次 `era:writeDone` 一定和它不同，于是重新抽天气，改写最新一楼。
- **结果不能重放。** 回写是一次新的写入，挂在当时的最后一条 AI 消息上，内容是当时算出的字面值。编辑、删除更早的楼层或完全重算时，ERA 只会重放这些字面值，不会重新计算；`Math.random` 的结果本身也无法重现。“天数在哪一楼变化，天气就在哪一楼变化”的关系也丢了。
- **每次都算两轮。** 回写触发新一轮同步和 `era:writeDone`，需要额外的判断防止循环；两轮之间，界面和宏读到的是还没有派生值的变量。
- **数学函数的结果因浏览器而异。** `Math.sin`、`Math.exp`、`Math.pow`、`**` 的末位在不同浏览器上可能不同。

改法：派生值写进 `Era.onAfterApply` 钩子，随机数用 `ctx.random()`，三角、指数等用 `ctx.math`。钩子在每一楼的指令执行之后、同一次计算中运行，修改记入该楼的日志，重算时结果不变。

```javascript
await waitGlobalInitialized('Era');
const off = Era.onAfterApply('我的卡.世界计算', ({ stat, old_stat, random, math }) => {
  const world = stat.世界;
  if (world) {
    // 天数变化的那一楼抽一次天气：种子是这一楼的 MK，重算时不变；滑动生成的新回复会重新抽
    if (world.天数 !== old_stat.世界?.天数) {
      world.天气 = random() < 0.3 ? '雨' : '晴';
    }
    // 半日潮，周期约 12.42 小时
    world.潮位 = math.round(math.sin((2 * math.PI * world.小时) / 12.42) * 100) / 100;
  }
  if (stat.角色) {
    stat.角色.生命上限 = 100 + stat.角色.等级 * 10;
    stat.角色.生命 = math.min(stat.角色.生命, stat.角色.生命上限);
  }
});
$(window).on('pagehide', off);
```

| 旧写法 | 改成 |
| --- | --- |
| `eventOn('era:writeDone', …)` 加写入事件 | `Era.onAfterApply(id, hook)`，直接修改 `ctx.stat` |
| 记在内存里的“上次的值”（`lastDay`） | `ctx.old_stat`：本楼执行前的变量 |
| `Math.random()` | `ctx.random()` |
| `Math.sin`、`Math.exp`、`Math.pow`、`**` | `ctx.math.sin`、`ctx.math.exp`、`ctx.math.pow` |
| 防循环的标志、计时器 | 不需要 |

`Math.floor`、`Math.min` 这类函数本来就是确定的，可以照用；示例统一写成 `math.*` 只是为了少记一条规则。

迁移时注意：

- 删掉回写变量的 `era:writeDone` 监听器；只刷新界面的监听器保留。
- 钩子要在**角色卡脚本**里注册，见上面的编写规则第 7、8 条。前端项目用 `util/era.ts` 的 `registerEraHook('after', id, hook)`。
- 钩子只影响之后计算的楼层。想让已有聊天的历史也按钩子重算，执行一次“强制完全重算”（`era:forceSync` 的 `full`）。
- 已有聊天里旧写法写进去的回写（追加在正文末尾的指令块，或旁路写入）仍然存在，重算时照样执行。钩子在它们之后执行，同一楼里钩子写的字段以钩子为准；钩子没有改写的楼层和字段，旧回写的值保留。
- 需要由 AI 决定掷骰的场合（例如“掷 1d6 决定伤害”），让 AI 在 `<VariableEdit>` 里写表达式 `$expr`，见 [02 指令手册](./02-指令手册.md)；作者自己的派生数值写钩子。

## 9. 在前端界面中使用

本母版已内置以下两个文件（来自 ERA-Heron 的 `开发工具/`），供酒馆助手前端模板（vue + pinia）的项目使用：

| 文件 | 位置 | 内容 |
| --- | --- | --- |
| [`util/era.ts`](../../util/era.ts) | 与 `mvu.ts` 同一目录，可以 `import { defineEraDataStore } from '@util/era'` | 下表的函数 |
| [`exported.era.d.ts`](../../exported.era.d.ts) | 根目录（不要移进 `@types/`，`bump_deps` 会清空它） | 全局 `Era` 和 `era:*` 事件的类型声明 |

`era.ts` 依赖 pinia，以及模板提供的全局 `_`、`z`、`ref`、`shallowRef`、`defineStore`、`errorCatched`、`eventOn`、`waitGlobalInitialized` 等；不使用模板时请自行引入这些依赖，或参照它直接调用 `Era`。

| 函数 | 作用 |
| --- | --- |
| `defineEraDataStore(schema, id?, options?)` | 基于 pinia 的 store：只读的 `data`（通过 schema 校验的变量）、`raw`、`error`，以及写入方法（见下）。默认读取聊天的**最新**变量；`options.message_id` 指定楼层时读取那一楼处理完之后的变量。 |
| `defineEraFloorStore(schema, message_id?)` | 读取某一楼变量的 store，`message_id` 默认是界面所在的楼层（`getCurrentMessageId()`）。每次 `era:writeDone` 后重新读取。需要 `Era.getVarsAt`，旧版 ERA 会退回显示最新变量。 |
| `isLatestFloor(message_id?)` | 某一楼是否是聊天的最后一楼，默认判断界面所在的楼层。 |
| `registerEraSchema(schema, options?)` | 在角色卡脚本中注册 schema：ERA 晚加载时等待，ERA 重载后自动补注册，脚本卸载时自动注销。 |
| `registerEraHook(phase, id, hook, options?)` | 在角色卡脚本中注册钩子（`phase` 为 `'before'` / `'after'`），处理方式与上一项相同。ERA 重载后的补注册需要 `Era.hasHook`。 |
| `registerEraEntryFilter(name, filter)` | 在角色卡脚本中注册条目过滤器（作用于主生成、分步更新和正文前规划），处理方式与上一项相同；ERA 不支持时只在控制台提示。 |
| `registerEraTool(name, definition)` | 在角色卡脚本中注册工具（`<EraFCall>`），处理方式与上一项相同；ERA 不支持时只在控制台提示。 |
| `registerEraExprFn(name, fn, options?)` | 在角色卡脚本中注册 `$expr` 自定义公式函数，处理方式与上一项相同；ERA 不支持时只在控制台提示。 |
| `requireEra(min_version, options?)` | 检查玩家的 ERA 是否不低于 `min_version`，不满足时提示，见[版本检查](#eraversion--erafeatures)。 |
| `compareEraVersions(a, b)` | 比较两个版本号：负数表示 a 较旧，0 相同，正数表示 a 较新；无法识别时为 `NaN`。 |
| `getEraMath()` | 等待 ERA 加载后返回 `Era.math`；ERA 没有它时 Promise 失败。 |

store 的写入方法：

| 方法 | 作用 |
| --- | --- |
| `commit(operations, options?)` | **推荐**。等同于 `Era.commit`：不修改正文，返回 Promise，失败时说明原因，可以 `atomic`。 |
| `patch(operations, options?)` | 执行 `<VariablePatch>` 的操作，等同于 `commit({ patch: operations }, options)`。 |
| `update` / `insert` / `remove` | 分别发送 `era:updateByObject` / `era:insertByObject` / `era:deleteByObject`。拿不到结果，默认设置下会追加到 AI 消息正文；为兼容旧版 ERA 保留。 |

```typescript
import { defineEraDataStore, defineEraFloorStore, isLatestFloor } from '@util/era';
import { Schema } from './schema';

// 常驻界面：最新变量
const useEraStore = defineEraDataStore(Schema);
// 楼层状态栏：这一楼当时的变量
const useFloorStore = defineEraFloorStore(Schema);

const store = useEraStore();
try {
  await store.commit([{ edit: { 金币: '-=3' } }, { patch: [{ op: 'insert', path: '/背包/-', value: '面包' }] }], {
    atomic: true,
  });
} catch (error) {
  toastr.warning(error.message);
}
```

要点：

- ERA 的变量是**聊天级**的。`defineEraDataStore` 默认读到的是聊天的最新变量，无论界面在哪一楼。
- 数据是只读的，不能双向绑定：写入会异步计算，也可能被拒绝。请调用 `commit` 等方法，再从 `data` 观察结果。
- 状态栏的完整写法见 [03 状态栏](./03-状态栏.md) 和 [`示例/状态栏-事件版.html`](./示例/状态栏-事件版.html)。

### 旧楼的状态栏

楼层状态栏默认显示的是最新变量，长聊天里每一楼都显示同样的内容。可以任选一种做法：

- **每楼显示当时的值**：用 `defineEraFloorStore`（或 `Era.getVarsAt(getCurrentMessageId())`），旧楼显示那一楼处理完之后的变量，回看剧情时更直观。开启了 `日志保留楼层数` 时，折叠边界之前的楼层需要开启 `折叠日志存档` 才能读到，否则 `error` 会说明原因。
- **只在最新一楼显示完整状态栏**：在楼层界面里用 `isLatestFloor()` 判断，旧楼只显示一个简短的摘要或什么都不显示。新消息到来时旧楼不会重新渲染，因此要在 `era:writeDone` 和酒馆的 `MESSAGE_RECEIVED`、`MESSAGE_DELETED` 等事件里重新判断：

```javascript
function updateVisibility() {
  $('#full-statusbar').toggle(getCurrentMessageId() === getLastMessageId());
}
eventOn('era:writeDone', updateVisibility);
eventOn(tavern_events.MESSAGE_DELETED, updateVisibility);
updateVisibility();
```

## 10. 脚本设置

设置保存在 ERA 脚本的**脚本变量**中（ERA 装在角色卡脚本里时，会随角色卡导出）。修改方法：

- 悬浮球 → 面板 → 设置；
- 或酒馆助手脚本库 → ERA 脚本 → 变量。`开启悬浮球`、`开启黑夜模式` 不在设置列表中显示：前者对应面板“设置 → 面板与悬浮球 → 显示悬浮球”，后者被面板的配色选项取代。

分步更新（额外模型）的设置不在这里，它们保存在酒馆的全局变量 `ERA额外模型` 中，见 [06 分步更新](./06-分步更新.md)。

### 全部设置

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| `在ai消息尾部生成特殊符号` | 开 | AI 消息末尾没有 `特殊符号值` 时自动追加，配合正则把它替换成状态栏，见 [03 状态栏](./03-状态栏.md)。 |
| `特殊符号值` | `<StatusPlaceHolderImpl/>` | 上一项追加的符号。发给 AI 的提示词里会去掉 AI 消息中的这个符号，没有更新规则的旧卡也一样；自定义的值只在上一项开启时处理。 |
| `开启悬浮球` | 开 | 关闭后不显示悬浮球；面板仍可从酒馆扩展菜单的“ERA 面板”或发送 `/era` 打开，发送 `/era ball` 会重新开启。变量计算照常进行。 |
| `开启黑夜模式` | 关 | 在面板“设置”里没有选过配色时，开启则用暗色，否则跟随酒馆配色。选过配色后以面板的选择为准。 |
| `强制重载功能` | 关 | 每次写入或同步后约 1 秒，把最近几条消息原样写回一次，让楼层重新渲染，刷新其中的宏。 |
| `强制重载消息数` | `2` | 上一项重新渲染的消息数。 |
| `繁体转简体` | 关 | 解析指令块（以及写入事件的数据）前，把繁体中文转成简体，避免 AI 输出繁体键名导致路径对不上。修改后，重算历史楼层时也按新设置执行。 |
| `数组内保留对象` | 关 | 见下文。 |
| `清理失效日志` | 关 | 见下文。 |
| `日志保留楼层数` | `0` | 见下文。 |
| `折叠日志存档` | 关 | 见下文。 |
| `下划线只读` | 关 | 见下文。 |
| `宽松解析` | 开 | 指令块的 JSON 写坏时（尾逗号、单引号、缺引号、全角标点等）尝试修复后再解析。修改后，重算历史楼层时也按新设置执行：关闭后，旧楼里靠修复才能解析的指令块会失效。 |
| `指令失败提示` | 关 | 最新一条消息有指令没有生效时弹窗。无论是否开启，都会广播 `era:commandError`。 |
| `思考标签` | `think, thinking` | 这些标签里的指令不执行，只对新建的聊天生效，见下文。 |
| `指令外层标签` | 空 | 填写后只执行该标签内的指令，只对新建的聊天生效，见下文。 |
| `API写入不修改消息` | 关 | 见下文。 |
| `调试模式` | 关 | ERA 的警告和错误除了写到浏览器控制台，还会弹窗显示。详细的调试日志不受它控制，见下文。 |

### 修改设置对历史楼层的影响

ERA 计算时读取的是**当前**的设置，重算历史楼层（编辑或删除旧楼、滑动、折叠后从头重放、“完全重算变量”）也一样。因此 `数组内保留对象`、`繁体转简体`、`宽松解析`、`下划线只读` 这几项会改变旧楼的计算结果；`思考标签`、`指令外层标签` 会改变新建的聊天中旧楼的计算结果。**角色卡发布前定好，之后不要改**；必须改时，告诉玩家已有聊天的变量可能在下一次重算时变化。

### `数组内保留对象`

默认关闭时，ERA 把数组内的对象或数组转成 JSON 字符串存储，例如 `[{"name": "药水"}]` 会变成 `["{\"name\":\"药水\"}"]`。开启后数组可以直接存放对象。

默认关闭是为了兼容依赖旧行为的角色卡和状态栏。开启后如果对已有聊天完全重算，历史消息写入的数组也会按新规则保存。

### `清理失效日志`

被删除或被滑走的消息会在日志中留下不再使用的记录，经常重 roll 会让聊天文件持续变大。开启后，ERA 在每次重算时删除它们，`era:writeDone` 和 `era:queryResult` 的 `editLogs` 中只包含当前聊天里存在的消息。

### `日志保留楼层数`

默认 `0`（不折叠）。设为 N 时，只保留最近 N 楼的逐楼日志，更早的合并成一份等效的 `insert` 日志，用于控制几百楼以上长聊天的体积。建议 50~100：越小聊天文件越小，但能直接回滚、查询快照的旧楼越少。

开启后：

- `editLogs` 只包含近期楼层；折叠边界之前的楼层查不到历史快照（除非开启 `折叠日志存档`）。
- 修改、删除很早的楼层时，ERA 会从第 0 楼按正文重算，耗时变长。
- 不要在折叠之后从旧楼层的正文里删除变量指令块。
- `Era.commit` 的原子提交、`Era.simulate` 对折叠边界之前的楼层无法试算。
- 想恢复完整日志，把该设置改回 `0` 并执行一次“强制完全重算”。

### `折叠日志存档`

只在 `日志保留楼层数` 大于 0 时有效。每攒够 10 楼，把它们的逐楼日志存到酒馆服务器上的单独文件 `user/files/era_logs_*.json`，确认保存成功后才从聊天中移除。聊天文件保持小巧，同时仍能回滚到旧楼、查询旧楼的快照。

文件只是缓存：丢失、损坏、换了设备都不影响变量，需要旧日志时会改为从头按正文重算。删除当前角色卡的聊天时会一并删除；新的分支写入自己的文件。

写入文件前，每楼的日志会在楼内压缩：同一路径上连续的几次修改合并成一条，插入后又删除的抵消掉，中间夹着该路径的上级或下级路径的修改时不合并。每楼压缩后都会核对正向和回滚的结果与压缩前完全相同，不同就保留原日志，因此不影响任何重算结果。还原到聊天里的旧楼日志是压缩后的样子，`editLogs` 中这些楼的条目会比当初少。

### `下划线只读`

开启后，AI 的指令不能修改或删除以 `_` 开头的字段，但仍可插入新的。

- 用 `<VariablePatch>` 整体替换一个对象时，其中的 `_` 字段保留原来的值；删除整个父级时会一起删除。
- 钩子、`Era.commit`、开启 `API写入不修改消息` 时的写入事件不受限制。
- 默认设置下的写入事件写在正文里，与 AI 指令无法区分，会一并受限。
- 修改后，重算历史楼层时也按新设置执行：中途开启后，一旦从旧楼重算，旧楼里原本生效的 `_` 字段修改会被拦截，变量随之改变。
- `Era.applyText` 写入的指令按正文指令处理，同样受限制。

### `思考标签` 与 `指令外层标签`

这两项只对**新建的聊天**生效。ERA 第一次往一个聊天写入数据时（聊天变量 `ERAMetaData` 原本为空），在 `ERAMetaData` 中记下 `ParserVersion: 3`，之后这个聊天一直按新方式解析。没有这个标记的旧聊天保持原来的解析方式：思考块里的指令照旧执行，外层标签不起作用，重算结果与以前相同。

- **`思考标签`**：用逗号、顿号或空格分隔，可以带尖括号，不区分大小写。这些标签里的指令不执行。按你的预设增删（例如加上 `reasoning`）；留空表示不遮蔽。
- **`指令外层标签`**：填一个标签名，例如 `ERA_Update`（写成 `<ERA_Update>` 也可以）。填写后只执行该标签内的指令，标签外的一律不执行；分步更新写入的 `<era_extra>` 不受影响。默认设置下写入事件追加到正文的指令块会自动包在外层标签里。ERA 的规则条目和隐藏正则不知道这个标签，要在自己的提示词里要求 AI 使用它，需要时自己加正则隐藏它。

**在新聊天开始时就设好 `指令外层标签`，不要中途开启。** 这两项保存在 ERA 脚本里，不随聊天保存，重算时新聊天的每一楼都按**当前**设置重新解析。聊天进行到一半才开启“指令外层标签”，之前没有包外层标签的楼层在下一次重算（编辑、删除旧楼、滑动、完全重算）时，指令会全部失效，变量随之改变。中途关闭、改名，或修改 `思考标签`，同样会让历史楼层按新设置重新解释。已有聊天要中途开启时，先确认能接受这个结果。

配对规则（嵌套、未闭合、缺开始标签等）和 `<era_extra>` 区段的认法见 [02 指令手册](./02-指令手册.md#思考块与指令外层标签)。

### `API写入不修改消息`

默认关闭：写入事件（`era:insert*` / `era:update*` / `era:delete*` / `era:patch`）把指令块追加到最后一条 AI 消息的正文。开启后，这些写入改为保存在聊天变量 `ERAMetaData.ApiOps` 中，正文不再变长。

- 写入仍挂在最后一条 AI 消息上（没有 AI 消息时挂在最后一条消息上）。滑动、删除、编辑、复制、完全重算的效果与写在正文里相同，钩子、schema、`$meta` 保护照常生效。
- AI 不会再从正文里看到这些写入。需要让 AI 知道时，请用变量宏，见 [04 宏](./04-宏.md)。
- 聊天变量是这些写入的唯一副本：清空聊天变量、以 TXT 导出、把正文复制到别的聊天、或移除正文中的 `<era_data>`，都会丢失它们。前端改写楼层正文时，用 [`Era.keepMessageKey`](#erakeepmessagekey) 保留 `<era_data>`。
- 关闭该设置后，已有的写入仍会继续生效。
- 滑块之类的高频写入请在前端做防抖。

### `调试模式`

开启后，ERA 的警告和错误除了写到浏览器控制台，还会用弹窗显示，便于制卡时及时发现问题。它不会输出更多日志。

需要详细的调试日志时，在浏览器控制台（F12）执行：

```javascript
eraDebug.add('*');                       // 输出全部模块的调试日志
eraDebug.add('ERA变量框架/core/*');       // 只输出 core 目录下的模块
eraDebug.remove('ERA变量框架/core/key/*'); // 屏蔽某些模块
eraDebug.status();                       // 查看当前规则
eraDebug.clear();                        // 清空规则，关闭调试日志
```

模块名是源码相对 `src/` 的路径（不含扩展名），`*` 是通配符。规则保存在浏览器的 localStorage 中，刷新页面后仍然有效；浏览器控制台需要显示“详细”（Verbose）级别的消息才能看到。

## 11. 斜杠命令

ERA 注册了下面几个斜杠命令，可以在聊天输入框、STscript 和快速回复里使用。

| 命令 | 作用 |
| --- | --- |
| `/era [页面]` | 打开 ERA 面板。`/era close` 关闭，`/era ball` 显示悬浮球，`/era hide` 隐藏悬浮球，`/era settings` 等打开指定页面。 |
| `/era-get [meta=true] [路径]` | 读取变量，返回 JSON。 |
| `/era-issues [format=json\|model]` | 最新一条 AI 消息中没有生效的指令与原因。 |

酒馆不支持注销命令：ERA 脚本停用后命令仍在，调用时提示“ERA 脚本没有在运行”并返回空串。

### `/era-get`

返回变量的 JSON：已反转义，去掉了 `$meta` 等以 `$` 开头的字段。

- 路径规则与宏 `{{ERA:路径}}` 相同，见 [04 宏](./04-宏.md)。路径留空时返回全部变量。
- `meta=true`：保留 `$meta` 等字段。
- 字符串也按 JSON 返回，带引号（如 `"晴"`），便于判断类型；找不到时返回空串。
- 读取前最多等待 3 秒，让进行中的同步完成；超时后读取当前的变量。

```
/era-get 角色.生命 | /echo
/era-get meta=true 角色
```

### `/era-issues`

列出最新一条 AI 消息中没有生效的指令与原因，每条一行（`- 路径：原因`），没有问题时返回空串。聊天末尾是用户消息时，看的是它前面最近的 AI 消息。

- 默认列出这一楼全部来源的问题：正文里的指令、旁路写入、钩子、分步更新的输出，以及被 schema 拦截的修改。
- `format=json`：返回完整结果，形如 `{"message_id":3,"mk":"…","problems":[{"path":"…","reason":"…","origin":"text"}]}`。旁路写入和额外模型输出的问题带 `source`（见 [`era:schemaError`](#eraschemaerror)）；无法计算时带 `unavailable` 说明原因；聊天里没有 AI 消息时 `message_id` 为 `null`。
- `format=model`：返回与宏 `{{ERA-issues}}` 相同的、给主模型看的文字，只含主模型自己写在正文里的指令。
- 与 `{{ERA-issues}}` 读同一份记录。刷新页面后还没有同步过时，`/era-issues` 会从上一楼的状态重新计算这一楼，宏则当作没有问题。
- 读取前同样最多等待 3 秒同步。
