## 是什么

默认情况下，剧情模型写完正文后自己写 `<VariableThink>` 和指令块。开启分步更新后：

1. 剧情模型只写剧情，看不到变量更新规则；
2. 回复完成后，ERA 在后台另请求一次模型（可以是另一个接口、另一个模型），让它只根据这段剧情写指令；
3. 指令先试算一遍，有问题就把问题发回去让它重写；
4. 结果写到**那一楼**正文末尾的 `<era_extra>` 里，再按普通指令计算。

因为结果仍在正文里，滑动、删除、编辑、完全重算、导出聊天都和以前一样。

## 怎么开

悬浮球 → 面板 →“分步更新”，改完点“保存”：

| 设置 | 说明 |
| --- | --- |
| 变量更新方式 | “额外模型解析（剧情写完后另请求一次）”：开启；“随 AI 输出”：剧情模型自己写指令；“跟随角色卡”（默认）：按角色卡的推荐，卡片没有推荐时等同于随 AI 输出，见[角色卡推荐设置](#角色卡推荐设置) |
| 等待方式 | “后台更新，发送下一条前等它完成”（默认）：可以先看剧情，发送下一条时如果还没更新完会等它；“后台更新，不等待”：发送时不等 |
| 输出有问题时 | “保留有效的指令”（默认）：能用的指令照常生效；“整次放弃，变量不变”：只要有问题，这次输出全部不用 |
| 发送最近几楼 | 发给更新模型的剧情楼数，默认 2（玩家的一句和 AI 的一段） |
| 出错时重试次数 | 默认 1，最多 10。见[失败、重试与备用接口](#失败重试与备用接口) |
| 超时（秒） | 一次请求超过这个时间没有完成就算失败（可以重试），默认 120，最少 5 |
| 最大回复 token | 更新模型的最大回复长度，0 为不限（默认） |
| 温度 | -1 为不设置（默认），使用接口自己的温度 |
| 附加要求 | 附在发给更新模型的提示词最后，可以留空；可以使用 `{{ERA:路径}}` 宏 |
| 默认接口 | 来源可选“跟随酒馆当前连接”“酒馆的代理预设”“自定义接口”，并可指定模型 |
| 分组接口 | 输入分组名，点“为分组指定接口”，为 `[era_update:组名]` 分组单独指定接口；没有指定的分组用默认接口 |
| 备用接口 | 可以留空。主接口（分组接口或默认接口）请求失败时依次换用 |

设置保存在本机酒馆的全局变量里，**不会随角色卡导出**，对所有 ERA 卡生效。密钥也存在这里，请先看[API 密钥的安全](#api-密钥的安全)。

“分步更新”页的“重新解析最后一条 AI 消息”可以为最后一条 AI 消息重新生成，替换上一次的结果。没有开启分步更新时也能用：消息里原有的指令保持不变，模型只补充遗漏的部分。

旧卡建议先点一次“工具”页的“更新旧卡的规则”。不更新也能用，只是更新模型不会使用 `<VariablePatch>`。

## 角色卡推荐设置

专门为分步更新写的卡（剧情条目不要求写指令、规则全在 `[era_update]` 条目里），可以在**角色卡变量**里推荐设置。角色卡变量随卡导出，玩家导入后不用自己去面板里开。

在酒馆助手的“变量管理器”→“角色卡”中添加 `ERA分步更新`，或在卡片脚本里写：

```javascript
await updateVariablesWith(variables => _.set(variables, 'ERA分步更新', {
  变量更新方式: '额外模型解析',
  聊天楼层数: 3,
  重试次数: 2,
}), { type: 'character' });
```

- 可以推荐的项：`变量更新方式`（`'额外模型解析'` 或 `'随AI输出'`）、`等待方式`、`失败处理`、`聊天楼层数`、`重试次数`、`超时秒数`、`最大回复`、`温度`、`附加要求`，写法与面板中的值相同；没写的项用玩家自己的设置。
- **接口和密钥不能推荐**，始终用玩家自己的设置（默认是跟随酒馆当前连接）。
- 只有玩家的“变量更新方式”是“跟随角色卡”（默认）时才采用；玩家选了“额外模型解析”或“随 AI 输出”，就完全按玩家的设置，卡片的推荐不起作用。
- 无效的值（例如写成字符串的数字、超出范围）会被忽略。
- 以前保存过设置的玩家，“变量更新方式”保持原来的选择，要采用卡片推荐需要改成“跟随角色卡”。

## API 密钥的安全

“自定义接口”的密钥以明文保存在酒馆的**全局变量** `ERA额外模型` 里。全局变量不会随角色卡导出，但**所有酒馆助手脚本和角色卡的前端界面都能读取它**，包括你从别处下载的角色卡。

- 推荐使用“酒馆的代理预设”：在酒馆的 API 连接设置里保存一个代理预设，这里只填预设名，ERA 的设置里不会有密钥。
- 使用来路不明的角色卡（尤其是带脚本的卡）时，不要在这里填密钥。
- ERA 没有把密钥换到别处：浏览器里没有比全局变量更隔离的位置（酒馆助手脚本和前端都在同一个页面里运行），脚本变量还会随卡导出。
- ERA 自己不会把密钥写进聊天、日志或 `Era.extra.status()` 的记录里。

## 失败、重试与备用接口

每个分组单独请求、单独重试：

- **输出有问题**（指令不能生效、没有闭合、没有任何指令）：立即带着问题重试，最多“重试次数”次。
- **请求失败**：超时、限流（429）、服务器错误（5xx）、网络错误会等一会儿再试（2 秒、4 秒、8 秒……最多 30 秒），同样占用重试次数；鉴权、参数等其他 4xx 错误（例如 401 密钥错误）重试也不会成功，不再重试。
- **备用接口**：填了备用接口时，主接口请求失败（不论什么错误）就立即换用下一个，不占重试次数；备用接口用完后，在最后一个上按上面的规则重试。输出有问题时不换接口。

重试仍不成功时弹出“变量更新失败”，可以在面板里重新解析。要看实际发送的提示词和模型的原始回复，可以在控制台执行 `Era.extra.status().last`（只保存最近一次，只在内存中）。

## 世界书条目怎么写

按条目**名字**区分：

| 名字中含有 | 剧情模型 | 更新模型 |
| --- | --- | --- |
| （什么都没有） | 能看到 | 看不到 |
| `[era_update]` | 看不到 | 能看到 |
| `[era_update:组名]` | 看不到 | 只有这一组能看到 |
| `[era_both]` | 能看到 | 能看到 |

- “ERA 变量操作规则”和“ERA 变量意图说明”等同于 `[era_update]`，旧卡不用改名。名字必须一字不差（中间有一个空格），否则会被当成普通条目发给剧情模型。
- **只有更新模型应该写指令。** 其他世界书条目或预设里如果也要求剧情模型输出变量指令（例如“输出格式”条目末尾的指令要求），剧情模型仍会自己写指令，ERA 就不会再请求更新模型：
  - 世界书条目：把这一段拆成单独的条目，名字加 `[era_update]`；
  - 预设：预设条目不能加标记，请从预设中删掉这一段，移到带 `[era_update]` 的世界书条目里。
- 没有开启分步更新时，这些标记不起作用，条目照常发送，所以同一张卡两种方式都能用。
- 读取全局、角色卡（群聊时为全部成员）、聊天和用户人设绑定的世界书。
- 蓝灯条目总是发送；绿灯条目按关键字匹配最近几楼。递归、概率、分组权重等世界书功能对更新模型无效，条目里的 EJS 代码也不会执行。
- 条目里可以使用 `{{ERA:路径}}`，取的是这一楼在没有额外模型输出时的值（已含这一楼自己的指令和脚本写入）。没有任何条目写 `{{ERA:$ALLDATA}}`（或 `{{ERA-withmeta:$ALLDATA}}`）时，会自动附上全部变量。
- 注册了变量结构（`Era.registerSchema`）时，没有任何条目写 `{{ERA-schema}}` 就会自动附上结构说明；写了就按你安排的位置放。快速初始化生成的“ERA 变量意图说明”已经包含这两个宏，不会重复发送。

## 分组

变量很多时，可以用 `[era_update:战斗]`、`[era_update:好感]` 把规则分成几组。各组同时请求，还可以在面板里为每组指定不同的接口。没有组名的 `[era_update]` 条目每组都会看到。

各组应当负责互不重叠的变量；如果改了同一个变量，按组名顺序执行。

## 在自己的前端界面里发送

“发送下一条前等它完成”只拦得住酒馆自己的发送按钮和回车。前端界面、快速回复用 `/send`、`/trigger` 等命令发送时不会等待，这时更新仍会在后台完成并写到正确的楼层，只是紧接着的那次生成看到的还是更新前的变量。需要等待的前端界面或脚本，在发送前加一行 `await Era.extra.wait()`：

```javascript
await Era.extra.wait(); // 没有正在进行的更新时立即完成；返回 false 表示没等到完成
await triggerSlash('/send 你好 | /trigger');
```

## 什么时候不会请求

- 没有任何发给更新模型的条目；
- 剧情模型自己已经写了指令；
- 开场白、脚本创建的消息。

请求期间重新生成、继续、删除该楼或切换聊天，结果会作废，不会写到别处（继续写完后会重新解析）；只是滑到别的 swipe 看看，结果仍会写到原来那一条。

## 发送前等待

选了“发送下一条前等它完成”时，点发送会先等更新完成，再替你点一次发送：

- 最多等到每次请求都超时、用完全部重试和备用接口、再加上写入的时间（默认设置下约 6 分钟）；一般远早于此就完成了。
- 等待期间会显示“正在等待变量更新完成”，**点击这条提示**可以不再等待，直接发送。
- 没等到完成就发送时，会提示“变量仍在更新，已先发送”：更新完成后仍会写回原来那一楼，只是这次生成看到的是更新前的变量。
- 等待期间再次点发送不会重复发送；等待期间切换聊天、改了文字或开始了别的生成，就不再自动发送，文字留在输入框里。
