# 动态提示词：按变量决定发给 AI 的内容

同一张卡在不同阶段需要的设定不同：以一个世界模拟器为例，人在潮汐港时只需要港口的风俗和地点，潜入时才需要潜入规则，和平时代转入战争时代要整套换掉规则。全部常驻会浪费上下文，也让 AI 分不清当下该用哪一份。动态提示词就是按 ERA 变量（以及最近的剧情）决定这一轮发什么。

本文介绍 ERA 下的几种做法、各自适合的场景，以及怎样把“脚本改写世界书开关”的旧做法换成条目过滤器。

## 几种做法一览

| 做法 | 适合 | 需要 | 滑动、删楼、切换聊天后 |
| --- | --- | --- | --- |
| ERA 宏 `{{ERA:路径}}` | 把变量的值写进提示词 | 无 | 发送时按同步完成后的变量替换 |
| **条目过滤器** `Era.registerEntryFilter` | 按变量或最近的剧情决定条目发不发，或改写条目内容 | 一段角色卡脚本 | 每次生成重新判断，只在内存里改，不写世界书文件 |
| EJS（`<% %>`、`@@if`） | 条目里按变量写不同的段落、循环列出变量 | 酒馆的“提示词模板”扩展 | 每次生成重新渲染；只用 EJS 的卡滑动时要注意（见下文） |
| 酒馆的绿灯（关键字）条目 | 正文提到某个词时带出设定 | 无 | 按扫描到的正文 |
| 脚本改写世界书开关（`replaceWorldbook`、`updateWorldbookWith` 改 `enabled`） | **不推荐** | 一段角色卡脚本 | 开关写进了世界书文件，见下文 |

为什么不推荐改写世界书开关：

- 开关写进了世界书**文件**，所有用这本世界书的聊天共用同一套开关。在 A 聊天里推进到后期，切到 B 聊天的开局，B 拿到的是后期的条目，直到下一次改写。
- 通常在发送（`MESSAGE_SENT`）时改写。滑动、重新生成、删楼不会发送，开关停在上一次的状态；而 ERA 的变量已经回滚，两者对不上。
- 分步更新、正文前规划读条目时按文件里的开关，解析旧楼时拿到的是“上一次发送时”的条目。
- 每一轮都写一次世界书文件，世界书越大越慢，还可能和作者在编辑器里的修改互相覆盖。

条目过滤器做的是同一件事（按变量决定条目），但只在每次生成加载世界书时、在内存里决定，没有上面这些问题。

## 条目过滤器（1.7.0 起，主生成 1.8.0 起）

在角色卡脚本里注册一个函数，ERA 每次组织提示词时对每个世界书条目调用它：

```javascript
await waitGlobalInitialized('Era');
const off = Era.registerEntryFilter('我的卡.区域', (entry, ctx) => {
  const match = /\[区域:([^\]]+)\]/.exec(entry.name);
  if (match) return ctx.stat.世界?.当前区域 === match[1];
  return undefined; // 其他条目不表态，按文件里的开关和关键字
});
$(window).on('pagehide', off);
```

用前端模板的项目可以用 `util/era.ts` 的 `registerEraEntryFilter`：它等 ERA 加载、ERA 重载后补注册、脚本卸载时注销。完整的示例脚本见 [示例/动态世界书过滤器示例.js](示例/动态世界书过滤器示例.js)。

**返回值**：

| 返回 | 含义 |
| --- | --- |
| `false` | 这一次不发送这个条目 |
| `true` | 发送，即使文件里关着；不再看关键字（当作常驻） |
| 字符串 | 发送，并用这段文字替换条目内容 |
| 其他（`undefined` 等） | 不表态：按文件里的开关和关键字 |

多个过滤器按名字顺序调用：有一个返回 `false` 就排除；返回字符串时，后面的过滤器看到的是替换后的内容。

**参数**：

- `entry`：条目的副本。`entry.name` 是条目名（备注），`entry.uid`、`entry.world`、`entry.content`、`entry.enabled`（文件里的开关）。
- `ctx.stat`：变量（去掉了 `$meta` 等字段、已反转义），只读。`ctx.statRaw` 是 ERA 存储的原样。
- `ctx.text`：最近几楼的正文（楼层数取分步更新设置的“聊天楼层数”，默认 2），可以用来按剧情里出现的词判断。
- `ctx.mk`：最新一楼的 MK。
- `ctx.purpose`：这次是给谁选条目。`main` 是主生成（1.8.0 起），用最新的变量；`extra` 是分步更新，用**被解析那一楼**的变量；`plan` 是正文前规划。只想影响其中一种时按它判断，其余返回 `undefined`。

**什么时候调用**：

- 主生成（1.8.0 起）：每次生成加载世界书时。ERA 先等变量同步完（例如滑动时的回滚，最多约 3 秒），所以读到的是这一轮该用的变量。删除条目、改开关、改内容只影响这一次生成，世界书文件不变。
- 分步更新、正文前规划：ERA 自己组织提示词时。

**规则**：过滤器必须是同步的、只依赖参数的纯函数：不要在里面请求网络、改变量、调用 `Era.commit`（会被拒绝，见 [05-接口与设置.md](05-接口与设置.md) 的重入保护）。出错或返回 Promise 时忽略它的结果并记一条告警。

**写法建议**：

- 用**条目名里的标记**认条目（如 `[区域:潮汐港]`、`[时代:战争]`），不要在脚本里写死 `uid`。条目被复制、导入另一本世界书时 `uid` 会变，名字不会。
- 一张卡只注册一两个过滤器，在函数里按条目名分派，比每类条目注册一个更容易看清楚。
- 判断要和变量结构对得上：读不到的字段用 `?.` 和默认值兜住，变量还没初始化（开场白之前）时返回 `undefined`，让条目按文件里的开关来。

## 从“脚本改写世界书开关”迁移

按变量开关条目的旧脚本通常是这样（以虚构的世界模拟器“雾港群岛”为例）：

```javascript
// 旧做法：发送时算出要开的条目，写回世界书文件
eventOn(tavern_events.MESSAGE_SENT, async () => {
  const uids = new Set(DEFAULT_UIDS);
  if (vars.世界.区域 === '潮汐港') uids.add(12);
  if (/潜入/.test(recentText)) uids.add(40);
  const book = await getWorldbook('我的世界书');
  await replaceWorldbook('我的世界书', book.map(e => ({ ...e, enabled: uids.has(e.uid) })));
});
```

改成过滤器的步骤：

1. **给条目标上标记**：在条目名里写明它什么时候该出现，如 `[区域:潮汐港] 港口风俗`、`[行动:潜入] 潜入规则`、`[时代:战争] 战时规则`。原来常驻的条目不用改。
2. **把“算出一个 UID 集合”改成“逐条判断”**：过滤器拿到一个条目，看它的标记，返回 `true` / `false`；没有标记的返回 `undefined`。
3. **变量从 `ctx.stat` 读，最近的剧情从 `ctx.text` 读**，不要再用脚本里缓存的“上一次 `era:writeDone` 的变量”。
4. **删掉写世界书的代码**（`replaceWorldbook`、`updateWorldbookWith` 改 `enabled` 的部分），以及为它准备的 `MESSAGE_SENT` / `era:writeDone` 监听。
5. **把文件里的开关恢复成默认状态**：受过滤器管理的条目，文件里的开关只是过滤器不表态时的默认值。建议都设为关闭，由过滤器决定何时打开；这样即使脚本没加载，也不会一下子把所有条目都发出去。

```javascript
// 新做法：每次生成时按变量逐条判断，不写文件
registerEraEntryFilter('雾港群岛.动态世界书', (entry, ctx) => {
  const stat = ctx.stat;
  const tag = (kind) => new RegExp(`\\[${kind}:([^\\]]+)\\]`).exec(entry.name)?.[1];

  const region = tag('区域');
  if (region) return stat.世界?.区域 === region;

  const action = tag('行动');
  if (action) return ctx.text.includes(action);

  const era = tag('时代');
  if (era) return stat.世界?.时代 === era;

  return undefined;
});
```

迁移后，“和平、战争两套规则二选一”这类整套切换，在主生成、分步更新、正文前规划里都按同一个函数判断，解析旧楼时也拿到那一楼对应的规则。

**单字名字误触**：按 `ctx.text` 判断人名时，单字名（如“岚”）会被“山岚”“晓岚”误触。可以先去掉黑名单里的词再判断：

```javascript
const mentions = (text, name, blacklist = []) => blacklist.reduce((t, word) => t.replaceAll(word, ''), text).includes(name);
```

## EJS：条目里的条件文字

条目内容本身要按变量变化（“人口大于 1000 写一段，否则写另一段”“列出背包里的每件物品”）时，用 EJS 更直接。需要安装并开启酒馆的“提示词模板”扩展。示例见 [示例/EJS动态提示词示例.txt](示例/EJS动态提示词示例.txt)，规则见 [04-宏.md](04-宏.md#需要条件判断时ejs)。要点：

- **读变量**：`getvar('stat_data.路径', { scope: 'local' })`。读到的是 ERA 存储的原样：文本里的 `.`、`"`、`'` 被转义成 `__DOT__`、`__DQUOTE__`、`__SQUOTE__`，还有 `$meta` 等字段。只是插入值时用 `{{ERA:路径}}` 更省事。
- **整条开关**：条目开头写 `@@if 条件`，条件为假时整条不发送。按变量切换整条条目，`@@if` 和条目过滤器都能做；已经写了 EJS 的卡用 `@@if`，写脚本的卡用过滤器，两者可以同时用。
- **不要在 EJS 里写变量**（`setvar` 等）：ERA 的变量只能由指令修改，EJS 写进去的值在下一次同步时会被覆盖，重算也无法重现。
- **滑动时读到旧变量**：主生成的 EJS 由扩展渲染，ERA 不参与。提示词里一个 ERA 宏都没有时，滑动重新生成的那一刻 EJS 可能读到回滚前的变量。在任意条目里放一个 ERA 宏（例如 `{{ERA:世界.时间}}`）可以让 ERA 先算完再交出提示词（聊天补全类接口有效）。条目过滤器没有这个问题。
- **分步更新与正文前规划**：发给这两个模型的条目里的 EJS，由 ERA 按目标楼的状态渲染（分步更新设置“EJS 预处理”为“自动”时），写变量的函数在这里不执行。见 [06-分步更新.md](06-分步更新.md#ejs-预处理)。

## ERA 宏与脚本注入

- **只是插入值**：直接在条目里写 `{{ERA:路径}}`、`{{ERA:$ALLDATA}}`，见 [04-宏.md](04-宏.md)。ERA 在请求发出前替换，有同步在进行时先等它完成。
- **脚本算出一段文字再注入**：用酒馆助手的 `injectPrompts`。注入的内容里可以写 ERA 宏，ERA 会在发送时按同步完成后的变量替换，比在脚本里自己读变量拼文字更可靠：

```javascript
eventOn(tavern_events.GENERATION_AFTER_COMMANDS, () => {
  injectPrompts([{ id: '我的卡.天气', position: 'in_chat', depth: 2, role: 'system',
                   content: '当前天气：{{ERA:世界.天气}}，气温 {{ERA:世界.气温}} 度。' }]);
});
```

  注入要按条件出现、内容又只是几段固定文字时，写成条目再用过滤器开关更简单。

## 与分步更新、正文前规划配合

- `[era_update]` 条目只发给分步更新的更新模型，`[era_plan]` 只发给正文前规划的模型，`[era_both]` 两边都发；剧情模型看不到 `[era_update]`（开启分步更新时）和 `[era_plan]` 条目。见 [06-分步更新.md](06-分步更新.md)。
- 条目过滤器对三者都生效：同一个函数在主生成里按最新变量判断，在分步更新里按被解析那一楼的变量判断。需要区别对待时看 `ctx.purpose`。
- 变量规则本身要按阶段切换时（例如和平、战争两套 `ERA 变量操作规则`），给两套条目分别标上阶段，用过滤器二选一，主生成和分步更新就会拿到同一套规则。

## 怎么选

| 想做的事 | 推荐 |
| --- | --- |
| 把变量的值写进设定 | ERA 宏 `{{ERA:路径}}` |
| 按变量开关整条条目（区域、地点、时代） | 条目过滤器；已经在用 EJS 的卡也可以用 `@@if` |
| 按剧情里出现的词开条目 | 酒馆的绿灯关键字；需要排除误触或结合变量时用过滤器读 `ctx.text` |
| 按玩家的行动开条目（“[行动] 潜入仓库”） | 条目过滤器读 `ctx.text` |
| 条目里按变量写不同段落、列出变量 | EJS；或用过滤器返回替换后的内容 |
| 整套规则随剧情阶段切换 | 条目过滤器（主生成、分步更新、正文前规划一致） |
| 脚本算出的一段说明 | `injectPrompts`，内容里用 ERA 宏 |
