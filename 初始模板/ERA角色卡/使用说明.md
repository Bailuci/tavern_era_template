# ERA 角色卡初始模板

一张开箱即用的 ERA 角色卡骨架。和 `初始模板/角色卡`（MVU 版）结构相同，变量由
[ERA-Heron](https://github.com/Bailuci/ERA-Heron) 管理。

## 包含什么

| 路径                          | 内容                                                                              |
| ----------------------------- | --------------------------------------------------------------------------------- |
| `index.yaml`                  | tavern_sync 角色卡配置：世界书条目、5 条正则、2 个脚本                            |
| `schema.ts`                   | 变量结构（zod）示例                                                               |
| `initvar.yaml`                | 初始变量；`pnpm era-init` 把它写进每个开场白                                      |
| `第一条消息/0.txt`            | 开场白，末尾 `ERA-INIT` 标记之间的 `<VariableInsert>` 由 `pnpm era-init` 生成      |
| `世界书/ERA/变量操作规则.txt` | 教 AI 写指令的规则，来自 ERA-Heron，一般不改                                      |
| `世界书/ERA/变量意图说明.txt` | 你的变量说明，已带 `{{ERA-schema}}` 和 `{{ERA:$ALLDATA}}`                         |
| `世界书/ERA/表达式规则.txt`   | 可选：教 AI 用 `$expr` 写公式和掷骰，`index.yaml` 里默认关闭                       |
| `脚本/变量结构/index.ts`      | 把 `schema.ts` 注册到 ERA                                                         |
| `界面/状态栏/`                | vue 状态栏：用 `@util/era` 的 `defineEraDataStore` 读变量，用 `Era.commit` 写变量 |

世界书条目和正则与 ERA 面板“ERA 快速初始化”生成的同名，所以用这个模板的卡**不需要再点快速初始化**。

5 条正则：`ERA 数据隐藏正则`、`ERA 元数据隐藏正则`、`ERA 思考块隐藏正则` 把指令块、元数据和思考块从显示与提示词里去掉；
`ERA 状态栏模板` 在显示时把 AI 消息末尾的 `<StatusPlaceHolderImpl/>` 换成状态栏；
`ERA 状态栏占位符隐藏正则` 只作用于提示词，把这个占位符从发给 AI 的历史消息里去掉，
免得 AI 学着输出它，显示不受影响。

## 用法

1. 把 `新建为src文件夹中的文件夹` 复制到 `src/` 下，改成你的角色卡名，例如 `src/我的卡/`。
2. 在 `index.yaml` 里把 `角色卡名称` 换成这个文件夹名，把 `GitHub用户名/仓库名` 换成你的角色卡仓库。
3. 改 `schema.ts`，设计你的变量（写法见 `docs/era/05-接口与设置.md`）。
4. 改 `initvar.yaml`：写出全部初始变量。改 `第一条消息/0.txt` 的开场白正文，保留末尾的两行 `ERA-INIT` 标记；备选开场白另存为 `第一条消息/1.txt` 等，同样放上这两行标记。然后运行 `pnpm era-init`（见下面的“初始值生成器”）。
5. 改 `世界书/ERA/变量意图说明.txt`：每个变量什么时候改、改多少、用哪种指令。
6. 改 `界面/状态栏/App.vue`。
7. `pnpm watch` 构建；在 `tavern_sync.yaml` 里加上这张卡的配置，用 `pnpm sync` 推送到酒馆或打包。
8. 按 `docs/era/01-快速上手.md` 的第 9 步测试：新开聊天、发送、滑动、删除、编辑、完全重算变量。

## 初始值生成器 `pnpm era-init`

ERA 的初始变量写在开场白里（每个开场白末尾一个 `<VariableInsert>`），手写时容易和 `schema.ts` 对不上，有几个开场白就要改几份。
生成器替你写这一块：

- 读取 `src/` 下每张同时有 `schema.ts` 和 `initvar.yaml` 的卡，把初始值写进 `第一条消息/*.txt` 中
  `<!-- ERA-INIT:BEGIN -->` 与 `<!-- ERA-INIT:END -->` 之间。标记之外的正文不动，没有标记的开场白跳过。
- 某个开场白的初始值不同时，在旁边建 `第一条消息/<文件名>.initvar.yaml`，只写不同的部分：对象逐层合并，数组整体替换。
- 写出前用 `schema.ts` 校验；不合法时报告第一处问题并跳过那个开场白。
- `schema.ts` 里用 `.meta({ era: { updatable: false } })`、`.meta({ era: { necessary: 'self' } })`、
  `.meta({ era: { unInsertAble: 'self' } })` 标出的保护，写成初始值里对应对象的 `$meta`；标在 `z.record` 的值上时，
  还写成 `$template.$meta`，之后插入的新条目也会带上。`$meta` 只能放在对象上，标在数字、文本上的会提示并忽略。
  `.meta()` 与 `.describe()` 都要用时，写在同一个 `.meta({ era: { … }, description: '…' })` 里。
- `$meta` 是软保护：AI 可以按 `docs/era/02-指令手册.md` 的写法解除它，重要的规则仍要靠 schema 和钩子保证。

```bash
pnpm era-init            # 生成全部角色卡
pnpm era-init 我的卡      # 只处理 src/我的卡
pnpm era-init --check    # 只检查是否需要更新，需要时以退出码 1 结束
```

## 维护

- ERA 更新了规则提示词时，用 ERA-Heron 仓库的
  `src/ERA变量框架/initer/manual/worldbook_entries/era_var_operation_rule.txt` 覆盖
  `世界书/ERA/变量操作规则.txt`；已经发布的卡也可以在酒馆里点 ERA 面板的“更新旧卡的规则”。
- ERA 升级版本时，改 `index.yaml` 里 `ERA-Heron` 脚本的版本号。
- 想用分步更新（另一个模型专门更新变量）：见 `docs/era/06-分步更新.md`。这两个条目的名字不能改。

完整的制卡流程见 `.agents/skills/era-character-card/SKILL.md`。
